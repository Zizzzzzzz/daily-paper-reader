## 摘要
智能体 LLM 工作负载在每一轮中都会将位完全相同的 token 放置在偏移后的位置，导致前缀缓存在第一个差异字节处失效。运营商报告称，缓存命中率下降导致了从轻微减速到未改变内容上 10-16 秒的严重首字延迟（TTFT）激增。先前的位置无关缓存系统在完整的 $d_K$ 维键（key）上修正 RoPE，这是由 GQA 带来的架构成本，而非缓存本身。多头潜在注意力（MLA）已在 DeepSeek-V2/V3/R1、Kimi-K2/Moonlight、GLM-5 和 Mistral Large 3 中大规模部署，它将每一行 KV 分解为位置无关的 $c_{KV}$ 和一个可以闭式修正的 64 维 $k_r$；这种结构使得内容寻址缓存成为一种天然适配，而非针对 GQA 的权宜之计。我们提出了 Irminsul，它通过对 CDC 分块段进行内容哈希键控以及针对 $k_r$ 的 $δ$ 旋转规则，扩展了 SGLang 的基数缓存（radix cache）。我们评估了三个原生的 MLA-MoE 部署——DeepSeek-V2-Lite (16B/2.4B)、Kimi Moonlight-16B-A3B 和 JoyAI-Flash (48B/3B)——在所有三个模型上均实现了输出一致性，并在两个端点上测量了恢复率；在智能体流量中，Irminsul 在精确前缀之外恢复了高达约 83% 的 prompt token，同时每次缓存命中可节省 63% 的预填充能耗。我们认为，内容寻址缓存应当作为推理栈中的一等原语，而非对前缀匹配的补丁。

## Abstract
Agentic LLM workloads put bit-identical tokens at shifted positions every turn, voiding prefix caches at the first byte of divergence. Operators report cache-hit regressions ranging from moderate slowdowns to severe TTFT spikes of 10-16s on unchanged content. Prior position-independent caching systems correct RoPE on the full $d_K$-dimensional key, an architectural cost imposed by GQA, not by caching itself. Multi-Head Latent Attention, deployed at scale in DeepSeek-V2/V3/R1, Kimi-K2/Moonlight, GLM-5, and Mistral Large 3, factors each KV row into a position-free $c_{KV}$ and a 64-dim $k_r$ correctable in closed form; this structure motivates content-addressed caching as a natural fit rather than a GQA workaround. We present Irminsul, which extends SGLang's radix cache with content-hash keying over CDC-chunked segments and a $δ$-rotation rule for $k_r$. We evaluate three native MLA-MoE deployments - DeepSeek-V2-Lite (16B/2.4B), Kimi Moonlight-16B-A3B, and JoyAI-Flash (48B/3B) - with output-consistency on all three and recovery measured on the two endpoints; Irminsul recovers up to ~83% of prompt tokens above exact-prefix on agentic traffic while delivering 63% prefill energy savings per cache hit. We argue that content-addressed caching belongs in the serving stack as a first-class primitive, not a retrofit over prefix matching.

### 论文总结：Irminsul —— 面向智能体 LLM 推理服务的 MLA 原生位置无关缓存

#### 1. 核心问题与整体含义（研究动机和背景）
在智能体（Agentic）LLM 应用中，Prompt 通常由静态系统提示词、动态检索文档、工具输出和历史对话组成。这种动态组合导致即使 Token 内容完全相同，其在序列中的**绝对位置也会发生偏移**。
*   **传统前缀缓存（Prefix Caching）的失效**：如 SGLang 或 vLLM 使用的基数缓存，一旦在某个字节处出现差异（如插入了一个新文档），后续所有相同的 Token 都会因为位置哈希不匹配而导致缓存失效，引发严重的预填充（Prefill）延迟和能耗浪费。
*   **现有 PIC 系统的局限**：先前的位置无关缓存（PIC）系统（如 CacheBlend, EPIC）主要针对 GQA 架构，需要对完整的 $d_K$ 维 Key 向量进行复杂的 RoPE 逆旋转修正，计算开销较大。
*   **MLA 的机遇**：DeepSeek 等模型采用的 **MLA（多头潜在注意力）** 架构天然将 KV 分解为位置无关的潜在向量（$c_{KV}$）和极低维（64维）的旋转项（$k_r$）。这为实现低成本、高效率的内容寻址缓存提供了物理基础。

#### 2. 方法论：核心思想与关键技术
Irminsul 的核心思想是“**按内容缓存，而非按位置缓存**”。
*   **内容寻址分块（CDC）**：使用基于 Gear-hash 的内容定义分块（Content-Defined Chunking）技术，将 Prompt 切分为变长块。通过在共享内容周围插入 64-token 的边界标记（Marker），确保相同内容无论在何处都能产生一致的哈希值。
*   **$\delta$-旋转规则**：针对 MLA 架构，缓存中存储原始的 $c_{KV}$ 和基础位置的 $k_r$。当发生位置偏移时，仅需对 64 维的 $k_r$ 进行一次闭式的 $\delta$ 旋转修正（$\delta = p_{target} - p_{source}$），而占 KV 行 89% 体积的 $c_{KV}$ 无需任何修改即可复用。
*   **首块挖除（First-Chunk Carve-out）**：针对“注意力汇”（Attention Sink）现象，Irminsul 发现 Sink 效应是序列起始位置相关的，而非分块起始相关的。因此，系统强制对序列前 32 个 Token 进行常规预填充，从而绕过 Sink 区域，保证后续缓存块的数值稳定性。
*   **算法流程**：匹配前缀 $\rightarrow$ 对剩余部分进行 CDC 分块 $\rightarrow$ 检查内容哈希 $\rightarrow$ 命中后执行 $k_r$ 旋转修正 $\rightarrow$ 拼接 KV 序列。

#### 6. 主要结论与发现
*   **高恢复率**：在智能体元数据偏移场景下，Irminsul 在精确前缀缓存之外额外恢复了 **77% - 83%** 的 Token。
*   **显著节能**：相比完全重新计算，MLA 架构下的缓存命中可节省 **63%** 的预填充能耗（GQA 可节省更多，但修正成本更高）。
*   **架构敏感性**：PIC 仅在 Softmax 注意力架构下有效；对于混合 SSM/线性注意力架构，由于其递归状态不可索引，缓存节省几乎为零。
*   **精度保持**：$\delta$-旋转的代数误差极小（$4.7 \times 10^{-3}$），在各项下游任务中保持了与完全重计算几乎一致的输出质量。

#### 7. 优点
*   **架构原生性**：深刻洞察了 MLA 架构与内容寻址缓存的数学契合度，将 PIC 的修正成本从 $O(d_K N)$ 降至 $O(64 N)$。
*   **实用性强**：直接针对生产环境中 OpenClaw 等框架遇到的实际痛点（如文档重排、系统变量更改导致的缓存失效）。
*   **理论支撑**：通过 ROC 分析和注意力汇锚定实验，为 PIC 的可行性和安全性提供了坚实的理论依据。

#### 8. 不足与局限
*   **MHA 支持有限**：由于 MHA 的注意力汇具有局部集中特性，论文提出的“首块挖除”策略在 MHA 上效果不佳，目前仅能保证 MLA 的安全性。
*   **依赖边界标记**：为了获得最佳性能，需要智能体框架配合插入 Marker（S2 策略），对于完全不可控的黑盒 Prompt，恢复率会下降。
*   **新架构适配**：DeepSeek-V4 引入的 HCA（重度压缩注意力）打破了 Token 级的独立性，Irminsul 需要进一步适配这种聚合表征。
*   **端到端延迟**：虽然理论上修正开销极低，但论文中的 TTFT 测量是在模拟脚手架上完成的，尚未完全集成到 FlashMLA 的融合内核中进行端到端实测。
