## 摘要
静态图大语言模型（LLM）解码器提供了可预测的启动、固定的张量形状以及较低的提交开销，但在线解码表现出高度不规则的 KV 缓存行为：请求长度各异、EOS 事件异步到达，且逻辑历史随时间而碎片化。动态运行时通过分页 KV 管理和步级调度恢复了灵活性，而静态图执行器通常会过度预留内存，并遭受突发延迟离群值的影响。本文研究了是否可以在固定的解码接口之下吸收大部分这种变动性。我们提出了 KV-RM，这是一种在静态图 LLM 解码器之下规范化 KV 缓存移动的运行时设计。KV-RM 将逻辑 KV 历史与物理存储解耦，通过块分页器跟踪活跃的 KV 状态，并通过单个提交描述符实现每个解码步骤。在固定形状的注意力算子消耗数据之前，一个合并阶段传输路径将非连续的 KV 映射合并为少量的大型传输组。在相同的接口下可以启用可选的有界远期历史摘要，但核心设计并不依赖于它们。在双 GPU NVIDIA A100 节点上，相对于静态图基准，KV-RM 提高了混合长度解码的吞吐量并降低了尾部延迟，减少了各类工作负载中的预留 KV 内存，并消除了生产追踪重放下的严重突发延迟峰值。这些结果表明，KV 缓存移动而非算子形状，可以作为在静态图 LLM 推理服务中恢复运行时灵活性的有效边界。

## Abstract
Static-graph LLM decoders provide predictable launches, fixed tensor shapes, and low submission overhead, but online decoding exposes highly irregular KV-cache behavior: request lengths differ, EOS events arrive asynchronously, and logical histories fragment over time. Dynamic runtimes recover flexibility through paged KV management and step-level scheduling, while static-graph executors often over-reserve memory and suffer burst-time latency outliers. This paper studies whether much of this variability can be absorbed below a fixed decode interface. We present KV-RM, a runtime design that regularizes KV-cache movement beneath a static-graph LLM decoder. KV-RM decouples logical KV histories from physical storage, tracks active KV state through a block pager, and materializes each decode step through a single committed descriptor. A merge-staged transport path coalesces non-contiguous KV mappings into a small number of large transfer groups before a fixed-shape attention kernel consumes them. Optional bounded far-history summaries can be enabled under the same interface, but the core design does not depend on them. On a 2-GPU NVIDIA A100 node, KV-RM improves mixed-length decoding throughput and tail latency relative to a static-graph baseline, reduces reserved KV memory across workload families, and removes severe burst-time latency spikes under production-trace replay. These results suggest that KV-cache movement, rather than kernel shape, can be an effective boundary for recovering runtime flexibility in static-graph LLM serving.

### 1. 核心问题与整体含义（研究动机和背景）
在 LLM 推理服务中，存在**静态图执行器**（如 TensorRT-LLM）与**动态运行时**（如 vLLM）之间的权衡。
*   **静态图执行器**：优点是启动可预测、张量形状固定、提交开销低；缺点是面对不规则的在线解码（请求长度不一、EOS 异步到达）时，必须按最坏情况预留内存，导致内存浪费严重，且在请求突发时会出现严重的延迟峰值（Tail Latency）。
*   **动态运行时**：通过分页管理（Paged KV）恢复了灵活性，但带来了复杂的宿主机/运行时交互和非连续访问导致的传输抖动。
*   **核心问题**：能否在保持静态图“形状固定”的优势下，吸收 KV 缓存的不规则性？论文提出 **KV-RM**，旨在通过规范化（Regularizing）KV 缓存的移动，在静态图框架内实现动态运行时的灵活性。

### 2. 方法论：核心思想与关键技术
KV-RM 的核心思想是**将灵活性下移至描述符传输层**，保持上层解码算子（Kernel）形状稳定。
*   **KV Pager（分页器）**：将逻辑 KV 历史与物理存储解耦。它提供四种原语：`Reserve`（预留页面）、`Alias`（前缀共享/写时复制）、`Trim`（回收 EOS 或冷数据页）、`Frame`（将所有编辑打包成单次原子提交）。
*   **Merge-staged Transport（合并阶段传输）**：这是解决传输抖动的关键。它将分页器产生的碎片化非连续映射，在提交给算子前，合并成极少数（通常为 1-2 个）大型 DMA 传输组（Trains）。这保证了即使物理存储是碎片的，数据传输依然是连续且高效的。
*   **固定形状滑动窗口算子**：算子在编译时固定窗口宽度 $W^*$，每步只处理最新的 $W^*$ 个状态。通过分页器的映射编辑，实现逻辑上的全量历史追踪。
*   **可选的远期摘要（Far-view Summarization）**：在固定预算内，通过均匀聚合（Uniform Aggregation）将远期历史压缩为摘要，使其适配固定形状的算子接口。

### 7. 优点
*   **架构优雅**：通过“描述符合并”巧妙解决了分页内存导致的 DMA 碎片化问题，这是很多分页系统忽略的底层瓶颈。
*   **兼容性强**：不需要修改底层的注意力算子（Kernel），只需在控制面和传输层做文章，易于集成到现有静态图框架。
*   **确定性**：在提供动态灵活性的同时，保留了静态图低开销、无重编译的确定性优势。

### 8. 不足与局限
*   **应用限制**：主要针对单节点场景，未讨论在多节点张量并行或分布式解耦（Disaggregated Prefill/Decode）下的表现。

*   **硬件依赖**：虽然在 IPU 上做了验证，但核心优化（如 DMA 合并）高度依赖于 GPU 的内存拷贝和描述符管理机制，在其他非主流加速器上的普适性有待进一步观察。
