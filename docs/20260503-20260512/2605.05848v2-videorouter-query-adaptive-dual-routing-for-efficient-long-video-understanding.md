## 摘要
视频大多模态模型日益面临可扩展性瓶颈：长视频会产生极长的视觉标记（token）序列，这在推理过程中显著增加了内存占用和延迟。虽然现有的压缩方法在特定场景下有效，但大多数方法要么对查询的感知较弱，要么在不同帧之间应用固定的压缩策略，当视觉证据在时间上分布不均时，这些方法往往并非最优。为了解决这一问题，我们提出了 VideoRouter，这是一个基于 InternVL 构建的查询自适应双路由器框架，用于在预算限制下进行证据分配。语义路由器（Semantic Router）负责预测主导分配策略，在广泛的时间覆盖与自适应高分辨率保留之间做出选择；而图像路由器（Image Router）则利用大语言模型（LLM）的早期层对帧相关性进行评分。这使得模型能够对相关性较低的帧进行激进压缩，同时保留关键证据帧的细节。为了训练这两个路由器，我们构建了用于分配策略监督的 Video-QTR-10K 数据集和用于帧相关性监督的 Video-FLR-200K 数据集。在 VideoMME、MLVU 和 LongVideoBench 上的实验表明，在相当或更低的预算下，VideoRouter 相比 InternVL 基线模型取得了持续的改进，并实现了高达 67.9% 的标记削减。

## Abstract
Video large multimodal models increasingly face a scalability bottleneck: long videos produce excessively long visual-token sequences, which sharply increase memory and latency during inference. While existing compression methods are effective in specific settings, most are either weakly query-aware or apply a fixed compression policy across frames, proving suboptimal when visual evidence is unevenly distributed over time. To address this, we present VideoRouter, a query-adaptive dual-router framework built on InternVL for budgeted evidence allocation. The Semantic Router predicts the dominant allocation policy, choosing between broad temporal coverage and adaptive high-resolution preservation, while the Image Router uses early LLM layers to score frame relevance. This enables aggressive compression on less relevant frames while preserving detail on critical evidence frames. To train both routers, we build Video-QTR-10K for allocation-policy supervision and Video-FLR-200K for frame-relevance supervision. Experiments on VideoMME, MLVU, and LongVideoBench show that VideoRouter consistently improves over the InternVL baseline under comparable or lower budgets, achieving up to a 67.9% token reduction.

#### 1. 核心问题与整体含义

#### 2. 方法论
VideoRouter 提出了一个**查询自适应的双路由框架**，主要包含以下核心组件：

*   **双路由器架构**：
    *   **语义路由器 (Semantic Router)**：作为轻量级策略分类器，分析用户查询（Question）。它决定采用“全局策略”（Global，侧重均匀的时间覆盖）还是“片段策略”（Fragment，侧重局部高分辨率保留）。
    *   **图像路由器 (Image Router)**：当选择片段策略时，该路由器利用 LLM 的前几层（Shadow Stack）作为特征提取器，计算每一帧与查询的相关性得分。
*   **关键技术细节**：
    *   **特征复用**：为了保持轻量化，路由器复用了 InternVL 骨干网络中 LLM 的前 4 层解码器层，捕捉多模态融合特征。
    *   **动态预算分配算法**：根据 LLM 的最大上下文长度、文本长度和预留生成长度，动态计算可用的视觉 Token 预算 $B_{img}$。
    *   **优先级感知池化**：根据相关性得分进行差异化空间池化。相关帧保留高分辨率（如 Scale=1），无关帧进行激进压缩（如 Scale=4），若预算仍超标则按优先级丢弃低相关性帧。
*   **监督数据构建**：
    *   **Video-FLR-200K**：包含 20 万个 QA 对，带有帧级相关性标注。
    *   **Video-QTR-10K**：包含 1 万个视频-查询对，带有分配策略标签。

#### 6. 主要结论与发现
*   **性能提升**：VideoRouter 在显著减少 Token（最高减少 67.9%）的情况下，性能依然优于或持平于全量 Token 的基线模型。
*   **动态分配的价值**：在预算极度匮乏时，动态分配比增加采样帧数更有效；在预算充足时，增加采样帧数配合动态压缩能达到更高的性能上限。
*   **效率优势**：虽然引入了额外的路由计算开销，但由于 LLM Prefill 阶段处理的 Token 大幅减少，整体推理延迟和内存占用均显著下降。

#### 7. 优点
*   **查询自适应**：打破了传统方法“一刀切”的压缩模式，实现了真正的按需分配。
*   **轻量且高效**：复用 LLM 早期层特征，无需引入庞大的额外参数。
*   **端到端可控**：引入了明确的 Token 预算机制，能够根据硬件限制动态调整压缩率，避免 OOM（显存溢出）。
*   **数据贡献**：开源了两个大规模的路由监督数据集，填补了该领域的空白。

#### 8. 不足与局限
*   **骨干网络局限**：主要实验集中在 8B 规模的模型上，尚未在超大规模模型（如 70B+）上广泛验证。
*   **离线采样依赖**：目前仍依赖于预先采样的帧，而非完全在线的流式处理。
*   **监督偏差风险**：由于训练数据是由更强的 VLM/LLM 自动生成的，可能存在教师模型的固有偏差。
*   **复杂场景挑战**：对于同时需要极高空间细节和极长时序逻辑的极端复杂查询，双路由策略仍存在证据丢失的风险。
