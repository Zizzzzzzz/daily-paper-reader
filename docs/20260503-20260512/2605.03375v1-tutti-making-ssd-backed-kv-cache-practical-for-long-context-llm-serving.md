## 摘要
大语言模型（LLM）推理服务依赖前缀缓存（prefix caching）来提升推理性能。随着上下文长度的增加，键值（KV）缓存的占用空间远超 GPU HBM 和 CPU DRAM 的容量，因此 KV 缓存越来越多地被卸载到 NVMe SSD。然而，从 SSD 恢复 KV 缓存面临 I/O 性能差和严重的 GPU 停顿问题。这主要是因为碎片化的 GPU 内存布局导致了大量微小的随机 I/O，使得低并行度的 CPU 即使在使用 GPU Direct Storage (GDS) 的情况下也成为了严重的瓶颈，因为 GDS 仍依赖 CPU 干预来发起每次 I/O，本质上仍是以 CPU 为中心的。本文提出了 Tutti，一种高效的基于 SSD 的 KV 缓存解决方案，它消除了 HBM 与 SSD 之间关键数据和 I/O 控制路径上的 CPU 干预。Tutti 的核心是一个以 GPU 为中心的 KV 缓存对象存储，其中 CPU 仅负责每层一次地向 GPU 异步加载 I/O 内核。Tutti 通过以下设计实现了 NVMe SSD 带宽的饱和利用，并将 GPU 停顿降至接近零：(i) 提供 GPU 原生对象抽象，支持批量 KV 缓存传输与管理；(ii) 通过引入 GPU io_uring 重新构建 GPU 存储栈，以支持异步 GPU 直接对象 I/O；(iii) 提出松弛感知的 I/O 调度，以避免 GPU 资源竞争。我们实现了 Tutti 并将其集成到 vLLM 中。广泛的评估表明，与最先进的启用 GDS 的基于 SSD 的 LMCache 相比，Tutti 在严格的服务水平目标（SLO）约束下将首字延迟（TTFT）降低了 78.3%，并将可达到的请求速率提高了 2 倍。服务成本降低了 27%。Tutti 实现了与基于 DRAM 的 LMCache 几乎相同的推理性能，同时提供了近乎无限的容量。

## Abstract
LLM serving relies on prefix caching to improve inference performance. As growing contexts push key-value (KV) cache footprint far beyond GPU HBM and CPU DRAM capacity, KV cache is increasingly offloaded to NVMe SSDs. Unfortunately, restoring KV cache from SSDs suffers from poor I/O performance and incurs significant GPU stalls. This is primarily because the fragmented GPU memory layout results in a massive number of tiny random I/Os, rendering the low-parallelism CPU a severe bottleneck even with GPU Direct Storage (GDS), which still relies on CPU intervention to initiate each I/O and thus remains CPU-centric. This paper presents Tutti, an efficient SSD-backed KV caching solution that eliminates CPU intervention from the critical data and I/O control paths between HBM and SSDs. At the core of Tutti is a GPU-centric KV cache object store, in which the CPU is only responsible for asynchronously loading I/O kernels once per layer to the GPU. Tutti saturates NVMe SSD bandwidth and reduces GPU stalls to near zero through the following designs: (i) we provide a GPU-native object abstraction that enables bulk KV cache transfers and management; (ii) we re-architect the GPU storage stack by introducing GPU io_uring to support asynchronous GPU direct object I/O; and (iii) we propose slack-aware I/O scheduling to avoid GPU resource contention. We have implemented Tutti and integrated it to vLLM. Extensive evaluation shows that compared to the state-of-the-art GDS-enabled, SSD-backed LMCache, Tutti reduces TTFT by 78.3% under strict SLO constraints and improves the achievable request rate by 2x. The serving cost is reduced by 27%. Tutti achieves nearly the same inference performance as DRAM-backed LMCache, while providing almost infinite capacity.

### 1. 论文的核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）上下文窗口的不断扩大（如百万级 token），KV Cache（键值缓存）的体积已远超 GPU 显存（HBM）甚至系统内存（DRAM）的承载能力。为了降低重复计算成本，将 KV Cache 卸载到 NVMe SSD 成为必然选择。
然而，现有的 SSD 后端方案存在严重瓶颈：
*   **CPU 中心化架构的局限性：** 即使使用 NVIDIA GDS（GPU Direct Storage），I/O 的发起和控制仍依赖 CPU。
*   **碎片化 I/O 挑战：** LLM 引擎（如 vLLM）采用分页内存管理，导致 KV Cache 在物理上极度碎片化。从 SSD 恢复数据时会产生大量微小的随机 I/O，导致 CPU 成为瓶颈，GPU 产生高达 70%-80% 的停顿（Stalls）。
*   **性能倒挂：** 在某些情况下，从 SSD 加载缓存的速度甚至慢于直接重新计算。

**Tutti 的目标**是构建一个**以 GPU 为中心**的存储架构，彻底消除 I/O 路径上的 CPU 干预，使 SSD 缓存性能接近 DRAM。

---

### 2. 论文提出 Method 论
Tutti 的核心思想是将数据平面和控制平面全部移交给 GPU，主要包含以下三个关键技术：

*   **GPU 原生对象抽象（GPU-Centric Object Store）：**
    *   将 KV Cache 块映射为“对象”，由 CPU 预先管理元数据（如哈希索引），但在关键路径上由 GPU 直接访问。
    *   引入 **SGL（分散聚合列表）** 代替传统的 PRP（物理页区域），将内存映射开销从 GB 级降低到 MB 级，并支持大块连续传输。
*   **GPU io_uring (gio_uring)：**
    *   在 GPU 端模拟 Linux 的 `io_uring` 机制，建立基于 HBM 的无锁环形缓冲区（SQ/CQ）。
    *   GPU 线程可以直接提交 I/O 请求并轮询完成状态，无需 CPU 介入。
    *   通过 **SM 分区（SM Partitioning）** 技术，将 GPU 资源划分为“计算域”和“I/O 控制域”，确保 I/O 内核不会阻塞模型计算。
*   **松弛感知 I/O 调度（Slack-Aware I/O Scheduler）：**
    *   **离线分析：** 预先分析模型每一层计算中的“松弛时间”（即 GPU 利用率较低的窗口）。
    *   **在线调度：** 在计算空隙中插入 I/O 操作，并采用读写分离策略，避免 SSD 内部缓存竞争导致的带宽骤降（最高可避免 60% 的带宽损失）。
