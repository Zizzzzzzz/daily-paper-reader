## 摘要
视频大多模态模型日益面临可扩展性瓶颈：长视频会产生极长的视觉 Token 序列，导致推理过程中的内存占用和延迟剧增。尽管现有的压缩方法在特定场景下有效，但大多数方法要么对查询的感知较弱，要么对所有帧应用固定的压缩策略，在视觉证据随时间分布不均时表现欠佳。为解决这一问题，我们提出了 VideoRouter，这是一个基于 InternVL 构建的查询自适应双路由框架，用于在预算限制下进行证据分配。语义路由器（Semantic Router）预测主导分配策略，在广泛的时间覆盖和自适应高分辨率保留之间进行选择；而图像路由器（Image Router）则利用大语言模型（LLM）的早期层对帧相关性进行评分。这使得模型能够对相关性较低的帧进行大幅压缩，同时保留关键证据帧的细节。为了训练这两个路由器，我们构建了用于分配策略监督的 Video-QTR-10K 数据集和用于帧相关性监督的 Video-FLR-200K 数据集。在 VideoMME、MLVU 和 LongVideoBench 上的实验表明，在相当或更低的预算下，VideoRouter 相比 InternVL 基准模型取得了持续的改进，并实现了高达 67.9% 的 Token 削减。

## Abstract
Video large multimodal models increasingly face a scalability bottleneck: long videos produce excessively long visual-token sequences, which sharply increase memory and latency during inference. While existing compression methods are effective in specific settings, most are either weakly query-aware or apply a fixed compression policy across frames, proving suboptimal when visual evidence is unevenly distributed over time. To address this, we present VideoRouter, a query-adaptive dual-router framework built on InternVL for budgeted evidence allocation. The Semantic Router predicts the dominant allocation policy, choosing between broad temporal coverage and adaptive high-resolution preservation, while the Image Router uses early LLM layers to score frame relevance. This enables aggressive compression on less relevant frames while preserving detail on critical evidence frames. To train both routers, we build Video-QTR-10K for allocation-policy supervision and Video-FLR-200K for frame-relevance supervision. Experiments on VideoMME, MLVU, and LongVideoBench show that VideoRouter consistently improves over the InternVL baseline under comparable or lower budgets, achieving up to a 67.9% token reduction.

### 1. 核心问题与整体含义（研究动机和背景）
长视频理解在多模态大模型（MLLM）中面临严重的**扩展性瓶颈**。长视频生成的视觉 Token 序列极长，导致推理时的内存占用和延迟呈指数级增长。现有的压缩技术（如 Token 丢弃或均匀池化）存在两个主要缺陷：
*   **查询感知弱**：压缩决策往往在理解问题之前就已做出，忽略了不同问题对视觉细节的需求差异。
*   **策略固定**：对所有视频帧应用统一的压缩率，但在长视频中，关键证据往往只分布在少数帧中，均匀压缩会破坏关键细节。
**研究动机**：将长视频压缩建模为一个“预算化的证据分配”问题，即在有限的 Token 预算内，动态决定是追求“全局覆盖”还是“局部高精”。

### 2. 方法论：核心思想与关键技术
VideoRouter 提出了一个**查询自适应的双路由框架**，其核心组件包括：
*   **双路由架构**：
    *   **语义路由器 (Semantic Router)**：轻量级分类器，分析问题文本，决定分配策略是“全局模式”（Global，侧重全视频粗略覆盖）还是“片段模式”（Fragment，侧重关键帧的高清保留）。
    *   **图像路由器 (Image Router)**：复用 LLM 的前 4 层（影子栈）作为特征提取器，计算每一帧与问题的相关性得分。
*   **预算约束的动态分配算法**：
    *   根据 LLM 最大上下文长度动态计算可用视觉 Token 预算 $B_{img}$。
    *   **优先级池化**：若为片段模式，优先以高分辨率（Scale=1）保留相关帧，对不相关帧进行大幅下采样（Scale=4）；若预算极度受限，则按优先级丢弃帧。
*   **监督数据构建**：
    *   **Video-FLR-200K**：通过反向 QA 生成技术，标注回答特定问题所需的最小关键帧集合。
    *   **Video-QTR-10K**：通过 A/B 测试对比不同策略的性能，为问题类别标注最优分配策略。

### 3. 实验设计
*   **数据集/场景**：在多个主流长视频理解基准上进行评估，包括 **Video-MME**（全长度覆盖）、**LongVideoBench**（长上下文交织理解）、**MLVU**、**LVBench** 和 **EgoSchema**。
*   **基准模型 (Benchmark)**：主要基于 **InternVL3-8B**，并验证了在 **Qwen2.5-VL** 上的迁移能力。
*   **对比方法**：
    *   **原生模型**：InternVL3, Qwen2.5-VL。
    *   **压缩方法**：FastV, PruMerge, DyToK, QTSplus, DToMA, DIG 等。
    *   **受控基准**：均匀池化 (Uniform Pooling)、基于 CLIP 的相关性池化。

### 4. 资源与算力
*   **硬件设备**：实验使用了 **4 台 NVIDIA H20 GPU**。
*   **训练流程**：采用三阶段训练：
    1.  图像路由器预训练（5 epoch）。
    2.  语义路由器训练（2 epoch）。
    3.  联合微调（Joint Fine-tuning，1 epoch）。
*   **推理效率**：虽然增加了路由器的前向计算，但由于大幅减少了 LLM 的 Prefill Token 数量，总推理时间（TTFT）和峰值内存均显著下降。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了 5 个主流数据集，进行了详尽的对比实验。
*   **消融实验**：针对双路由器的各自贡献、LLM 早期层抽取的深度（k 层）、训练策略（是否联合微调）等进行了多组消融研究。
*   **客观性与公平性**：论文特别设置了“受控比较”（Controlled Comparison），在相同的输入帧数和 Token 预算下对比不同压缩策略，排除了因数据量差异带来的干扰，实验设计较为严谨客观。

### 6. 主要结论与发现
*   **效率与精度双赢**：VideoRouter 在减少高达 **67.9%** 视觉 Token 的情况下，性能依然优于或持平于全量 Token 的基准模型。
*   **动态分配的必要性**：在预算极度匮乏时，保留关键帧的质量比增加采样帧数更重要；而在预算充足时，增加采样帧数能提供更好的时间覆盖。
*   **早期层特征有效性**：LLM 的前 4 层已具备足够的跨模态语义对齐能力，足以支撑高精度的帧相关性评分。

### 7. 优点（亮点）
*   **自适应性强**：不再是死板的压缩，而是根据“问题”来决定“看哪里”和“看多清”。
*   **轻量化集成**：通过复用 LLM 早期层，避免了引入沉重的额外参数，且推理开销可被 Token 减少带来的收益抵消。
*   **高质量数据集**：贡献了两个专门用于路由监督的大规模数据集，填补了该领域的空白。

### 8. 不足与局限
*   **模型依赖**：主要在 InternVL3-8B 上验证，虽然做了 Qwen 的迁移，但在更大规模或其他架构模型上的泛化性仍需更多验证。
*   **离线假设**：目前假设可以访问完整的采样帧序列，对于流式或超长实时视频处理的适配性未深入讨论。
*   **监督偏差**：由于训练数据是由更强的 VLM/LLM 辅助生成的，可能存在教师模型的固有偏差或噪声。
