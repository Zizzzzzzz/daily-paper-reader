## 摘要
现有针对全模态大语言模型的令牌压缩方法通常依赖一种模态来决定在另一种模态中保留什么。我们发现这一假设常常失效：对于同一查询，音频和视频的相关性往往在不同时刻达到峰值。这种跨模态显著度不匹配使得单向引导容易在激进压缩下丢弃关键线索。我们提出OmniScope，一种无需训练的令牌压缩框架，它利用查询作为共享语义锚点，同时分别估计音频和视频的相关性。OmniScope分配模态特定的令牌预算，采用锚点-增量策略修剪视觉令牌以保留全局上下文和时间变化，并在每秒内合并音频令牌以减少冗余同时保持时间连续性。在四个音频-视频基准测试和两个Qwen2.5-Omni模型规模上，OmniScope在所有压缩设置下均获得最佳平均准确率。在整体令牌保留25%时，它实现高达3.53倍的预填充加速和超过15%的GPU内存减少，平均准确率仅下降0.35个百分点。这些结果表明全模态大语言模型推理的一个简单设计原则：跨模态共享查询，但不共享显著度估计。代码开源在 https://github.com/MAC-AutoML/OmniScope。

## Abstract
Existing token compression methods for omnimodal large language models typically rely on one modality to determine what to retain in the other. We show that this assumption often breaks down: for the same query, audio and video relevance often peaks at different moments. This cross-modal salience mismatch makes unidirectional guidance prone to discarding answer-critical cues under aggressive compression. We propose OmniScope, a training-free token compression framework that uses the query as a shared semantic anchor while estimating relevance separately for audio and video. OmniScope allocates modality-specific token budgets, prunes visual tokens with an anchor-delta strategy that preserves both global context and temporal changes, and merges audio tokens within each second to reduce redundancy while maintaining temporal continuity. Across four audio-video benchmarks and two Qwen2.5-Omni model scales, OmniScope achieves the best average accuracy across all compression settings. At 25% overall token retention, it delivers up to 3.53x prefill speedup and more than 15% GPU memory reduction, with only a 0.35-point drop in average accuracy. These results suggest a simple design principle for OmniLLM inference: share the query across modalities, but not the salience estimates. The code is available at https://github.com/MAC-AutoML/OmniScope.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：全模态大语言模型（OmniLLM）能联合处理视觉、听觉和文本，但音频和视频编码后会产生大量令牌，导致推理计算和内存开销剧增。令牌压缩是缓解此瓶颈的关键。
- **现有方法的不足**：已有的全模态令牌压缩方法（如OmniZip）通常采用单向跨模态引导策略，即让一种模态的显著度决定另一种模态的保留。然而，同一查询下音频和视频的相关性峰值往往在不同时刻出现，这种“跨模态显著度不匹配”使得单向引导在高压缩比下容易丢弃另一模态中的关键线索。
- **核心挑战**：如何在不依赖跨模态显著度估计的前提下，独立压缩各模态令牌，同时保持查询相关的语义完整性。

### 2. 论文提出的方法论

- **核心思想**：以查询（query）作为共享语义锚点，让视觉和音频分别独立评估自身令牌的重要性并分配压缩预算，避免单向跨模态引导的脆弱性。
- **关键技术细节**：
  - **Query-Aware Scoring（查询感知评分）**：
    - **视觉评分**：使用外部模型CLIP计算每帧与查询的余弦相似度作为重要性。
    - **音频评分**：利用OmniLLM自身的音频编码器输出（经投影后）与文本查询嵌入的gated交叉相似度，按秒聚合并通过邻居增强传播。
  - **Token Budget Allocation（令牌预算分配）**：基于重要性分数，按比例为每帧/每秒分配保留的令牌数，各模态独立配置压缩率。
  - **视觉压缩——AD-STC（Anchor-Delta Spatio-Temporal Compression）**：
    - **Anchor帧（偶数索引）**：使用DPC-KNN（密度峰值聚类）保留空间最独特、密度最低的令牌。
    - **Delta帧（奇数索引）**：根据保留率动态切换策略：高预算时采用联合不可替代性分数（同时考虑空间和时间冗余，乘积融合）；低预算时仅保留与前一帧变化最大的令牌（时间差分）。
    - 两者交替确保全局覆盖率与时间增量的平衡。
  - **音频压缩——Per-Second Token Merging**：
    - 在每秒钟内，通过二分软匹配（bipartite soft matching）合并冗余令牌，而非直接丢弃，保持时间连续性。
    - 将偶数索引令牌视为源集，奇数索引为目标集，匹配相似度最高的对，并求平均融合。
- **算法流程**（文字描述）：先使用CLIP和模型自身音频评分分别得到视觉/音频重要性 → 按比例分配每帧/每秒保留数 → 视觉侧：Anchor帧选密度最低令牌，Delta帧根据保留率选低不可替代性或低时间相似性令牌 → 音频侧：每秒钟内迭代执行二分软匹配直至达到保留数 → 将压缩后的令牌输入LLM。

### 6. 论文的主要结论与发现

- OmniScope在所有压缩设置下（45%和25%保留）均获得最高平均准确率，45%保留时几乎无损（+0.30和+0.03）。

- 跨模态显著度不匹配普遍存在（78.3%查询-视频对的相关性弱），证明单向引导不可靠。
- 设计原则：全模态推理应共享查询但不共享显著度估计。

### 7. 优点

- **创新性**：首次明确提出跨模态显著度不匹配问题，并设计解耦压缩方案。

- **通用性**：在两种模型规模、多个基准、多种压缩率下一致最优。
- **效率出色**：预填充速度提升显著，内存节省可观，且CLIP评分开销随生成长度增加而摊薄。
