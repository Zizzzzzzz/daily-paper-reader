## 摘要
长上下文、多轮和代理型LLM工作负载越来越多地重复使用先前处理过的上下文，使得KV缓存复用对于减少冗余计算至关重要。然而，这种复用将瓶颈转移到了存储和提供可复用KV状态的存储层，且规模达到集群级别。GPU HBM和主机DRAM成本过高，难以扩展到TB级的共享上下文容量，因此需要由低成本、高容量的介质构建的远程存储层。本文提出了HyMCache，一个集成CXL混合内存（CXL-HM）用于多轮LLM服务的KV缓存框架。CXL-HM将少量设备内DRAM与CXL接口后的大容量SSD存储相结合。通过利用多轮KV缓存访问的读主导、可预测和仅追加特性，HyMCache重新思考了CXL-HM内的DRAM管理，以高效支持TB级SSD存储的KV复用。它使用请求级前缀预取和机会性写缓冲，将延迟关键的读操作分阶段放入设备DRAM，从而以SSD级别的成本实现DRAM级别的KV缓存效率。我们在真实CXL-HM原型上，在单聚合器和PD分离服务配置下评估了HyMCache。在相同DRAM预算下，HyMCache在单节点服务中性能优于本地LMCache 3.0倍，在PD分离服务中性能优于1.45倍。与1TB分布式DRAM Mooncake相比，HyMCache性能降低约30%，但DRAM使用量减少16倍。

## Abstract
Long-context, multi-turn, and agentic LLM workloads increasingly reuse previously processed context, making KV-cache reuse essential for reducing redundant computation. However, this reuse shifts the bottleneck to the memory tier that stores and serves reusable KV states at cluster scale. GPU HBM and host DRAM are too costly to scale to TB-scale shared context capacity, motivating remote tiers built from lower-cost, higher-capacity media. This paper presents HyMCache, a KV-cache framework that integrates CXL-hybrid memory (CXL-HM) for multi-turn LLM serving. CXL-HM combines a small amount of in-device DRAM with large SSD-backed capacity behind a CXL interface. By exploiting the read-dominant, predictable, and append-only nature of multi-turn KV-cache access, HyMCache rethinks DRAM management within CXL-HM to efficiently support TB-scale SSD-backed KV reuse. It uses request-level prefix prefetching and opportunistic write buffering to stage latency-critical reads in device DRAM, enabling DRAM-scale KV-cache efficiency at SSD-level cost. We evaluate HyMCache on a real CXL-HM prototype under both single-aggregator and PD-disaggregated serving configurations. Under the same DRAM budget, HyMCache outperforms local LMCache by 3.0x in single-node serving and 1.45x in PD-disaggregated serving. Compared with 1 TB distributed-DRAM Mooncake, HyMCache incurs about 30% lower performance but uses 16x less DRAM.

# 论文 HyMCache 详细中文总结

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：多轮、长上下文和代理型（Agentic）LLM工作负载中，KV缓存重用可以大幅减少冗余计算，但重用导致存储瓶颈。GPU HBM和主机DRAM成本极高，难以扩展到TB级共享上下文容量，亟需低成本、高容量的远程存储/内存层。
- **整体含义**：将KV缓存层次结构从昂贵的DRAM向更经济的存储介质（如SSD）扩展，同时保持低延迟访问。CXL混合内存（CXL-HM）结合少量设备DRAM与大容量SSD，通过CXL接口暴露为内存地址空间，为LLM服务提供一种成本-性能折中方案。HyMCache框架旨在利用多轮KV访问模式（读主导、可预测、仅追加）来优化CXL-HM内部DRAM管理，实现“DRAM级效率、SSD级成本”。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：在CXL-HM设备中，不使用通用LRU缓存，而是利用LLM服务层已知的KV对象访问顺序（前缀预取），由服务框架显式指导设备DRAM的预取和释放，使延迟关键的KV读取尽可能命中设备DRAM，而大部分数据驻留在SSD中。
- **关键技术细节**：
  - **请求级前缀预取**：服务框架通过`chm_prefetch_object`、`chm_prefetch_wait`、`chm_prefetch_release`三个API，将后续可能被重用的KV块预先从SSD加载到设备DRAM。
  - **读优先写隔离（Read-Prioritized Write-Isolated KV Flushing）**：写操作（新生成KV）与读操作隔离，采用机会性写缓冲，避免后台写与前台读争抢SSD带宽。
  - **统一CXL-HM地址空间**：多个CXL-HM设备映射为CPU-less NUMA节点，通过HyMCache KV Manager进行请求级NUMA分配（round-robin或负载感知），保持有序访问。
  - **支持异构KV对象大小**：每个请求携带模型专属KV对象大小，KV Manager据此动态调整预取窗口（如每个请求最多8个16MB块或4个32MB块）。
  - **软件模块**：HyMCache Master（全局元数据）、HyMCache Lookup（早期远程命中匹配、批量查询、协调预取）、HyMCache KV Connector（集成到vLLM的回调，执行RDMA读/写）、HyMCache KV Manager（管理CXL-HM预取和资源）。
- **算法流程（文字说明）**：
  1. 请求到达后，GPU前缀缓存和可选的DRAM缓存（如LMCache）进行匹配。
  2. 剩余未匹配的KV块由Lookup模块向Master查询，并立即向KV Manager发送预取提示（按读取顺序）。
  3. KV Manager调用CXL-HM预取API，将即将被读取的KV对象从SSD分阶段加载到设备DRAM。
  4. 当Worker准备好读取时，通过RDMA GET直接从CXL-HM地址空间获取（如果预取已完成则命中DRAM）。
  5. 新生成KV块通过RDMA PUT写入CXL-HM地址空间，由KV Manager异步刷新到SSD。

- **大量对比实验**：与当前主流方案（LMCache、Mooncake、NVMe-oF）全面比较，覆盖不同部署模式和预算。
- **成本效益突出**：以极低DRAM成本达到接近分布式DRAM的性能，对大规模推理集群有实际指导意义。

## 8. 不足与局限

- **硬件原型限制**：CXL-HM原型基于FPGA，成本被开发板主导，且非商用产品，可能未充分反映量产性能功耗比。

- **写跳过问题**：约15%的新KV块因写缓冲区满无法写入，在未来工作负载更重时可能更严重。
- **模型与规模覆盖有限**：仅测试8B和32B模型，未涉及70B+参数或数百万token超长上下文场景。

- **实验规模**：单集群实验（4个预填充节点），未在更大集群（如数十节点）中验证可扩展性。
