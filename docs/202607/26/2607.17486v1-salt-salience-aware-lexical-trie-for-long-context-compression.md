## 摘要
随着大型语言模型（LLMs）处理越来越长的提示，计算和KV缓存内存成本已成为推理系统中的主要瓶颈。现有的输入级提示压缩方法解决了这一问题，但通过标量相关性分数对每个句子进行排序，将文档视为非结构化的单词和句子集合。在严格的预算下，这会导致主题坍缩，即文档中的主导主题消耗了预算，忽略了较少出现但任务相关的主题。为了保持主题覆盖，需要跨重复主题分配预算，而不是孤立地对句子进行评分。为此，我们提出了SALT，一种与模型无关的抽取式框架，它将每个句子的关键词组织成一个按句子频率（SF）排序的词汇树，句子频率是文档主题结构的轻量级、可重用代理。这种基于词汇树的结构平滑了内存分配，并防止了主导主题垄断预算。多锚点检索会激活由查询关键词标记的任何深度的词汇树节点，并且词汇树在对话轮次中持续存在，支持无需重新编码文档的多轮使用。通过保留文档主题，SALT减少了长上下文提示的预填计算和内存成本，同时与针对解码时延和内存的KV缓存方法兼容。

## Abstract
As large language models (LLMs) process increasingly longer prompts, computation and KV-cache memory costs have emerged as major bottlenecks in inference systems. Existing input-level prompt compression methods address this, but rank each sentence by a scalar relevance score, treating the document as an unstructured pool of words and sentences. Under tight budgets, this causes theme collapse, where the dominant theme(s) of a document consumes the budget, discarding less-frequent yet task-relevant themes. Preserving thematic coverage instead requires allocating the budget across recurring themes rather than scoring sentences in isolation. To this end, we propose SALT, a model-agnostic extractive framework that organizes per-sentence keywords into a trie ordered by sentence frequency (SF), a lightweight, reusable proxy for document thematic structure. This trie-based organization smooths memory allocation and prevents dominant themes from monopolizing the budget. Multi-anchor retrieval activates trie nodes labeled by query keywords at any depth, and the trie persists across dialogue turns, supporting multi-turn use without re-encoding the document. By preserving document themes, SALT reduces the prefill computation and memory cost of long-context prompts while remaining composable with KV-cache methods that target decoding-time latency and memory.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题**：大型语言模型（LLMs）处理长上下文（>32k tokens）时，预填计算和KV缓存内存成为主要瓶颈。
- **现有方法缺陷**：输入级压缩方法（如EXIT、RECOMP）通常对每个句子独立计算标量相关性分数，按排名填充预算。这导致**主题坍缩（theme collapse）**：高频主题占据大部分预算，低频但对任务重要的主题被丢弃，尤其是在多跳问答等需要跨主题推理的场景。
- **整体目标**：提出一种**主题感知的压缩框架**，在压缩前先识别文档的主题结构，将预算在重复出现的主题间合理分配，而非单一全局排序。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- 将压缩问题重新定义为：在固定预算下**保留文档的主题覆盖**，而非最大化单个句子的分数。
- 利用**词汇级别的主题结构**（基于句子频率，SF）构建轻量级可复用索引，并在索引上执行预算分配与句子选择。

### 关键技术细节

#### (1) 索引阶段（Indexing）
- **句子分割**：将文档分为N个句子。
- **关键词提取**：使用**BGE-small-en-v1.5**（轻量编码器）对每个句子提取关键词。
  - 方法：利用[CLS]注意权重排序句子中的内容词；通过**Kneedle算法**确定保留词数（上限40%），以最大程度重建原句嵌入。
  - 输出：每个句子的关键词集合 \(K_i\)（含注意权重）。
- **句子频率**：统计每个关键词跨所有句子出现的频次 \(SF(w)\)，保留处于p分位数以上（默认p=0.9）的词汇构成**显著集S**。
- **词汇树构建**：
  - 对每个句子 \(s_i\)，将其关键词集与显著集取交集 \(T_i = K_i \cap S\)，并按关键词的SF降序排序。
  - 将排序后的序列作为从根到叶的路径插入Trie，叶子节点存储句子ID。
  - 一个句子的多个关键词形成路径，**公共前缀对应共享高频关键词的句子组**。
- **覆盖质量度量**：对Trie节点v，定义其子树的关键词签名\(\Gamma(v)\)。给定已选集合R，节点v的**未覆盖质量** \(U_v(R) = \sum_{w \in \Gamma(v) \setminus C_v(R)} cSF(w)\)，其中\(cSF(w)\)为归一化句子频率。

#### (2) 预算约束选择（Budget-Constrained Selection）
- 统一算法（Algorithm 1）：
  1. 设置初始空集R。
  2. **查询模式**（若给定查询x）：
     - 提取查询关键词 \(K_q\) 和嵌入 \(e_q\)。
     - 激活Trie中与查询关键词匹配的节点（包括之前因频率低被剪枝的关键词）。
     - **锚点阶段**：根据词汇重叠和嵌入相似度选出前\(\beta_q B\)个候选及邻域句子。
  3. 计算剩余预算 \(B^*\)。
  4. 确定活跃分支集合B（Trie的第一层分支）。
  5. **分支分配**：对每个活跃分支b，分配配额 \(\beta_b\)：
     - 固定底线 + 按 \((M_b + \epsilon)^\alpha\) 比例分配（\(0<\alpha<1\)），\(M_b\)为分支剩余未覆盖质量。
     - 这种**亚线性指数压缩**防止高分数主题垄断预算。
  6. **分支阶段**：在每个分支内，按公式(5)评分句子：
     \[
     \text{score}_b(s_i | R) = \frac{\Delta_b(s_i | R)}{L(n_i)} \cdot I(s_i)
     \]
     其中边际收益\(\Delta_b\)为减少的未覆盖质量，\(L(n_i)\)偏好中等长度句子，\(I(s_i)\)包含位置/查询匹配先验。
  7. **全局填充**：若有剩余预算，在全局范围内选择未覆盖质量最大的句子。
  8. 输出按文档顺序排序的R。

- **模式**：
  - 摘要模式（无查询）：起始于根节点，直接分配分支配额。
  - 查询模式：通过多锚点激活，优先提取查询相关句子，剩余预算按主题分配。

#### (3) 多轮对话重用
- Trie一旦构建，可跨轮次重复使用，无需重新编码文档。每次查询仅需提取查询关键词并激活节点，成本极低（约11ms/轮）。

## 7. 优点

- **模型无关**：输出纯文本，可配合任何LLM和KV缓存方法。
- **轻量可复用**：索引构建一次，支持多轮查询/预算调整，无需重新编码。
- **主题覆盖显式保障**：通过Trie分支分配预算，而非事后多样性惩罚，从根本上防止主题坍缩。
- **多锚点检索**：查询模式通过激活所有含查询关键词的Trie节点（即使非主要锚点），避免丢失浅层匹配。
- **硬件兼容性广**：不依赖新架构专用内核（如FlashAttention），可在V100等旧GPU上运行。
- **实验充分**：涵盖多种任务、预算、长度、交互模式、硬件，与主流方法进行公平对比。

## 8. 不足与局限

- **代码任务弱点**：在代码类任务上性能明显下降（LongBench Code子项仅37.06），原因是句子级别粒度破坏了代码结构，词汇关键词无法捕捉标识符和运算符语义。所有预处理方法均存在此问题。
- **粒度限制**：句子级别操作，无法压缩到低于5-20%的极低预算（相比token级KV缓存方法可更激进）。作者承认这在某些场景下是下限。
- **依赖外部编码器**：使用BGE-small进行关键词提取，虽然轻量，但仍需一次额外前向传播。在超长上下文（256k+）中，编码时间仍占一定比例（但已被密集打包优化）。
- **未验证更大模型**：实验仅基于8B参数模型，未测试70B/405B等更大LLM，虽然方法理论上可扩展。
- **未提供不确定性度量**：实验结果未报告标准误或置信区间，难以判断差异的统计显著性。
- **未讨论隐私或安全性**：压缩可能无意中保留或丢弃敏感信息，论文未涉及。
