## 摘要
长上下文LLM服务现在支持数十万到数百万token的提示，使得键值（KV）缓存成为首要的服务成本。由于缓存随上下文长度线性增长，它会耗尽GPU内存，迫使批量变小，并降低服务吞吐量。现有的KV缓存压缩技术通常只针对序列维度或通道维度，当上下文窗口扩展时，这留下了有限的提升空间。同时压缩两个维度有望实现更高的内存减少，但直接应用这两种压缩形式会导致显著的准确率损失。本文介绍了MosaicKV，一种用于极长上下文服务的动态二维KV缓存压缩系统。MosaicKV利用动态二维压缩来解决准确率挑战，利用KV缓存内元素的重要性分布不均匀。MosaicKV不是全局应用一种压缩模式，而是为每个KV向量识别重要元素，并在KV缓存段的粒度上选择压缩策略。为了解决性能挑战（细粒度稀疏性和压缩管理开销可能抵消压缩带来的收益），MosaicKV引入了压缩KV缓存管理。该机制利用未被充分利用的GPU和CPU资源来维护压缩的KV缓存并加速注意力计算。在H800 GPU上对多个LLM的评估表明，与未压缩的基线相比，MosaicKV实现了高达16倍的注意力加速、4.8倍的解码延迟降低和7.3倍的吞吐量提升。同时，它将内存使用减少了3倍，并且在LongBench和RULER上仅导致平均1.76%的准确率损失。

## Abstract
Long-context LLM services now sustain prompts with hundreds of thousands to millions of tokens, making the key-value (KV) cache a first-order serving cost. Because the cache grows linearly with context length, it can exhaust GPU memory, force smaller batches, and reduce serving throughput. Prior KV cache compression techniques typically target only the sequence dimension or only the channel dimension, which leaves limited headroom as context windows scale. Compressing both dimensions promises higher memory reduction, but applying the two forms of compression directly leads to significant accuracy loss.   This paper introduces MosaicKV, a dynamic two-D (dimensional) KV cache compression system for extremely long-context serving. MosaicKV uses dynamic two-D compression to address the accuracy challenge, exploiting the non-uniform importance distribution of elements within the KV cache. Instead of applying one compression pattern globally, MosaicKV identifies important elements for each KV vector and selects compression strategies at the granularity of KV cache segments. To address the performance challenge, where fine-grained sparsity and compression management overhead can offset the gains from compression, MosaicKV introduces compressed KV cache management. This mechanism uses underutilized GPU and CPU resources to maintain compressed KV caches and accelerate attention computation.   Evaluation on an H800 GPU with multiple LLMs shows that MosaicKV delivers up to 16x attention speedup, 4.8x lower decode latency, and 7.3x higher throughput than the uncompressed baseline. At the same time, it reduces memory usage by 3x and incurs only 1.76% average accuracy loss on LongBench and RULER.

### 1. 核心问题与整体含义（研究动机和背景）

- **问题**：长上下文LLM推理时，KV缓存随上下文长度线性增长，严重占用GPU显存，导致批处理规模被迫缩小、解码延迟增加、吞吐量下降。例如，处理128K token的8个并发请求，KV缓存需128GB（模型权重的8倍）；1M token时可达1TB（模型权重的64倍）。
- **现有局限**：已有KV缓存压缩主要沿**序列维度**（选择重要token）或**通道维度**（压缩每个token的通道）单独进行，单维度压缩率受限。若将两种维度的压缩简单叠加，会导致显著的精度损失（实验显示，70%通道压缩叠加序列压缩后精度损失达82.8%）。
- **整体目标**：在极高压缩率下保持模型精度，同时利用压缩带来的性能收益，降低解码延迟、提高吞吐量。

### 2. 论文提出的方法论

- **核心思想**：关键在于利用KV缓存内元素重要性分布的非均匀性，采用**动态二维压缩**（Dynamic Two-D Compression），即同时沿通道和序列两个维度压缩KV缓存，且针对不同段采用自适应策略。为缓解稀疏访问带来的性能问题，引入**压缩KV缓存管理**，利用空闲的GPU CUDA核心和CPU资源加速计算与缓存维护。

- **关键技术细节**：
  - **两阶段二维压缩**：
    - **阶段1：逐向量通道压缩**（Stage-1 Per-Vector Channel Compression）：对每个KV向量，先通过SVD旋转将重要信息集中到若干通道，然后选择该向量内绝对值最大的前r个元素保留（而非全局统一掩码）。输入token的KV缓存直接在预填充阶段压缩；生成token则通过异步机制逐步压缩。
    - **阶段2：动态序列压缩**（Stage-2 Dynamic Sequence Compression）：在解码阶段每个注意力层前，将token划分为小块（如8个token），计算每块的键均值，然后根据当前query与每块键的点积分数，选择得分最高的前k块参与注意力计算。
  - **动态压缩策略**（Dynamic Compression Strategy）：
    - 将整个KV缓存切分为多个**段**（segment）。输入token的段在预填充时固定长度切分（如64K token）；输出token的段动态切分——维护一个压缩损失指标，当新token加入后损失超过阈值，则终止当前段并开始新段（同时限制最大段长）。
    - 每段独立选择压缩参数：通道压缩率、元素分组大小（1/2/4），序列压缩率、token块大小。
  - **压缩KV缓存管理**：
    - **Packed KV Format**：将稀疏向量压缩为密集格式，用位图记录保留元素的位置。元素分组进一步减少位图开销。
    - **Compressed KV Encoding**：在预填充阶段异步进行SVD、通道截断（丢弃全局低重要性通道）和转换为packed格式。
    - **PackedAttention**：在解码阶段直接在packed格式上计算注意力，无需解压。利用CUDA核心逐位图重建元素索引，与查询向量点积；将反旋转合并入单个查询向量计算，避免旋转整个矩阵。兼容FlashAttention。
    - **异构双缓冲压缩**（Heterogeneous Double Compression Buffering）：GPU侧保存临时压缩的当前段KV缓存，CPU侧维护未压缩的副本，异步执行段切分、SVD计算、策略生成和压缩，完成后替换GPU侧数据，不阻塞解码。
    - **增量策略生成**（Incremental Strategy Generation）：通过增量更新协方差矩阵加速SVD，对每个候选参数评估压缩损失后选择最高压缩率。

- **准确率**：在LongBench上平均准确率损失仅0.86%（相对Full），在RULER上平均1.86%损失；相对Quest损失更小（LongBench 0.64%，RULER 0.55%~2.69%）。

- **内存**：KV缓存内存减少3倍（75%通道压缩），同时支持3倍更大的批处理规模。
- **关键发现**：重要性分布的非均匀性是双维度压缩精度损失的根本原因，逐向量选择与动态段策略可有效缓解。

### 7. 优点

- **方法创新**：首次在解码全阶段（token选择与注意力计算）同时应用通道与序列二维压缩，且实现高精度。
- **细粒度适应性**：逐向量元素选择与段级动态策略，比统一压缩更符合实际数据分布。
- **高效管理**：利用空闲CUDA核心实现packed稀疏注意力，利用CPU异步处理缓存管理，避免在关键路径引入额外开销。
- **兼容性**：可集成FlashAttention、PagedAttention、RadixAttention等常见优化。
- **扩展性**：可与量化、KV缓存卸载等技术正交组合。

- **实验覆盖**：仅测试LLaMA-3.1-8B、Qwen3-4B、Ministral-3-8B三个模型，未在更大规模模型（如70B、MoE）或更长的上下文（1M+ token）上进行实际端到端测试，部分1M token结果是外推得到。
