## 摘要
一项伴随研究在2011年的NVIDIA Tesla C2075（费米架构，sm_20，6GB）上运行了一个35B的混合专家模型，采用GPU预填充/CPU解码混合方式，因为4位模型无法放入设备内存（arXiv:2606.24031）。本报告保持硬件不变，探讨一个能放入内存的模型能做什么：我们将MiniCPM-V-4.6——一个现代的、结合了SigLIP2视觉编码器和窗口注意力合并器（16倍视觉令牌压缩）与紧凑型混合门控-增量-网络骨干的多模态助手——完全部署在GPU上。三个结果：（i）一个建立在实测基础上的全GPU引擎：投影层一次性反量化8位权重并调用还在最后一个费米工具链中的供应商SGEMM（达到FP32峰值的64%；我们最好的手写GEMM达到37%，曾被误认为上限）；对循环层进行分块delta规则重写，在归因暴露一个不良内核后比顺序扫描快2.8倍；以及一个实测负面结果：4位权重在此处使解码比8位更慢，因为费米架构以半速率执行半字节解包移位。（ii）视觉侧是一个带有证明义务的移植：我们将编码塔、合并器和投影器转换为sm_20 CUDA，并对每个阶段通过本地生成的前向参考验证（整个编码塔误差1.4e-5）。一个失败案例——位置嵌入分桶在精确有理数相等时出现差异——推广为一条规则：索引算术中的浮点数平局打破是未定义行为；应调用参考算子，而非重新实现。（iii）长上下文暴露了短基准测试隐藏的O(N^2)瓶颈：在朴素的注意力内核中，预填充从2k令牌时的114 tok/s下降到10k时的21 tok/s；每个头调用供应商GEMM并写入现有的分数缓冲区（零额外内存）恢复了平坦的性能曲线（2k时408，10k时361；提升17倍），通过从60%深度精确取回针验证。同样的重写将图像编码时间降低6倍，至0.93秒。该系统端到端回答一个图像问题仅需1.7秒。

## Abstract
A companion study ran a 35B mixture-of-experts model on a 2011 NVIDIA Tesla C2075 (Fermi, sm_20, 6GB) as a GPU-prefill/CPU-decode hybrid, because the 4-bit model did not fit in device memory (arXiv:2606.24031). This report keeps the hardware and asks what a model that fits can do: we deploy MiniCPM-V-4.6, a modern multimodal assistant pairing a SigLIP2 vision encoder and window-attention merger (16x visual token compression) with a compact hybrid gated-delta-net backbone, entirely on the GPU. Three results. (i) An all-GPU engine built on measured foundations: projections that dequantize 8-bit weights once and call the vendor SGEMM still in the last Fermi toolchain (64% of FP32 peak; our best hand-written GEMM hit 37%, wrongly called the ceiling); a chunked delta-rule rewrite of the recurrent layers, 2.8x faster than the sequential scan once attribution exposed one bad kernel; and a measured negative: 4-bit weights make decode slower than 8-bit here, since Fermi issues nibble-unpacking shifts at half rate. (ii) The vision side is a port with a proof obligation: we translate tower, merger, and projector to sm_20 CUDA, validating every stage against a locally generated reference forward (full tower 1.4e-5). One failure, position-embedding bucketization differing on exact rational ties, generalizes to a rule: float tie-breaking in index arithmetic is implementation-defined; call the reference operator, do not reimplement it. (iii) Long context exposes an O(N^2) wall short benchmarks hide: prefill falls from 114 tok/s at 2k tokens to 21 at 10k in a naive attention kernel; per-head vendor-GEMM calls writing into the existing score buffer (zero extra memory) restore a flat profile (408 at 2k, 361 at 10k; 17x), verified by exact needle retrieval from 60% depth. The same rewrite cuts image encoding 6x, to 0.93s. The system answers an image question end-to-end in 1.7s.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：现代多模态大模型（如 MiniCPM-V-4.6）通常依赖较新的GPU硬件（张量核心、快速FP16等）。2011年的NVIDIA Tesla C2075（Fermi架构，6GB内存，无张量核心，峰值1.03 TFLOPS）已被主流软件生态抛弃（CUDA 8.0为其最后一个支持的工具链）。
- **动机**：前期工作（arXiv:2606.24031）在同样硬件上运行35B MoE模型时，因模型放不下只得采用GPU预填充/CPU解码混合方案。本论文则研究**当模型刚好能完全放入GPU内存时**，能否全 GPU 推理一个现代多模态助手，并探究速度与正确性的极限。
- **核心问题**：在Fermi GPU上，如何设计全GPU推理引擎？视觉栈能否可靠移植？长上下文是否暴露隐藏瓶颈？多项直觉（如手写GEMM天花板、4-bit解码更快、2k基准代表全貌）是否成立？

## 2. 论文提出的方法论

### 2.1 全GPU语言引擎（三块实测基石）

- **预填充投影（Prefill Projections）**：8位分组对称量化权重，每64个权重一个FP32缩放因子。先**一次性反量化**到FP32缓冲区，然后调用**cuBLAS SGEMM**进行矩阵乘法。这达到了FP32峰值的64%（手写寄存器分块GEMM仅37%）。反量化开销远小于调用手写GEMM的劣势，且被整个chunk的多个位置分摊。
- **循环层（Gated Delta-Net）的分块扫描**：将顺序的token-by-token循环重写为**块内（intra-chunk）+块间（inter-chunk）**公式。块内变为下三角矩阵系统，用两个小矩阵乘积求交互矩阵，然后进行前向替换求解；块间只有少量顺序状态的矩阵乘积。所有矩阵运算用批处理的小型cuBLAS GEMM实现。**关键修复**：最初的实现因一个糟糕的前向替换内核（重复计算已得出的点积且过度同步）导致2.4倍更慢，经组件归因暴露后，重写该内核，最终比顺序扫描**快2.8倍**。
- **解码时为何4位更慢**：解码是带宽受限的矩阵-向量乘法。4位需要从打包字节中解包，涉及移位和掩码操作。Fermi架构**以融合乘加的一半速率执行整数移位**，导致计算能力成为瓶颈，实际解码速度反而比8位版本**慢12%**。因此引擎保留8位解码（48.6 tok/s）。

### 2.2 视觉栈的阶段验证移植（Stage-Validated Porting）

- **整体策略**：由于宿主CPU无AVX，无法原生运行参考实现。通过设置CPU能力覆盖标志，强制库走旧代码路径，在本地生成31个阶段的参考前向轨迹（包括嵌入、27层编码器、窗口注意力合并器、下采样投影器）。
- **逐阶段验证**：每个手写CUDA内核（sm_20）输出与参考轨迹对比，要求绝对误差约1e-3才进入下一阶段。
- **失败案例与通用规则**：位置嵌入分桶（NaViT风格）在精确有理数相等（如10/28 = 25/70）时，参考实现的浮点数平局打破行为是**实现定义的**。尝试用float64、确切整数算术等待方式都会在某些网格上出错。结论：**对于可触及精确相等的索引算术，应直接调用参考算子，而非重新实现**。修复后全塔精度达到1.4e-5（多切片1.2e-4）。
- **窗口注意力合并器**：唯一真正需要新写的内核：在2×2窗口内运行自注意力（4 tokens），全部在共享内存中完成，然后串联并通过宽MLP投影。
- **多切片大图**：独立编码每个切片后拼合，验证与参考打包方式一致（1.2e-4精度）。

### 2.3 两个用cuBLAS重写的注意力模块（零额外内存技巧）

- **零分配技巧**：引擎现有的每（位置，头）注意力分数缓冲区（行主序）可以解释为头 h 的**列主序**分数矩阵（领先维度为 heads × seq），直接作为cuBLAS SGEMM的输出，**无需新分配内存**。
- **视觉编码器注意力**：双向，两次GEMM（QK^T + softmax + score*V）。编码1024片图像时间从5.7秒降至0.93秒（6.1倍）。
- **语言侧预填充注意力**：因果，全矩形GEMM后执行带因果遮罩的列softmax（只归一化有效前缀，尾部填充零）。使得10k令牌预填充从21 tok/s恢复到361 tok/s（17倍），且平面性能曲线。针测试（60%深度）精确取回验证正确性。

- **全GPU推理可行且高效**：在2011年GPU上，现代多模态助手可完全运行于设备端。单图问答端到端1.7秒，五切片图约7秒。
