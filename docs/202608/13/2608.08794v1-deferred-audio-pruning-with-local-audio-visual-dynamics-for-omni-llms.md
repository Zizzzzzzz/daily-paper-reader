## 摘要
全能模态大语言模型联合处理音频、视频和文本，但长多模态序列会带来大量的预填充和KV缓存开销。现有的全能模态压缩方法主要聚焦于大语言模型前的令牌缩减，而跨大语言模型边界的模态特定压缩尚未充分探索。我们提出A-PACK，一个两阶段框架，将音频剪枝延迟到查询条件化的多模态交互出现之后。我们的分析表明，与视频相比，音频每个令牌具有更高的任务相关信息密度和表示多样性。我们进一步发现，局部音视频动态为视觉选择提供了比令牌级匹配更有效的线索。因此，我们在进入大语言模型前保留音频并用局部动态压缩视频，然后在大语言模型内部逐步剪枝低相关性的音频和视觉令牌及其KV缓存条目。在Qwen2.5-Omni-7B/3B的四个基准测试上，A-PACK在评估的先前的方案中取得了最强的平均性能，同时将预填充FLOPs降低高达78%，并将解码吞吐量提升高达2.21倍。

## Abstract
Omni-modal LLMs jointly process audio, video, and text, but long multimodal sequences incur substantial prefill and KV-cache costs. Existing omni-modal compression methods primarily focus on pre-LLM token reduction, leaving modality-specific compression across the LLM boundary underexplored. We propose A-PACK, a two-stage framework that defers audio pruning until query-conditioned multimodal interactions emerge. Our analysis shows that audio exhibits higher task-relevant information density and representational diversity per token than video. We further find that local audio-visual dynamics provide a more effective cue for visual selection than token-wise matching. We therefore preserve audio and compress video with local dynamics before the LLM, then progressively prune low-relevance audio and visual tokens and their KV-cache entries inside the LLM. Across four benchmarks on Qwen2.5-Omni-7B/3B, A-PACK achieves the strongest average performance among the evaluated prior methods while reducing prefill FLOPs by up to 78% and improving decoding throughput by up to 2.21x.

# 基于局部音视频动态的延迟音频剪枝用于全能大语言模型（A-PACK）——论文详细总结

## 1. 核心问题与整体含义（研究动机）

- **背景**：全能模态大语言模型（Omni-LLM）需要同时处理音频、视频和文本。虽然功能强大，但长音视频序列会导致**高昂的 prefill 计算成本和 KV-cache 内存开销**，限制实际部署与推理效率。
- **已有方法的不足**：现有 omni-modal 压缩方法（如 OmniZip、OmniSelect、UniComp 等）大多在 LLM 之前做 token 压缩。这种“pre-LLM 决策”存在两个问题：
  1. **相关性估计不完整**：在音频、视频和 query 进入 LLM 形成联合上下文之前，模态特征仍是孤立的，无法准确判断哪些 token 对查询重要。早期剪枝可能丢掉短暂但关键的音视频证据。
  2. **token 级匹配忽略时间局部性**：逐点音视频相似度可能把语义相似但在时间上相距很远的事件错误关联，而真正有用的是短时间窗口内“共同演化”的跨模态动态。
- **核心观察**：
  - 音频 token 比视频 token 具有**更高的任务相关信息密度**和**表征多样性**（per-token 重要性高约 9.8×，有效秩高 1.7×）。
  - 在固定预算下保留音频比剪掉音频更有效；剪掉音频省下的成本远小于它提供的紧凑证据价值。
  - 因此，作者提出一种“**跨 LLM 边界的阶段依赖压缩**”思想：LLM 前保留音频、主要压缩冗余视频；LLM 内部再根据查询条件化后的上下文，渐进剪枝低相关音视频 token 及其 KV-cache。

## 2. 提出的方法论

### 2.1 整体框架：两阶段 A-PACK

- **Stage 1（LLM 前）**：保留全部音频，将压缩集中在视频上；利用“局部音视频动态（local audio–visual dynamics）”分配视觉预算，并去除视频内部冗余。
- **Stage 2（LLM 内）**：从中间解码层开始，利用 query 注意力分数逐步剪枝低相关音频和视频 token，同时删除对应的 KV-cache 条目，实现“延迟音频剪枝”。

### 2.2 Stage 1：局部对齐压缩（Pre-LLM Local Alignment Compression）

- **局部结构级对齐度量**：使用 Centered Kernel Alignment（CKA）在短时间窗口 \(w=3\) 内比较音频与视频表征的协方差结构，而非逐 token 相似度：
  \[
  c_f = \mathrm{CKA}(A_f, V_f) = \frac{\|V_f^\top A_f\|_F^2}{\|A_f^\top A_f\|_F \|V_f^\top V_f\|_F}
  \]
- **门控细粒度打分**：当全局 CKA 平均较弱（\(\bar{c}<\tau\)）时，用逐帧音视频直接距离作为补充，缓解时间偏移（如旁白先于动作）导致的 CKA 低值问题：
  \[
  s_f = \begin{cases}
  c_f, & \bar{c} \ge \tau \\
  (1-\beta)c_f + \beta(1-\hat{d}_f), & \bar{c} < \tau
  \end{cases}
  \]
- **分段与预算分配**：
  - 通过连续帧余弦相似度做场景切分；
  - 按“峰值 + 均值 + 亚线性时长权重”评估段重要性 \(g_m\)；
  - 结合查询相关性与局部对齐分数，将视频预算分配到帧。
- **锚点去冗余（Anchor-based token selection）**：
  - 每段首帧为锚点帧，用 **DA-FPS（密度感知最远点采样）** 选择高覆盖、多样化的 token；
  - 非锚点帧只保留与其锚点对应空间位置最不相似的 token，从而去掉视频内部冗余。

### 2.3 Stage 2：LLM 内查询条件化压缩（Query-Aware Compression）

- 从中间层开始，重复计算当前多模态 token 的 query–key 注意力分数：
  \[
  I_i = \frac{\exp(q^\top k_i / \sqrt{d})}{\sum_{j\in S}\exp(q^\top k_j / \sqrt{d})}
  \]
- 保留最高 \((1-P)\) 比例的 token，删除其余 token 及其 KV-cache 条目；
- 在后续解码层重复该过程，逐步缩短序列，从而降低后续层注意力和自回归解码时的内存与计算成本。
- 作者强调：**音频不是永远不剪**，而是把剪枝时机从“LLM 前”推迟到“查询条件化融合后”，使剪枝决策更可靠。

## 7. 优点

- **思想新颖且合理**：把压缩策略从“选哪些 token”扩展为“在哪个阶段剪哪类模态”，提出跨 LLM 边界的阶段依赖压缩。
- **保留音频的洞见扎实**：用每 token 信息密度和有效秩两个指标量化了音视频不对称性，并用消融证明了“保留音频”优于“剪音频换视觉”。
- **局部 CKA 设计巧妙**：将 CKA 从训练/诊断工具迁移到推理时的时间窗口匹配，比静态逐点匹配更符合音视频事件共现的时间局部性。
- **计算友好**：预填充 FLOPs、KV-cache、解码吞吐均利好，且不增加训练成本；KV-cache 剪枝同时压缩内存和后续解码。
- **评估体系较严谨**：按实测 prefill-FLOPs 而不是名义 token 数对齐；提供 FLOPs 核算公式、TTFT 分解、序列长度计划等透明细节。
- **统计与定性分析并用**：有显著性检验、域级分解、失败案例分析，论证层次丰富。
- **开源承诺**：文中说明代码将在接收后发布。

## 8. 不足与局限

- **骨干与数据范围有限**：仅在 Qwen2.5-Omni-7B/3B 上评估，未验证其他全模态模型（如 Baichuan-Omni 1.5、Ola 等），泛化性有风险。
- **无训练/微调版本**：只验证了 training-free 推理加速；如需更强效果或对特定领域的自适应，可能需训练扩展，但本文未做。
- **部分基准比较不完整**：Video-MME 上多个基线 OOM，导致主表该列缺失，对整体排名的强健性有轻微影响。
- **对时间偏移与全局语义可能敏感**：CKA 局部窗口需要较可靠的音视频混合同步；若音视频时间偏移较大，门控机制中的 fallback 仍可能受限于 token 级距离的噪声。
- **极限压缩的风险**：作者也承认，当压缩非常激进时，细粒度或长距离证据可能丢失；失败案例显示其方法在“精确到秒”的音频定位任务上仍会犯错。
- **超参数较多**：包括窗口、门控阈值、β、γ、DA-FPS 参数等，实际部署需要按任务调整；敏感性分析显示连续性阈值、DA-FPS 功率等对精度影响较大，可能存在调参负担。
- **效率指标的某些前提较强**：解码吞吐测试假设 R=100 个生成 token，实际不同任务长度可能改变加速结论；对更长生成任务或更大批量未见测试。
