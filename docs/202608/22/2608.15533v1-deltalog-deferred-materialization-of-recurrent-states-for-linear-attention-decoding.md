## 摘要
线性注意力模型通过以循环状态更新替代成对词元交互，消除了softmax注意力的二次方前缀计算和不断增长的KV缓存。然而，现有的解码实现通常在生成每个词元后物化并写回完整的循环状态，使得状态维护成为内存流量的主要来源，尤其是对于具有大状态和多头的模型。本文提出了DeltaLog，一种循环状态解码方案，在不改变模型语义的情况下减少这种开销。具体而言，DeltaLog将循环状态表示为一个稠密基状态以及一个有限的最近紧凑更新日志。大多数解码步骤仅将紧凑的更新因子追加到此日志中，而周期性的合并步骤将累积的更新合并回稠密基状态。因此，模型观察到与急切解码相同的稠密状态，但大多数全状态写回被轻量级的追加操作取代。我们为GDN、KDA和RWKV6实现了DeltaLog，并将其集成到原型服务栈中。在这些模型上，DeltaLog将循环状态更新内核加速高达1.86倍，将分析得到的循环状态写流量减少高达7.83倍，并实现了相对于稠密循环基线1.05–1.20倍的端到端服务加速。

## Abstract
Linear attention models eliminate the quadratic prefix computation and context-growing KV cache of softmax attention by replacing pairwise token interactions with recurrent state updates. However, existing decoding implementations often materialize and write back the full recurrent state after every generated token, making state maintenance a major source of memory traffic, especially for models with large states and many heads. This paper presents DeltaLog, a recurrent-state decoding scheme that reduces this overhead without changing the model semantics. Specifically, DeltaLog represents the recurrent state as a dense base state together with a bounded log of recent compact updates. Most decode steps append only compact update factors to this log, while periodic merge steps fold the accumulated updates back into the dense base state. Thus, the model observes the same dense state as in eager decoding, but most full-state write-backs are replaced by lightweight append operations. We implement DeltaLog for GDN, KDA, and RWKV6 and integrate it into a prototype serving stack. Across these models, DeltaLog accelerates the recurrent-state update kernel by up to $1.86\times$, reduces profiled recurrent-state write traffic by up to $7.83\times$, and achieves $1.05$--$1.20\times$ end-to-end serving speedups over dense recurrent baselines.

## 1. 核心问题与研究动机

**背景问题**

- 线性注意力模型（Linear Attention）通过循环状态（recurrent state）替代 softmax 注意力的成对词元交互，消除了两个瓶颈：二次方前缀计算和随上下文增长的 KV 缓存。
- 然而，现有解码实现在每个生成步骤中都会"急切地"（eagerly）将更新后的完整稠密循环状态物化并写回 HBM（高带宽内存），这引入了新的性能瓶颈——即论文所称的 **"状态更新税"（state-update tax）**。
- 核心不对称性：每个新词元仅贡献 $O(d_k + d_v)$ 大小的紧凑因子，但急切物化需要读写 $O(d_k d_v)$ 个状态元素。当批量大小、头数和状态维度增大时，这种写放大问题更加严重。
- 通过 roofline 分析，论文指出急切稠密状态更新的算术强度仅约 0.5–1.0 FLOPs/byte，远低于现代 GPU 的机器平衡点（如 H200 约 208 FLOPs/byte），处于强内存受限（memory-bound）状态。
- 实测显示：在 Qwen3.6-35B-A3B 模型上，循环状态物化可占整体解码延迟的 25.2%（B=64）至 44.6%（B=256），是解码阶段的一阶瓶颈。

## 2. 方法论：DeltaLog

DeltaLog 是一种**延迟物化（deferred materialization）**的循环状态解码方案，在不改变模型语义和推理结果的前提下，优化状态更新的物理执行调度。

### 2.1 核心思想：基态 + 更新日志

- 状态表示为：**稠密基态（dense base）** $\bar{S}$ + **有界紧凑更新日志（bounded update log）**，日志中每条记录包含紧凑更新因子 $(a_t, b_t)$ 及其对应的对数衰减快照 $\Lambda_{\text{log}}[i]$。
- **追加阶段（Append）**：当日志长度 $L < C$（$C = M-1$，$M$ 为合并间隔）时，仅追加紧凑更新因子到日志，不动稠密基态。
- **合并阶段（Merge）**：当日志满时（$L = C$），将累积的逻辑状态一次性物化写回稠密基态，然后重置日志。
- 该方案在精确算术下与急切稠密解码**代数等价**，模型权重、算子方程和前缀计算完全不变。

### 2.2 状态不变量公式

逻辑状态表示（核心不变式）：

$$S_t = D(\bar{\ell}) \bar{S} + \sum_{i=0}^{L-1} D(\bar{\ell} - \Lambda_{\text{log}}[i]) K_{\text{log}}[i] U_{\text{log}}[i]^\top$$

其中 $D(\ell) = \text{diag}(\exp(\ell))$，$\bar{\ell}$ 为累积对数衰减。论文证明了该表示在 append 和 merge 两种操作下均保持闭合（closure），与急切循环精确等价。

### 2.3 流量模型

- 急切稠密解码每步流量：$T_{\text{dense}} \approx T_{\text{common}} + 2C_{\text{state}}$
- DeltaLog 每步平均流量：$T_{\text{delta}} \approx T_{\text{common}} + C_{\text{state}} + \frac{C_{\text{state}}}{M} + C_{\text{log}}(M) + 2C_{\text{decay}}$
- 其中 $C_{\text{log}}(M) \approx \left(\frac{M-1}{M} + \frac{M-1}{2}\right) C_{\text{entry}}$，包含摊销的追加写和回放读。
- DeltaLog 的收益条件是：避免的稠密写流量 $C_{\text{state}}(1 - 1/M)$ 大于新增的日志元数据流量。

### 2.4 内核级实现

- **Tiled Kernel 分解**：沿值维度（value dimension）将状态划分为多个 tile，每个工作单元处理一个稠密基态 tile 和对应的值侧日志分片。
- **共享元数据**：键侧日志（$K_{\text{log}}$）、对数衰减快照（$\Lambda_{\text{log}}$）、累积对数衰减（$\bar{\ell}$）和日志长度（$L$）在同一 slot-head 对的所有值 tile 间共享。
- **三阶段追加分解**：① ReplayPrep（计算可复用的键侧回放系数）→ ② AppendDecode（值 tile 并行解码并追加值侧日志）→ ③ Finalize（单写入者更新共享元数据）。
