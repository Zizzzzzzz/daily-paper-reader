## 摘要
我们提出MoNe，一种轻量级模块化神经记忆，它可附加到任何冻结的预训练Transformer上，无需重新训练即可实现长上下文推理。MoNe通过测试时学习具有层局部梯度更新的快速权重神经记忆网络，以固定大小的分段读取上下文；在推理时，记忆仅从查询令牌生成键和值，无需重新读取上下文令牌。这种两阶段设计将推理成本与上下文长度解耦，实现了O(N)预处理和O(1)查询成本，且峰值GPU内存不随N增长。在128K令牌下，与ICL相比，MoNe将计算和峰值GPU内存均减少约80%，参数开销仅为6.4%。MoNe可泛化到远超主干网络原生窗口的上下文长度，在RULER的大海捞针和单词提取基准上取得了强劲性能，而ICL在这些基准上性能急剧下降。

## Abstract
We present MoNe, a lightweight modular neural memory that attaches to any frozen pretrained Transformer to enable long-context inference without retraining. MoNe reads context in fixed-size segments via test-time learning of fast-weight neural memory networks with layer-localized gradient updates; at inference, the memory generates keys and values from the query tokens alone, with no context tokens re-read. This two-phase design decouples inference cost from context length, achieving $O(N)$ preprocessing and $O(1)$ query cost with peak GPU memory that does not grow with $N$. At 128K tokens, MoNe reduces both compute and peak GPU memory by approximately 80% compared to ICL with only 6.4% parameter overhead. MoNe generalizes to context lengths far beyond the backbone's native window, achieving strong performance on needle-in-a-haystack and word extraction benchmarks from RULER, where ICL degrades sharply.

# MoNe: Modular Neural Memory for Efficient Long Context Inference 论文总结

## 1. 核心问题与研究动机

长上下文推理是实际 AI 应用中的关键需求，但面临严峻挑战：

- **计算成本高**：将完整上下文作为提示输入（ICL）时，自注意力机制的 FLOPs 随上下文长度呈二次方增长（O(N²)），在资源受限设备上难以承受。
- **性能衰退**：即便在模型原生窗口内，小模型也难以从冗长提示中可靠提取信息，超过原生窗口后性能急剧下降（"context rot"现象）。
- **现有方案存在根本性局限**：
  - **RAG** 通过检索压缩上下文，但嵌入检索本质上基于独立分块，难以处理需要整合多个分散片段的多跳推理任务。
  - **循环模型**（如 Mamba、TTT、Titans）虽实现线性复杂度，但需从头设计并训练全新架构，无法无缝集成到现有预训练 Transformer 中。

**MoNe 的目标**：提出一种轻量级、即插即用的模块化神经记忆插件，附加到任意冻结的预训练 Transformer 上，在不重训练骨干网络的前提下实现高效的长上下文推理，同时解决效率、泛化和集成三大难题。

## 2. 方法论

### 2.1 核心思想

MoNe 采用**两阶段设计**，将推理成本与上下文长度解耦：

- **测试时学习（预处理）阶段**：将上下文按固定大小分段（T=512）顺序处理，每段通过**快速权重（fast-weight）神经记忆网络**以 O(N) 复杂度压缩存储为记忆。
- **推理阶段**：仅由查询令牌生成记忆令牌（键/值），查询只关注固定大小的记忆令牌，不直接关注任何上下文令牌，实现 O(1) 查询成本。

### 2.2 关键技术细节

- **记忆模块架构**：每层 Transformer 附加一个 SwiGLU MLP 作为快速权重记忆模块 M(x; W)，参数包括 Win、Wgate、Wout（均为 R^{dh×dh}），比线性映射具有更强的表达容量。
- **层局部化梯度更新**：使用**关联记忆损失**（负内积），目标键/值由冻结的 Wk/Wv 结合元训练的 LoRA 适配器生成。梯度更新完全基于本层前向传播激活，不穿越其他层，实现真正模块化。
- **位置编码**：采用分段局部 RoPE，位置索引始终在 [0, T) 范围内，与总上下文长度无关，查询长度 Q ≪ T，因此无需位置插值即可泛化到任意长度。
- **参数注入**：记忆令牌经 RMSNorm 和每头门控缩放后，用冻结的 Wk/Wv 投影为键/值，与查询自身的注意力条目拼接（Eq.5）。
- **离线元训练**：LoRA 适配器和元参数（学习率、动量衰减等）通过生成损失离线训练，部署时固定，使快速权重更新成为一个预学算法。

### 2.3 算法流程

1. **测试时学习**：W₀ → W₁ → ... → W_S（按段依次更新，每段计算局部梯度做一步更新）
2. **推理**：查询经 Wq 投影后读取记忆（无权重更新），生成记忆令牌供冻结骨干网络的注意力使用
3. 最终快速权重状态可跨多个查询复用，并支持增量扩展新上下文

## 3. 实验设计

  - **MK-NIAH**（多键大海捞针）：在散文片段中散布四对键值对，需在干扰项中检索指定键的值

  - **RAG**：将上下文分块（128 token）后使用 BGE-Large 做嵌入检索，取 top-K 块作为提示

## 6. 主要结论与发现

- **持续高性能**：MoNe 在全部任务和长度上保持 0.94~1.00 的得分，远超 ICL（在超窗后崩溃至 0.00~0.28）和 RAG（在跨片段整合任务上受限）。
- **效率显著提升**：128K 下总 FLOPs 从 786.33T 降至 149.61T（↓81%），峰值 GPU 内存从 7.07GB 降至 1.41GB（↓80%），且内存占用与上下文长度无关。
- **强大的长度外推能力**：仅用 ≤4K 训练上下文即可泛化到 128K（32 倍外推），无需额外训练或位置插值。
- **参数开销小**：仅 6.4% 的额外参数（全部 24 层附加时）。

## 7. 优点

- **真正的即插即用**：不修改骨干权重，可无缝集成任何预训练 Transformer，部署友好。
- **效率设计巧妙**：两阶段解耦实现了 O(N) 预处理 + O(1) 查询，峰值内存恒定，且快速权重状态支持多查询复用和增量扩展。
- **层局部化更新机制**：避免梯度跨层传播，使模块真正模块化，更新高效且可并行实现。
- **长度外推机制优雅**：段局部 RoPE 设计使位置编码与总长度无关，从根本上解决外推问题。
- **消融实验设计精细**：不仅评估性能影响，还结合了参数/FLOPs 开销，揭示"全层覆盖 + T=512"是最优权衡点。

## 8. 不足与局限

- **模型规模覆盖有限**：仅在 Qwen2.5-0.5B 上验证，未测试更大规模模型，方法的可扩展性尚未充分证明。
- **任务类型局限**：RULER 的检索/统计任务偏向"信息定位"型能力，未评估复杂推理、多文档 QA、真实对话历史等自然场景。
- **RAG 基线设置可能不公**：RAG 固定用 top-K 检索块（K≤8），未针对具体任务充分调优；同时，RAG 在实际系统中往往还会配合重排序等组件。
- **离线元训练依赖**：LoRA 适配器和元参数需离线训练，虽然部署时固定，但该训练流程本身需要额外的数据和计算资源。
- **对段大小的敏感性**：较小段大小（T=128/256）在超长上下文中性能衰退明显，说明压缩粒度对效果影响较大，在资源极度受限时需谨慎权衡。
- **未来工作仍需验证**：作者也承认，需要更多大规模、自然场景验证以及更灵活的 LoRA 策略来管理多记忆模块。
