## 摘要
在具身场景中准确且高效地回答问题面临显著挑战，原因是视觉语言模型（VLM）推理的计算和内存资源有限。现有方法采用视觉搜索关键帧检索方法来选择与问题相关的关键帧作为VLM输入。然而，视觉搜索方法效率低下，因为它们需要对每个用户查询在数千个视频帧中进行视觉搜索。在这项工作中，我们提出了一种记忆树引导的关键帧选择范式，用于具身场景中的高效3D问答。我们的方法利用一种紧凑且可复用的3D场景表示，称为MemTree3D，它支持利用相机6自由度位姿进行实时在线构建。MemTree3D捕获多级3D场景信息，使大型语言模型能够通过我们基于评分的帧选择高效查询和检索与问题相关的关键帧，而无需重新处理整个视频流。在OpenEQA上，我们的方法将GPT-4o的LLM-Match提高了17.4%，LLaVA-OneVision-7B提高了5.8%，优于现有视觉搜索方法。我们的代码可在https://github.com/hsiangwei0903/MemTree3D获取。

## Abstract
Answering questions accurately and efficiently in embodied scenarios presents significant challenges due to limited computational and memory resources for Vision Language Model (VLM) inference. Existing methods adopt visual search key frame retrieval method to select critical question-related key frames for VLM input. However, visual search methods are inefficient because they require visual search among thousands of video frames for each individual user query. In this work, we propose a memory tree guided key frame selection paradigm for efficient 3D question answering in embodied scenarios. Our method leverages a compact and reusable 3D scene representation, termed MemTree3D, which supports real-time online construction leveraging camera 6-DoF poses. MemTree3D captures multi-level 3D scene information, enabling a Large Language Model to efficiently query and retrieve question-relevant key frames through our scoring-based frame selection without reprocessing the entire video stream. On OpenEQA, our method improves the LLM-Match of GPT-4o by 17.4%, LLaVA-OneVision-7B by 5.8%, outperforms existing visual search methods. Our code is available at https://github.com/hsiangwei0903/MemTree3D

## 一、核心问题与研究动机

**核心问题：** 具身场景下的3D问答（Embodied 3D Question Answering）面临VLM（视觉语言模型）推理计算与内存资源受限的瓶颈。

**研究动机与背景：**
- 3D问答是场景理解的基础任务，广泛应用于具身导航、家庭机器人、AR/VR和辅助智能体等下游应用。
- 现有3D扫描视频通常以高帧率采集，包含数千帧画面，而VLM的Transformer注意力机制对视频长度的计算需求呈二次方增长，形成根本性瓶颈。
- 现有解决方案存在如下不足：
  - **多帧VLM方法**（如Video-LLaMA）：直接输入扫描视频，受限于计算/内存资源，需要时序降采样，导致信息丢失。
  - **场景图方法**（如ConceptGraphs）：仅使用对象级表示，虽内存高效，但丢失了超出对象级别的细粒度视觉信息，且构建流程复杂、依赖多个基础模型，难以实时。
  - **视觉搜索方法**（如VLM-Grounder）：虽兼顾内存与视觉能力，但存在三大局限：①每个查询都需在全部视频帧中做视觉搜索，运行时间随视频长度线性增长；②无法高效处理多轮查询场景；③当检测器漏检关键对象时缺乏失败恢复机制。

**核心突破方向：** 提出一种**基于预构建3D场景表示（MemTree3D）的LLM驱动关键帧检索范式**，绕过逐查询的穷举视觉搜索，同时具备失败鲁棒性。

## 二、方法论：MemTree3D 引导的关键帧选择

### 2.1 总体框架（三步流程）

1. **Step 1（一次性构建）：** 从3D扫描视频利用相机6-DoF位姿实时（25+ FPS）在线构建紧凑场景表示 MemTree3D。
2. **Step 2（LLM推理生成线索）：** 将 MemTree3D 序列化为JSON文本，输入LLM，由其进行显式推理，输出**时间线索**（候选位置）和**空间线索**（关键对象+线索对象）。
3. **Step 3（关键帧选择与问答）：** 根据评分策略从候选位置检索关键帧，将用户问题与选定帧输入VLM生成最终答案。

### 2.2 MemTree3D 表示（三级树结构）

- **位置节点（Location Node, LocNode）：** 利用相机6-DoF位姿分割视频流，当累计平移或旋转变化超过阈值（T_thres=1.5m，R_thres=45°）时创建新的位置节点，每个节点对应场景中一个空间位置。相比语义聚类方法，6-DoF方案计算开销极小且对视觉上均匀的3D场景更鲁棒。
- **对象节点（Object Node, ObjNode）：** 使用YOLO-World（开放词汇检测器）和BoT-SORT（多目标跟踪器）获得检测及其时间轨迹，将每个轨迹封装为对象节点，存储对象类别和跟踪ID。
- **检测节点（Detection Node, DetNode）：** 树结构的叶子节点，记录单帧检测的时间戳、边界框坐标和置信度分数，用于后续帧选择。

### 2.3 LLM 时空线索生成

- **时间线索：** LLM从树中选出Top-k个最可能包含答案答案的位置节点（默认k=3），即使关键对象因感知失败缺失，LLM仍能通过场景中的关系/上下文信息推断最可能的位置，实现感知错误的恢复。
- **空间线索：** LLM预测两类对象集合：
  - **关键对象（O_key）**：与答案直接相关的对象。
  - **线索对象（O_cue）**：可能出现在关键对象附近的周边辅助对象，提供上下文信息。

### 2.4 基于评分的帧选择

- 对每个帧，将检测到的关键对象和线索对象的置信度进行**加权聚合**：
  - 关键对象权重:线索对象权重 = **10:1**（未精细调优）。
- 加权聚合在部分可观测条件下近似查询条件语义对齐，即使关键对象检测较弱或部分缺失也能选出相对信息量最大的帧。
- 最终将问题与从不同位置节点选出的k个关键帧输入VLM进行回答。

### 2.5 效率优势

- **一次性构建**的 MemTree3D 可**跨多轮查询复用**，无需为每个查询重新运行视觉模型。
- 关键帧查询延迟与视频长度无关，取代了随视频长度线性增长的视觉搜索过程。

## 七、方法优点

- **创新性范式切换：** 从"逐查询视频检索"转变为"预构建表示+LLM推理查询"，从根本上解决效率瓶颈。
- **三重优势兼顾：** ①高效（一次性构建、跨查询复用）；②准确（SOTA性能）；③鲁棒（感知失败恢复能力）。
- **表示设计轻量实用：** 仅用检测器+跟踪器+6-DoF位姿，无需多基础模型融合，支持25+ FPS实时构建，满足实际具身部署需求。
- **时空线索分离设计：** 位置级（时间）与对象级（空间）线索解耦，评分机制采用10:1加权兼顾关键对象和上下文对象，设计简洁而有效。
- **跨VLM泛化能力强：** 对闭源GPT-4o和开源LLaVA-OneVision-7B均有效。
- **模块化程度高：** LLM/VLM可灵活替换（GPT-4o、Qwen3系列、LLaVA系列均可用）。

## 八、不足与局限

- **未见对象的定位失败：** 当问题是关于MemTree3D中完全未检测到的新颖对象时，LLM的推理式猜测不一定可靠，定位可能失败（如附录中"cardboard cat scratcher"案例）。
- **小场景增益有限：** 在较小的ScanNet场景（平均82.6m³）中，均匀采样已能较好地覆盖视觉信息，MemTree3D的增益相对有限（OpenEQA ScanNet子集+13.6% vs HM3D +24.6%）。
- **依赖检测器质量：** 底层对象检测器（YOLO-World）的感知质量仍影响树构建质量，虽然在部分缺失情况下有鲁棒性，但完全缺失或严重误检仍会损害最终性能。
- **超参数未充分调优：** 权重比（10:1）、位姿阈值（1.5m/45°）、k值（3）均为通用设置，论文指出逐场景调参可进一步提升但为体现部署现实统一固定——这也表明存在上限未被充分挖掘。
- **算力信息披露不足：** 未详细说明整体管线（构建+推理）的GPU资源消耗、内存占用峰值等关键工程指标；多轮查询实验未量化树构建的一次性成本在总预算中的占比。

- **基准局限性：** OpenEQA的GPT-4 LLM-Match评估协议本身依赖另一个VLM作为评判器，可能引入主观偏差。
