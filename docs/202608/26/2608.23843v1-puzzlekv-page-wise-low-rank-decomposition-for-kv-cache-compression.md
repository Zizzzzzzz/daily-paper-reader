## 摘要
大语言模型（LLM）中的长上下文推理日益受到键值（KV）缓存所需内存的限制。KV缓存压缩通过降低先前标记的存储成本来解决这一问题。在现有方法中，低秩压缩尤其具有吸引力，因为它以缩减的维度表示每个标记。先前的低秩方法通常从模型权重推导固定投影空间，从校准激活构建固定空间，或在较宽的缓存区域上构建共享基。此类表示可能无法捕获详细但重要的信息。我们将每个头的KV缓存划分为固定长度的逻辑页，并观察到单个页内存在显著的低秩结构。基于这一观察，我们提出了PuzzleKV，一种无需训练和校准的方法，将每个已完成的页视为独立的压缩单元。PuzzleKV在每层和每个KV头内对页进行分解，直接在稠密页和分解因式页上计算注意力，并在自回归解码期间增量压缩新合格的页。跨模型、上下文长度和基准的实验证明了PuzzleKV在匹配存储预算下的有效性。在约为原始KV缓存存储60%的情况下，PuzzleKV在两个评估模型及所有基准设置中均实现了超过Full KV性能的96%，在RULER上相较于Global SVD有显著提升，并在LongBench上具有竞争力的表现。为实现更激进的压缩比，PuzzleKV可进一步与量化结合，在仅使用原始存储18.7%的情况下，仍保持超过Full KV性能的93%。

## Abstract
Long-context inference in large language models (LLMs) is increasingly limited by the memory required for the key-value (KV) cache. KV cache compression addresses this problem by reducing the storage cost of previous tokens. Among existing approaches, low-rank compression is particularly attractive because it represents every token in reduced dimensions. Previous low-rank methods typically derive fixed projection spaces from model weights, construct fixed spaces from calibration activations, or construct a shared basis over a broad cache region. Such representations may not capture detailed but important information. We partition each per-head KV cache into fixed-length logical pages and observe substantial low-rank structure within individual pages. Based on this observation, we propose PuzzleKV, a training- and calibration-free method that treats each completed page as an independent compression unit. PuzzleKV decomposes pages within each layer and KV head, computes attention directly over dense and factorized pages, and incrementally compresses newly eligible pages during autoregressive decoding. Experiments across models, context lengths, and benchmarks demonstrate the effectiveness of PuzzleKV under matched storage budgets. At approximately 60% of the original KV cache storage, PuzzleKV achieves more than 96% of Full KV performance across both evaluated models and all benchmark settings, with substantial gains over Global SVD on RULER and competitive performance on LongBench. To achieve a more aggressive compression ratio, PuzzleKV can be further combined with quantization while retaining more than 93% of Full KV performance using only 18.7% of the original storage.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- 大语言模型（LLM）长上下文推理面临严重的显存压力，主要源于自回归解码时需存储的历史键值（KV）缓存。例如，Qwen3-32B 在 128K 上下文、BF16 精度下单序列 KV 缓存约需 32 GiB，且该开销随上下文长度和批次大小线性增长。
- 现有 KV 缓存压缩方法主要分为三类：**驱逐（eviction）**、**量化（quantization）** 和**低秩分解（low-rank decomposition）**。
  - 驱逐会永久丢弃部分 token，导致信息不可恢复。
  - 量化仅降低数值精度，不改变表示维度。
  - 低秩方法将 token 映射到低维空间，可保留全部 token，但先前的低秩方法存在共性问题：
    - 从模型权重推导固定投影空间（如 Palu、LoRC）或从校准激活构建固定基（如 EigenAttention、ECKVH）；
    - 或在一个较大的缓存区域上共享单一基（如 OjaKV、xKV 的序列级基）。
  - 这种“宽区域共享基”的表示以整体重建误差为主导，容易丢失稀疏但任务关键的信息（如重复文本中的单个唯一键值对、长 UUID 中的精确字段）。
- 本文核心观察：**每个 KV 头内部的固定长度逻辑页（page）内存在显著的低秩冗余**，且该性质跨模型、层、KV 头、页大小稳定成立。因此，论文提出以“页”为压缩单元，将每个已完成页面独立分解，以捕获更细粒度的局部结构。
- 整体意义：提供了一种**无需训练、无需校准**的 KV 缓存压缩方法，在约 60% 存储预算下接近全量 KV 性能，并可进一步与量化结合实现更激进的压缩。

## 2. 论文提出的方法论

### 2.1 核心思想
- **页即局部子空间（Page as a Local Subspace）**：将每个层、每个 KV 头的 KV 缓存按固定长度 P 切分为逻辑页，每个页拥有独立的低秩基。这使得每个区域由与自身最相关的方向表示，避免了单一全局基对稀疏但重要信息的压制。
- 保留少量稠密区域（attention sink 页和最近局部窗口页），其余已完成页全部进行截断 SVD 分解，不丢弃任何 token。

### 2.2 关键技术细节
- **页划分与分解**：
  - 在 prefill 阶段计算标准稠密 KV 缓存，按页大小 P 划分 token；
  - 保留初始 sink 页（通常 1 页）和最近若干页为稠密形式；
  - 其余每个已完成的页独立进行截断 SVD：\[
    \hat{X}_p = L_p^{(X)} R_p^{(X)},\quad L_p^{(X)} = U_{p,r_X}^{(X)},\quad R_p^{(X)} = \Sigma_{p,r_X}^{(X)} \left(W_{p,r_X}^{(X)}\right)^\top
    \]
    其中 \(X \in \{K, V\}\)，\(r_K\) 和 \(r_V\) 分别为键和值的秩。
  - 存储比例公式：\[
    \rho_{page} = \frac{(r_K + r_V)(P + d)}{2Pd}
    \]
  - 高效实现：因页是短宽矩阵（\(P < d\)），不直接调用每个页的 SVD，而是先计算较小的 Gram 矩阵 \(G_p = X_p X_p^\top\)（\(P \times P\)），取其前 \(r_X\) 个特征向量作为 \(L_p\)，再计算 \(R_p = (L_p)^\top X_p\)。这样可批量映射到 GPU 操作，避免逐页 SVD 开销。
- **混合注意力（Mixed-Paged Attention）**：
  - 对因子化页，直接利用 \(L_p, R_p\) 计算页级 softmax 状态（注意力分数、running max、归一化因子、未归一化输出），避免显式重建稠密历史 KV 缓存；
  - 对稠密页（sink + 局部窗口）同样计算页级状态；
  - 使用 FlashAttention 风格在线 softmax 归并所有页的部分结果，得到全局归一化注意力。
- **增量缓存更新（Incremental Cache Update）**：
  - 解码阶段每个新 KV 对先追加到当前稠密页，立即参与注意力；
  - 当页填满并离开局部窗口时，触发一次分解，该页转为低秩存储，释放稠密槽位；
  - 每个解码步骤至多触发一次页分解，之前已分解的页不再被修改。
- **整体流程**（prefill：① 计算稠密 KV → ② 页划分 → ③ 逐页分解；decode：④ 混合注意力 → ⑤ 增量页更新）保持了所有 token 以压缩形式存在。

### 2.3 与其他方法的关系
- 与量化互补：可将分解后的因子矩阵进一步做 INT4 量化，达到更低的存储比。
- 与驱逐根本不同：不丢弃任何 token。
- 与全局低秩（如 Global SVD）不同：每个页使用独立基，而非层/头级共享基。

## 6. 论文的主要结论与发现

- **页级低秩结构普遍存在**：跨模型、层、KV 头，页大小为 16/32/64 时，单个 KV 页在较低秩下即可高精度重建（80% 重建精度所需秩远低于全页秩）。
- **性能保持极佳**：在约 60% 存储预算下，PuzzleKV 在 RULER 上达到 Full KV 性能的 96% 以上（Llama3.1 的 96.2%/96.4%，Qwen3 的 99.3%/97.9%），在 LongBench 上达到 98% 以上。
- **显著优于全局低秩**：在 RULER 上，PuzzleKV 大幅超越 Global SVD（最高领先 26 分以上），尤其在 NIAH-S1（唯一键值对藏在重复上下文中）和 Variable Tracking（多跳变量链）任务上，全局 SVD 几乎失效，而 PuzzleKV 保持高分。这表明页级独立基能保留全局基忽略的稀疏但关键信息。
- **优于驱逐方法**：在 NIAH-S3（长 UUID 精确恢复）任务上明显优于 H2O，因为所有 token 都以压缩形式保留，不丢失精确内容。
- **与量化兼容**：PuzzleKV + INT4 可将存储比降至 0.187，性能仍保持 Full KV 的 93% 以上（Llama3.1 86.24 vs 92.33，Qwen3 90.20 vs 91.41），并优于直接 INT3 量化（在 Qwen3 上接近，在 Llama3.1 上略低）。
- **系统开销集中在 prefill 阶段**：解码阶段 TPOT 仅比 Raw KV 高 0.075 ms/token（约 0.18%），prefill 阶段的 TTFT 在 32K 时增加 20.9%，主要是页分解开销。
- **秩分配启示**：键的秩比值的秩更重要；在固定总秩下，\((r_K, r_V)=(16,14)\) 是较好的配置；继续增加秩的收益递减。

## 7. 优点

- **方法论创新性**：首次将 PagedAttention 的逻辑页作为低秩压缩单元，实现了比全局共享基更细粒度的局部低秩表示，能捕捉稀疏关键信息。
- **无需训练和校准**：完全基于推理时 KV 缓存进行分解，即插即用，避免了依赖校准数据集和额外离线处理。
- **不丢 token**：所有历史 token 均被保留，只是以低秩形式存储，从根本上避免了驱逐方法的信息不可逆损失。
- **高效实现**：
  - 利用 Gram 矩阵批量分解，避免逐页 SVD 的高开销；
  - 混合注意力在不解构完整历史缓存的情况下直接计算 attention，避免瞬时稠密缓冲区；
  - 增量页更新保证每个解码步骤最多一次分解，解码额外开销可忽略。
- **实验设计较扎实**：包含合成 + 真实基准、两个模型、多种压缩方法对比、详尽的秩消融和系统测量；对全局 SVD 的对比设计能直接验证“页级粒度”假设。
- **可组合性**：与量化方法天然兼容，进一步拓宽应用范围。

## 8. 不足与局限

- **实验覆盖有限**：
  - 仅两个 8B 模型，未覆盖更大模型（如 32B/70B）或不同架构（如 MoE、Mamba）；
  - 上下文长度最高 32K，未评估 128K 或更长上下文；
  - 所有实验使用 batch size 1、贪婪解码，未测试批处理推理、beam search 或采样解码。
- **对比公平性风险**：
  - Global SVD 是论文自定义基线，虽然有助于隔离变量，但其秩选择可能并非最优；
  - Palu 和 H2O 的配置依赖于论文的设定（如 H2O 的 heavy-hitter/recent 各 0.3 预算），不同设定下结果可能变化；
  - OjaKV 因为复现不稳定被放入附录，削弱了与最新在线低秩方法的直接比较。
- **系统性能评估不完整**：
  - 实现是单机批处理一的原型，未与 vLLM 等生产级推理引擎集成，也未在多请求并发场景下测量吞吐；
  - 没有报告分解过程的峰值显存占用（仅报告逻辑 KV 缓存足迹），也未说明 TTFT 增加中分解的占比细节；
  - TPOT 对比未考虑 SVD 在不同硬件上的性能差异（附录提到精度环境中存在 SVD 性能问题）。
- **理论分析不足**：论文主要依赖实验观察页面低秩性，未提供理论解释为何单页比全局基更利于下游任务。
- **存储比计算局限性**：存储比仅考虑 KV 数据本身，未计入 SVD 分解的临时开销、因子矩阵的索引开销以及页管理元数据。
- **潜在应用限制**：对于短上下文或小批量场景，分解开销可能覆盖压缩收益；在需要极低延迟的场景下，prefill 阶段 20.9% 的 TTFT 增加可能不可接受。
- **可复现性细节**：虽然提供了代码框架名（Hugging Face Transformers）和评估工具，但未提供开源仓库链接或具体实现代码，附录中详细的超参配置在一定程度上弥补了这一点。
