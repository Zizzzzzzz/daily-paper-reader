## 摘要
多轮推理与行动（ReAct）智能体会积累不断增长的推理、工具调用和观察轨迹。它们的键值（KV）缓存也随之增长，增加了模型推理期间的内存使用和注意力开销。现有的KV缓存压缩方法通过驱逐低注意力得分的状态来降低这些开销。然而，当前轮次中的低注意力并不意味着未来不相关，因为暂时不活跃的信息可能在之后变得重要。因此，基于快照的驱逐方法并未明确区分暂时休眠的信息与看似已完成其作用的信息。在本文中，我们提出CommitKV，它通过提交转换来识别KV生命周期。具体来说，CommitKV首先将已完成智能体事件划分为Token页，并在工具调用提交前以及提交返回的观察结果被纳入后，比较每个合格页面的删除效果。基于这些成对测量，CommitKV将休眠页面与从高到低的完成候选者区分开来。然后，它应用贪婪联合测试，仅当候选者提交后组合效果保持有界时，才接受其退役。最后，在后续的压缩检查点，被接受的页面被排除，等待提交后测量的有界页面集合被保护，其余KV状态在缓存预算内使用相同的键、值和绝对位置Token索引保留。这些机制确保CommitKV能够区分休眠信息与已完成其观察作用并可安全移除的信息。在各种基准上的实验表明，CommitKV减少了智能体内存使用，加速了端到端推理，并比现有KV缓存压缩方法实现了更高的准确性。

## Abstract
Multi-turn Reasoning-and-Acting (ReAct) agents accumulate growing trajectories of reasoning, tool calls, and observations. Their key-value (KV) caches grow accordingly, increasing memory use and attention cost during model inference. Existing KV cache compression methods reduce these costs by evicting states with low attention scores. However, low attention in the current turn does not imply future irrelevance, as temporarily inactive information may become important later. Snapshot-based eviction methods therefore do not explicitly distinguish temporarily dormant information from information that appears to have completed its role. In this paper, we present CommitKV, which identifies KV lifecycles through commit transitions. Specifically, CommitKV first divides completed agent events into token pages and compares each eligible page's deletion effect before a tool-call commit and after the commit's returned observation has been incorporated. Based on these paired measurements, CommitKV distinguishes dormant pages from high-to-low completion candidates. It then applies a greedy joint test, accepting candidates for retirement only when their combined post-commit effect remains bounded. Finally, at a later compression checkpoint, accepted pages are excluded, a bounded set of pages awaiting post-commit measurement is protected, and the remaining KV states are retained within the cache budget using the same token indices for keys, values, and absolute positions. These mechanisms ensure that CommitKV can distinguish dormant information from information that has completed its observed role and can be safely removed. Experiments on various benchmarks show that CommitKV reduces agent memory use, accelerates end-to-end inference, and achieves higher accuracy than existing KV cache compression methods.

### 1. 论文的核心问题与整体含义

- **研究动机**：多轮 ReAct（Reasoning-and-Acting）智能体在持续推理和工具调用的过程中，会不断累积推理轨迹、工具调用和观察结果。这些累积的历史信息使得键值（KV）缓存持续膨胀，导致模型推理时的内存占用和注意力计算开销显著增加。KV 缓存压缩是解决该问题的常见手段。
- **核心问题**：现有主流 KV 缓存压缩方法（如 SnapKV、R-KV、TriAttention）基于“快照（Snapshot）”原则，利用当前推理状态下的注意力分数或查询相关性来评估 Token 重要性，并驱逐低分 Token。然而，**当前轮次的低注意力并不等同于未来不相关**——有些信息只是暂时“休眠”，可能在后续轮次被重新需要；而另一些信息则确实已完成其角色，可以被安全移除。快照式方法无法区分这两种情况，可能导致有价值的信息被过早驱逐，造成性能损失。
- **整体含义**：论文提出 **CommitKV**，一种**生命周期感知（Lifecycle-Aware）** 的 KV 缓存压缩方法。它通过“提交转换（Commit Transition）”来识别 KV 的生命周期状态，从而区分“暂时休眠”的信息与“已完成角色”的信息，实现更安全、更精准的缓存压缩。

### 2. 论文提出的方法论

- **核心思想**：利用工具调用提交（Tool-Call Commit）前后的影响变化作为信号，判断信息在智能体事件生命周期中的状态。在工具调用完成前和返回观察结果被纳入后，成对测量同一事件页面的删除效果，以此区分休眠页面（低→低）与完成候选页面（高→低）。
- **关键步骤与公式**：
  1. **事件划分**：将已完成工具调用 \(a_i\) 和观察结果 \(o_i\) 划分为连续的“事件页（Event Page）” \(E\)，每个页面最多包含 \(G\) 个 Token，作为影响度测量的基本单位。
  2. **成对查询窗口**：对工具调用提交 \(c\)，定义提交前窗口 \(Q^-_c\)（工具调用生成的最后 \(W\) 个查询位置）和提交后窗口 \(Q^+_c\)（返回观察被纳入后下一轮解码的前 \(W\) 个查询位置）。
  3. **删除效果度量**：对于事件页 \(E\)，其在查询窗口 \(Q\) 上的删除效果定义为：
     \[
     R(E;Q) = \max_h \max_{p \in Q} \frac{\|o_p - o_p^{\backslash E}\|_2}{\|o_p\|_2}
     \]
     其中 \(o_p\) 是原始注意力输出，\(o_p^{\backslash E}\) 是删除 \(E\) 中 Token 并重新归一化注意力权重后的输出。
  4. **状态分类**：结合绝对删除效果和百分位排名，对每个页面在提交前后的状态进行高/低二分类（\(H^\pm_c(E)\)、\(L^\pm_c(E)\)），阈值分别由 \(\tau_{use}\)、\(\tau_{dead}\)、\(\rho_{use}\)、\(\rho_{dead}\) 控制。比较提交前后的状态，定义生命周期分类：高→低为“完成候选”（Completion Candidate），低→低为“休眠”（Dormant），低→高为“新激活”（Newly Active），高→高为“仍活跃”（Still Active），其余为“不确定”（Uncertain）。
  5. **贪婪联合验证**：仅对“完成候选”进行退役判断。候选页面按提交后影响从小到大排序，逐个测试加入淘汰集 \(D_c\) 后的联合删除效果 \(R^+_c(D_c \cup \{E\}) \le \tau_{joint}\)，只有通过验证的页面才被接受退役，避免多个小影响的累积效应导致输出大幅偏离。
  6. **待定页面保护**：等待提交后测量（即有提交前数据但提交后数据尚未收集）的页面，在压缩检查点被暂时保护在缓存中，保护的数量受限于 \(B_N = \lfloor \eta B \rfloor\)，优先保护提交前删除效果较大的页面。
  7. **固定预算压缩**：在压缩检查点，排除已接受的退役页面、保留受保护的待定页面索引，并从其余页面中选择 Token 以满足预算 \(B\)。同一索引集 \(I_j\) 一致地应用于键、值及绝对位置，保证 RoPE 位置信息的一致性与完整性。
