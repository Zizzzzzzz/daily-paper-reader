## 摘要
交通监控摄像头持续捕捉事故，但将原始CCTV录像转换为能够精确定位碰撞时间、地点和类型的结构化事件记录在大规模上仍未得到解决。ACCIDENT @ CVPR基准测试恰恰在严格约束下评估这一联合预测：没有可用的标记真实世界训练数据。我们引入了一种无训练、两遍粗到细的流程，将冻结的Qwen3-VL-32B-Instruct视觉语言模型与YOLO11x目标检测和Bo-SORT跟踪相结合。第一遍稀疏采样整个片段以锚定碰撞时刻；第二遍使用带有稳定车辆身份和归一化边界框坐标的标注帧，围绕该估计的紧凑时间窗口进行重新检查，这使模型既能获得视觉叠加层，也能获得同一场景的显式数值描述。在官方2,027片段真实CCTV测试集上，我们的系统实现了0.504的三向调和平均得分，以22%的相对幅度超过了所有组织者发布的基线，包括最佳多模型集成（0.412）。

## Abstract
Traffic surveillance cameras capture accidents continuously, yet converting raw CCTV footage into structured event records that pinpoint when, where, and what type of collision occurred remains unsolved at scale. The ACCIDENT @ CVPR benchmark evaluates exactly this joint prediction under a strict constraint: no labeled real-world training data is available. We introduce a training-free, two-pass coarse-to-fine pipeline that pairs a frozen Qwen3-VL-32B-Instruct vision-language model with YOLO11x object detection and BoT-SORT tracking. A first pass sparsely samples the full clip to anchor the collision moment in time; a second pass re-examines a tight window around that estimate using frames annotated with stable vehicle identities and normalized bounding-box coordinates, which gives the model both a visual overlay and an explicit numeric description of the same scene. On the official 2,027-clip real-CCTV test set, our system achieves a three-way harmonic mean score of 0.504, surpassing all organizer-published baselines including the best multi-model ensemble (0.412) by a 22% relative margin.

### 1. 核心问题与整体含义（研究动机与背景）

- **问题定义**：交通监控摄像头（CCTV）持续捕捉交通画面，但如何从原始录像中自动提取结构化事件记录（包括碰撞发生的**时间**、**地点**和**类型**）在大规模场景下仍未得到解决。
- **基准挑战**：ACCIDENT @ CVPR 基准测试将事故理解定义为三向联合预测任务，官方采用三者的调和平均值（Harmonic Mean）作为唯一评分标准——任一分支得分为零都会导致总分归零。该基准有严格约束：**不提供任何标注的真实世界训练数据**，参赛者只能使用 CARLA 合成开发集，所有系统必须零样本（zero-shot）泛化到真实监控视频。
- **核心难点**：
  - 事故仅占据 30 秒视频中约 100–500 毫秒，低帧率采样极易错过撞击时刻；
  - 真实 CCTV 视频分辨率低、压缩重、夜间条件差，精确坐标恢复困难；
  - 视觉语言模型（VLM）在不确定时存在**中间时刻偏差**（mid-video bias），默认预测片段的中间时刻。
- **研究意义**：该论文探索了纯推理（training-free）的 VLM 流水线能否在无真实标注数据的苛刻条件下同时解决时间定位、空间定位和类型分类三方面问题。

### 2. 论文提出的方法论

#### 核心思想
采用**两遍（two-pass）粗到细（coarse-to-fine）流水线**，将冻结的大视觉语言模型 Qwen3-VL-32B-Instruct 与 YOLO11x 目标检测、BoT-SORT 多目标跟踪相结合，通过“先粗定位时间，再细粒度空间与时序分析”的方式避免单次全片推理的失败模式。

#### 关键流程

1. **Pass 1：粗粒度时间定位**
   - 从完整片段中以 2 fps 稀疏采样最多 60 帧；
   - 按 Qwen 官方格式在帧之间插入时间戳 token `<T.T seconds>`；
   - 指令模型返回 JSON 格式的 `{"accident_time": <time>, "type": <type>}`；
   - 输出粗时间估计 \( \hat{t}_c \) 用于锚定 Pass 2，粗类型预测 \( \hat{c}_c \) 作为软提示（soft hint）传入第二遍。

2. **Pass 2：细粒度空间与时间精化**
   - 以 \( \hat{t}_c \) 为中心定义 4 秒精化窗口 \( [\hat{t}_c - 2s, \hat{t}_c + 2s] \)；
   - 在原生帧率下运行 YOLO11x + BoT-SORT 跟踪（置信度阈值降至 0.1 以保留模糊/遮挡车辆）；
   - 从跟踪窗口中均匀选取 24 帧，用边界框和车辆 ID 进行标注（可视化阈值 0.3，抑制低置信背景框）；
   - 每帧同时配有时间戳 token 和**归一化边界框文本列表**（如 `[Car 1: (0.491,0.620)-(0.589,0.694)]`）；
   - 模型同时获得**视觉叠加层**和**显式数值描述**，最终输出 `{"accident_time", "center_x", "center_y", "type"}`。

3. **推理时保护机制**（防止调和平均分数崩溃）：
   - 时间下限：\( \hat{t} < 0.3 \) 秒的输出被移除，防止零值导致 T 分支得分为零；
   - YOLO 重试机制：OOM 时降低图像尺寸重试；
   - 原始帧回退：窗口内检测不到车辆时回退到未标注帧；
   - 短窗口重试：VLM OOM 时减少帧数并压缩上下文重试；
   - JSON 安全保护：输出解析失败时保留非零预测，避免整段 clip 崩溃。

#### 设计动机（针对三类失败模式的对应关系）

| 失败模式 | 针对性设计 |
|---|---|
| 低帧率采样错过撞击时刻（100–500ms） | 粗定位先行，精化窗口聚焦，原生帧率跟踪 |
| 低分辨率下精确像素坐标恢复困难 | 归一化坐标文本与视觉叠加双通道输入 |
| 模型的中间时刻偏差 \( \hat{t} \approx D/2 \) | 两遍流程 + 窄窗口约束，将时间预测锚定在实际事件附近 |

### 6. 主要结论与发现

- **两遍流水线的有效性**：该训练-free 方法在官方测试集上达到 **HM = 0.504**，超过组织者最优基线（0.412）**22% 相对提升**；
- **分支增益分析**：相对 Best-from-all，时间定位 T 提升 +0.206，类型分类 C 提升 +0.070，空间定位 S 轻微下降 0.020——S 的下降源于跟踪器丢框和夜间低置信度，但这种牺牲换来了更大的 T 和 C 收益；
- **关键设计启示**：
  - 单一 Pass 的 VLM 调用是最大提升来源（+0.234 HM）；

  - 将视觉标注（bounding boxes + IDs）与归一化坐标文本并列输入，显著强化了模型的空间推理能力；
  - 贪心解码（greedy decoding）替代采样解码消除了 JSON 漂移和中心聚集问题。

### 8. 不足与局限

- **实验覆盖局限**：
  - 缺少真正的受控消融实验（隐藏测试集上无法逐变量控制）；
  - 未在 CARLA 合成验证集与其他公开事故数据集上验证，泛化结论的覆盖面有限；
  - 单 VLM、单检测器、单跟踪器的组合，未比较不同型号骨干模型的影响。
- **准确率瓶颈**：
  - 空间定位 S = 0.468 甚至低于组织者的 “Best from all” 集成基线（0.488），是三个分支中的短板；
  - 夜间和重度压缩场景下 YOLO 频繁失效触发原始帧回退，模型回归到中心先验 \( (0.5, 0.5) \)；
  - 单车辆事故中 VLM 会幻觉出第二辆车，导致 t-bone 误分类；
  - 侧面擦撞（sideswipe）等细微碰撞难以在粗采样中被锁定。
- **计算与应用限制**：
  - 40–90 秒/片段的高延迟不适合实时/近实时监控需求；
  - 依赖至少 80 GB 显存的大规模 VLM，部署成本高；
  - 每个 clip 两次大模型调用，处理海量摄像头数据的总吞吐量受限；
  - 在无真实标注的条件下，部分超参数（如窗口大小 ±2s、24 帧采样数）缺乏系统调优的依据，存在过拟合隐式测试集的风险。
- **其他**：未讨论多摄像头跨场景泛化、遮挡严重场景、恶劣天气（雨雪/雾霾）等更复杂条件下的表现。
