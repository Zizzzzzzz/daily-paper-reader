## 摘要
键值（KV）缓存是长上下文大语言模型推理中的主要内存瓶颈。现有方法从两个对立角度入手：驱逐方法永久丢弃 token，一旦被丢弃的 token 后来被证明是关键的，就会降低性能；而量化方法虽以低精度保留所有 token，但压缩能力有限。我们提出 AnchorKV，一种在不丢弃任何单个 token 的情况下将缓存压缩 20 倍的压缩方案。AnchorKV 使用一组精确存储的锚点来表示缓存，通过每个 token 最相似的锚点来表达所有其他 token，并且仅精化那些其近似性对模型输出影响最大的 token。AnchorKV 在多种模型和数据集上持续保持准确性，在 70B 规模下保留了完整缓存分数的 99%，同时以极低的成本维持整个上下文。

## Abstract
The key-value (KV) cache is the primary memory bottleneck in long-context LLM inference. Existing approaches attack it from opposite ends: eviction methods permanently discard tokens, degrading performance whenever a discarded token later proves essential, while quantization methods retain all tokens at low precision but offer limited compression. We propose AnchorKV, a compression scheme that shrinks the cache by $20\times$ without discarding a single token. AnchorKV represents the cache using a small set of anchors stored exactly, expresses every other token through its most similar anchor, and refines only those whose approximation most affects the model's output. AnchorKV consistently preserves accuracy across models and datasets, retaining 99% of the full-cache score at the 70B scale, while keeping the entire context at a fraction of its cost.

# AnchorKV：锚点-残差 KV 缓存压缩——论文详细总结

## 1. 核心问题与研究动机

- KV 缓存是长上下文 LLM 推理的**主要内存瓶颈**：每 token、每层都要存储一个 key 和一个 value，随上下文长度和 batch size 线性增长，且在每次解码时需被完整读取。
- 以 Llama-3.1-8B 为例，128K 上下文在 bf16 下需要 16 GiB 缓存，与模型权重本身相当。缓存容量决定了设备能容纳多少请求、每步解码推进多快。
- 现有方法存在两难困境：
  - **逐出（Eviction）方法**（如 SnapKV、AdaKV、PyramidKV）：永久丢弃 token。虽然压缩率原则上无限，但打分发生在查询未知之前，被丢弃的 token 无法恢复——一旦后续查询需要它，性能出现不可逆下降。论文实验表明，这并非罕见情况，而是该系列方法的**主导失效模式**。
  - **量化方法**（如 TurboQuant）：保留全部 token，但精度降至 1–2 bit 时准确度显著下降，压缩率受限于约 5× 附近，远不足以使缓存不再是瓶颈。
- 论文提出 **AnchorKV**：在不丢弃任何 token 的前提下实现 20× 压缩，目标是同时获得驱逐法的高压缩率和全保留法的信息完整性，并让压缩后缓存成为精确缓存的一个**扰动**而非**截断**。

## 2. 方法论

### 2.1 核心思想：锚点-残差表示

- 每个 KV head 选取少量 **锚点（anchors）**，以 bf16 全精度存储。
- 每个非锚点 token 表示为**最近锚点的缩放副本**：
  - 分配：`a(i) = argmax |<xi, xa>|/(||xi||·||xa||)`
  - 投影系数：`γi = <xi, xa(i)> / ||xa(i)||²`
  - 近似：`x̃i = γi·xa(i)`，残差 `ri = xi − x̃i`
- 存储成本仅为：一个锚点索引 + 一个标量系数（每侧 K/V）。任何 token 在 softmax 中**都不会缺席**。
- 对模型输出影响最大的 token 额外存储**量化残差**（2-bit），修复投影误差。

### 2.2 锚点选择

- 最后 W=32 个位置总是精确存储（兼顾 recency window、观察查询和锚点方向）。
- 剩余锚点槽位中：**70% 按 SnapKV 式打分**（观察窗口查询的平均注意力，经宽度 κ=7 的池化核平滑）选择高分位置；**30% 从上下文中均匀采样**，以增强方向覆盖度。
- 锚点预算 `k = S/128`（上下文的固定比例）。

### 2.3 注意力输出感知的残差评分

- 论文不按残差范数或注意力分数分配残差，而是按**对注意力输出的一阶影响**分配。
- 推导出两个通道的误差分解（Eq. 5）：
  - **K 通道**：key 误差通过 softmax 权重变化起作用，受 `Vt − y` 调制；
  - **V 通道**：value 误差直接作用于输出。
- 在非相干性近似下，期望误差分解为逐 token 可加项，从而得到效用函数（Eq. 6）：
  - `uKt ∝ (αt)² · (q^T Rt rKt)²/D · ||Vt − y||²`
  - `uVt ∝ (αt)² · ||rVt||²`
- 选择效用最高的 token 存储残差，即近似最小化注意力输出误差。

### 2.4 字节预算分配

- 用户设置单个参数 θ（保留缓存比例），精确的字节核算将其转化为每层残差数量。
- 每层内 keys 和 values 各分 `⌊N/2⌋` 个残差槽位；各 KV head 按效用**跨头池化竞争**残差预算。
- 存储布局：锚点在 bf16（keys 存于 RoPE 之前）、非锚点存索引+系数、残差以 2-bit 打包（Hadamard 旋转 + Lloyd-Max 码本），全部张量计入开销，确保不超过预算。

### 2.5 理论保证

- 定理 1 给出输出误差上界 `||y − ŷ|| ≤ EV + EK`：
  - 值误差 `EV` 为注意力加权平均；
  - key 误差 `EK` 为最坏情况，但每个 key 的误差受其自身投影残差范数约束。
- 与驱逐法的关键对比：若驱逐法保留同样的锚点集，它付出的代价是所有非锚点的完整 `||Vt||`，而 AnchorKV 只付出投影误差比例 `βV(t) ≤ 1`——**严格更优**。

### 2.6 推理流程

- 压缩仅在 prefill 结束时运行一次（在冻结模型上），注意力计算不变。
- 解码时通过 FlashAttention 风格的 tiled 核，按需重建 tile 的 keys/values，**从不物化稠密缓存**；value 残差贡献经 Hadamard 逆变换线性性质在一次变换后累加。

## 6. 主要结论与发现

1. **20× 压缩下超过基线 10× 的水平**：在全部 9 个模型-基准组合中，AnchorKV 在 20× 的分数高于所有驱逐基线在 10× 的分数——**同等精度只需一半内存**。
2. **精度随模型规模提升**：RULER-32K 在 20× 下保留 FullKV 分数的比例：Llama-8B 为 93.5%、Mistral-24B 为 95.3%、Llama-70B 为 **99.3%**——压缩最激进处恰是缓存成本最高处。
3. **驱逐法的失效模式被实证**：基线在需要检索抗干扰（cwe、single_3）或全上下文聚合（multikey_3、fwe）的任务上跌至 16% 以下，而 AnchorKV 保持 60%–92%。
4. **NIAH 对比悬殊**：5× 下 AnchorKV 平均 0.94 vs. 最强基线 AdaKV 0.18；10× 下为 0.80 vs. 0.11。
5. **效率收益显著**：20× 目标下解码峰值内存减少约 19×；64K 上下文解码延迟与 FullKV 持平；并发能力约翻倍（128K 从 1 请求升至 2 请求），各记忆边界吞吐提升 21–26%。
6. **每个设计组件都有贡献**：效用排序优于任何单一指标替代；去除任一组件都会降低准确度，且差距随预算收紧而扩大。
7. **Pre-RoPE 投影更好**：RoPE 会降低 key 到最近锚点的余弦（中位数下降 0.27），因此 key 在旋转前投影、解码时旋转。

## 7. 优点

- **核心思路新颖且有理论深度**：将“逐出 vs. 全保留”的二元对立转变为“全保留+按字节分配精度”的连续谱，并给出输出误差上界与驱逐法的严格对比，既有直觉又有形式化保证。
- **单一超参数，开箱即用**：用户只需设置保留比例 θ，所有内部参数固定且不随模型/任务调整，实用性强。
- **完全推理时方法，无需训练/校准**：预填充后一次性压缩，不依赖外部校准数据，适配任意模型。
- **公平严谨的实验**：统一按字节预算匹配所有方法；RULER 全任务逐项报告；NIAH 全网格扫描；TurboQuant 复现的偏差被明确交代。
- **完整高效的系统实现**：Triton 内核按 FlashAttention 模式运行，稠密缓存永不物化，残差逆变换在线性性下仅做一次，工程完成度高。
- **注意力输出保真度测量**：直接测量压缩对层的输出的影响（余弦分布），比仅看下游准确率更本质，能够区分方法差异的来源。
- **跨头预算动态分配的可视化分析**：证明非均匀分配确实被激活且随输入变化，而非装饰性设计。

## 8. 不足与局限

- **观察窗口假设的固有局限**：效果依赖“近期查询关注的位置即解码所需位置”的假设。若后续查询需要的信息集中在被存储为粗糙表示的区域，性能仍可能受损（虽然每个 token 保留时，损失是连续的而非灾难性的）。NIAH 中长上下文浅层放置的场景（needle 在最早期）仍有明显软化（约 30% 准确率下降）。
- **TurboQuant 复现问题**：原论文未开源代码，作者用社区复现替代，且社区实现与原文方法存在偏差（如保留 top-k 通道、fp16 离群值），量化基线可能未反映 TurboQuant 真实潜力。
- **解码延迟在小上下文偏高**：32K 时解码延迟约为 FullKV 的 1.3 倍；虽然 64K 后持平并 96K–128K 略快，但短上下文场景的代价需权衡。
- **NIAH 样本量有限**：每个网格单元仅 10 个样本，且单个数据集上的“0/1”精确匹配评分方差较大，统计效能有限。
- **模型覆盖面仍有限**：未测试非 Llama/Mistral 系列（如 Qwen、GLM 等）或视觉-语言模型；也未测试 batch size > 1 时的压缩精度性能。
- **长输出解码的压缩率漂移**：生成 token 以 bf16 追加且从不压缩，输出越长整体压缩率越低（32K 输出 60 步后 20× 变 19.3×）；虽然不可避免，但论文没有明确说清在极长生成下是否需要重新压缩。
- **论文日期标注为 2026 年 8 月**，属未来时间点的预印本，且标注 “Under review”，其结论尚未经过同行评审的完整验证。
