## 摘要
视觉-语言-动作（VLA）模型能够将场景理解、语义推理和轨迹生成连接起来，用于自动驾驶。然而，冗长的自然语言思维链（CoT）并不适合实时控制，因为它是开放式的、解码成本高，并且难以作为面向动作的表示进行优化。我们提出了XCoT-VLA，它用从自动构建的Reason-Action监督中学习的紧凑可执行CoT标记取代了描述性理由。记录的轨迹提供动作证据，而场景上下文提供因果语义。预测的XCoT序列保持在上下文中，并通过共享的多模态自注意力来条件化固定的轨迹查询。确定性的标记-函数路由将Reason FFN应用于XCoT标记，将Control FFN应用于轨迹查询，以进行流匹配轨迹生成。我们还引入了XCoT策略优化（XCPO）作为同一可执行标记空间中的可选精化扩展。XCoT-VLA在一般分布集上将纵向ADE从1.645降至1.323，在换道场景中将横向FDE从1.616降至0.648。通过仅使用2-6个可执行的XCoT标记来表示面向驾驶的推理，我们的方法大幅减少了自回归推理开销，并保持在实时规划预算内。这些结果表明，面向驾驶的推理可以是紧凑的、可执行的，并直接与轨迹生成相连。

## Abstract
Vision-Language-Action (VLA) models can connect scene understanding, semantic reasoning, and trajectory generation for autonomous driving. However, verbose natural-language Chain-of-Thought (CoT) is poorly suited to real-time control because it is open-ended, costly to decode, and difficult to optimize as an action-facing representation. We propose XCoT-VLA, which replaces descriptive rationales with compact executable CoT tokens learned from automatically constructed Reason-Action supervision. Logged trajectories provide action evidence, while scene context supplies causal semantics. The predicted XCoT sequence remains in context and conditions fixed trajectory queries through shared multimodal self-attention. Deterministic token-function routing applies the Reason FFN to XCoT tokens and the Control FFN to trajectory queries for flow-matching trajectory generation. We further introduce XCoT Policy Optimization (XCPO) as an optional refinement extension in the same executable token space. XCoT-VLA reduces longitudinal ADE from 1.645 to 1.323 on a general-distribution set and lateral FDE from 1.616 to 0.648 in lane-change scenarios. By representing driving-oriented reasoning with only 2-6 executable XCoT tokens, our method substantially reduces autoregressive reasoning overhead and remains within the real-time planning budget. These results demonstrate that driving-oriented reasoning can be compact, executable, and directly connected to trajectory generation.

  2. **解码成本高**：逐 token 自回归解码引入额外延迟，难以满足自动驾驶的严格实时约束；
  3. **难以优化**：语言作为面向动作的表示，与可执行轨迹之间的关联是隐式的，难以直接作为策略优化的目标空间。

**核心问题：**

> 驾驶 VLA 模型应该"是否推理"不是关键，关键在于**以何种形式的推理暴露给轨迹生成器**。

**核心主张：** 面向轨迹生成的推理应当具备三个特性——**决策关键性（decision-critical）**、**紧凑性（compact）** 和 **可执行性（executable）**。

## 2. 论文提出的方法论

### 2.1 核心思想

XCoT-VLA 用 **2–6 个紧凑的可执行语义-动作 token（XCoT tokens）** 替代冗长的自然语言推理，直接作为轨迹生成的条件。这类 token 示例包括 `LEFT_TURN_PREPARE`、`DECELERATE`、`RED_LIGHT_HOLD`、`NAV_LEFT_LANE_CHANGE` 等，直接编码决策关键的驾驶意图及其控制相关语义。

### 2.2 XCoT 训练数据构建流程

采用离线数据构建流水线，将每个日志样本映射为可执行的 XCoT 序列，完整流程如下：

```
(ot, τt) --fact--> at --fground--> (r*t, at) --gXCoT--> z*t
```

1. **动作证据提取（fact）**：从记录的轨迹（-3s~6s 窗口）中提取纵向行为（速度、加速度）和横向行为（车道相对位移、轨迹几何）作为动作证据 at。
2. **语义接地（fground）**：根据场景上下文推断候选原因（导航意图、道路结构、交通规则、周围交互、安全约束），通过一致性评分选择最匹配的因果语义 r*t。
3. **语义压缩（gXCoT）**：基于固定可解释词汇表将 Reason-Action 对映射为规范紧凑的 XCoT token 序列，长度不超过 6 个 token（Mmax=6），以 EOS 结束。

### 2.3 解耦的推理-控制架构

- 使用共享的多模态自注意力让所有 token 位置交互；
- **确定性 token-函数路由**：所有非轨迹 token（视觉、文本、提示、自车状态、XCoT token）经过 **Reason FFN** 处理，仅 24 个轨迹查询位置经过 **Control FFN** 处理；
- 路由公式：
  - 掩码满足：`mReason + mControl = 1`，二者互斥；
  - 层更新为 `h = h̃ + mReason·FFN_Reason(Norm(h̃)) + mControl·FFN_Control(Norm(h̃))`；
- 两条 FFN 分支通过共享自注意力交互，但计算路径分离，避免了联合微调的不稳定性。

### 2.4 两阶段训练

**Stage I（SFT）**：
- 推理路径：用 XCoT 序列的交叉熵损失 `LXCoT` 监督（teacher-forcing）；
- 控制路径：用条件流匹配（Conditional Flow Matching, CFM）损失 `LFM = E||vθ(xα; α, c) − (x1 − x0)||²` 训练轨迹生成；
- 总损失：`LSFT = λXCoT·LXCoT + λFM·LFM`。

**Stage II（XCPO，可选策略优化）**：
- 冻结执行栈（视觉编码器、共享自注意力、Control FFN、流匹配轨迹头），仅更新 Reason FFN 和 XCoT 预测头；
- 从旧策略采样 G 条 XCoT 序列，经冻结执行器解码为轨迹，计算组相对优势 `Ai = (Ri − μR)/(σR + ε)`；
- 使用类似 GRPO 的裁剪序列级目标 + KL 正则项约束。

## 6. 论文的主要结论与发现

1. **可执行推理优于冗长语言推理**：XCoT-VLA 在所有开环指标上优于 Trajectory-only 和 Verbose CoT 基线。
2. **显著改进换道性能**：在换道场景中，横向 ADE 从 0.5941 降至 0.3091，横向 FDE 从 1.6160 降至 0.6484。
3. **通用分布集也有增益**：纵向 ADE 从 1.6452 降至 1.3233，纵向 FDE 从 4.3541 降至 3.0887。
4. **推理开销大幅降低**：仅需 2–6 个 XCoT token 即可完成推理，最坏延迟低于 12 Hz 规划预算（83.3 ms），而 Verbose CoT 在所有输入长度下均超预算。
5. **解耦 FFN 路由对训练稳定性至关重要**：联合微调导致严重的纵向退化（ADE-2s-Long 从 0.2774 恶化为 1.1684），解耦微调则保持短时程纵向精度并改进横向指标。
6. **可执行推理可以紧凑地表示驾驶决策**：驾驶导向推理不必然冗长，可以是紧凑、可执行、直接与轨迹生成相连的。

## 7. 优点

- **问题把握精准**：直击自然语言 CoT 在实时控制中的结构性缺陷，提出"推理暴露给动作生成器的形式"这一关键设计问题；
- **创新的推理-控制解耦架构**：确定性 token-函数路由（Reason FFN / Control FFN）简洁有效，既保持多模态上下文共享，又避免推理表示干扰控制计算的稳定性；
- **数据构建流水线完整**：日志轨迹 → 动作证据 → 语义接地 → 语义压缩的自动标注流程具有可扩展性，人工标注仅覆盖 200k 复杂交互样本；
- **XCoT 词汇表设计精巧**：统一词汇表覆盖纵向控制、横向/导航操作、规则/交互/安全条件，支持组合表达复杂决策；
- **XCPO 设计在可执行 token 空间中进行策略优化**，保持了推理的可解释性和优化的可操作性，执行栈冻结降低了优化难度；
- **实验指标区分纵/横向**，比传统的欧氏 ADE/FDE 能更精细地诊断方法在不同控制维度上的效果。

## 8. 不足与局限

### 实验局限
- **XCPO 未提供定量结果**：论文明确声明不评估，只建议用闭环指标评估，显得该模块的贡献缺乏实证支持；
- **缺少闭环验证**：开环 ADE/FDE 无法反映真实驾驶安全性、交互性和舒适度；
- **缺乏外部基线对比**：未与其他已发表的 VLA 驾驶方法在同一基准上对比；
- **开环指标本身的局限性**：预测误差不一定等同于决策质量，良好的 ADE/FDE 可能源于"跟随保守行为"而不是"做出正确决策"。

### 方法局限
- **交互协商能力有限**：论文在结论中承认"有限的交互协商能力"，XCoT token 难以表达复杂的多智能体博弈；
- **对交通规则感知错误敏感**：XCoT 依赖上游场景语义的正确性，"红灯"等规则感知错误会直接导致错误的可执行决策 token；
- **纵向舒适性改进较小**：结果是纵向指标改善幅度弱于横向指标；
- **词汇表覆盖范围受限**：固定词汇表虽然可解释，但可能无法覆盖所有长尾场景；
- **Reason-Action 标注质量依赖场景理解专家**：自动标注中视觉语言专家的共识机制可能引入标注噪声或偏差。

### 潜在偏差风险
- 数据来源单一（小鹏内部大规模驾驶数据），分布代表性未知；
- 人工标注的标准和一致性未详细说明；
- 延迟测试使用 H100，实际车辆部署硬件可能性能差异较大。
