## 摘要
在移动机器人上部署十亿参数的视觉-语言-动作（VLA）策略会产生系统冲突：语义推理受益于云GPU，而闭环控制必须在本地响应，尽管存在网络延迟和抖动。现有的层次化和异步策略提高了吞吐量，但它们的慢路径表示仍可能过期到达，或需要明确的调度和延迟提示。我们提出了CloudEdgeVLA，一种云边策略，将时间错位视为表征学习问题。云VLA将延迟的观测编码为缓慢变化的任务特征，而轻量级边缘头将最新的可用云特征与当前局部视觉相结合。在训练期间，当前帧和随机延迟帧在新鲜路径和过期路径中与相同的当前动作目标配对。这一目标鼓励云表征保留任务级信息，同时边缘路径提供状态敏感校正。在四个LIBERO套件中，CloudEdgeVLA在40步均匀延迟窗口下保持63.8--78.0%的成功率，而VLASH最多达到6.4%，评估的单路径基线最多达到3.0%。通过从控制回路中移除阻塞同步，该设计为可扩展的VLA部署提供了实用途径，其中云模型可以增长，而边缘计算保持轻量级和响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

### 研究动机与背景
- **根本矛盾**：十亿参数级 VLA 模型（如 OpenVLA、π0、RT-2）具备强大的语义推理能力，但无法部署在算力、功耗受限的移动机器人本体上；若将推理放到云端，则面临网络延迟、抖动和丢包问题。这构成了"云端语义推理"与"本地闭环控制"之间的系统性冲突。
- **既有方案不足**：
  - 动作分块（action chunking）假设环境在开环执行期间静止，延迟会持续累积。
  - 同步快慢双速率系统（如 MResT、HiRT、DP-VLA）要求固定的频率比和有限延迟，真实网络环境中难以满足。
  - 异步策略（如 VLASH）虽提升吞吐量，但慢路径表征可能过期到达，或需要显式调度与延迟提示。
- **论文的核心主张**：将时间错位视为表征学习问题，而非纯推理调度问题。延迟容忍能力应成为"学习到的接口属性"，而非依赖外部同步机制。

### 核心问题
> 如何设计一种云-边协作策略，使云端 VLA 表征的网络延迟不影响闭环控制性能，且不需要阻塞同步、显式延迟信息或频率对齐？

## 2. 方法论：CloudEdgeVLA

### 核心思想
借鉴 Kahneman 的"系统 1 / 系统 2"双系统认知框架，将信息按时间角色分离：
- **云侧（System 2）**：编码"做什么"——任务目标、操作策略、物体语义等**缓慢变化**的任务上下文。
- **边缘侧（System 1）**：处理"现在怎么做"——利用当前实时视觉进行状态敏感控制。

### 系统架构（三个组件）
1. **云侧 VLA 骨干网络 fθ**（延迟不敏感）
   - 大型视觉语言模型，在 LoRA 微调权重下运行于云端。
   - 输入：观测 o 与语言指令 ℓ；输出：规划特征 h = fθ(o, ℓ) ∈ R^(L×D)，其中 L = T×A 为动作 token 位置数。
2. **边缘侧视觉编码器 vψ**（延迟敏感）
   - 轻量级 SigLIP-Base 视觉编码器，冻结权重，在本地提取实时特征 z_t = vψ(o_t)。
   - 关键优势：**永远基于当前最新观测**，零延迟。
3. **边缘侧动作头 gϕ**（延迟敏感）
   - 学习融合（可能过期的）云端规划特征与实时视觉特征，输出动作块 â_t = gϕ(h_{t−k}, z_t) ∈ R^(T×A)。
   - 实现：对规划特征按动作维度做均值池化 → 投影视觉特征到同一潜在空间 → 拼接 → 残差 MLP。

### 配对帧双路径训练（Paired-Frame Dual-Path Training）
这是方法的核心创新，具体流程如下：

1. **配对帧提取**：从同一 episode 中获取 W 帧连续观测窗口 {o_{t−W+1}, …, o_t}，构造当前帧 o_t 和延迟帧 o_{t−d}（d ~ Uniform(1, W−1)）。
2. **双前向传递**：两帧分别通过云骨干：
   - h_fresh = fθ(o_t, ℓ)
   - h_stale = fθ(o_{t−d}, ℓ)
   - **注意**：h_stale 不脱离计算图，两条路径均接收梯度。
3. **视觉增强动作预测**：两组规划特征与相同的实时视觉特征 z_t = vψ(o_t) 融合：
   - â_fresh = gϕ(h_fresh, z_t)
   - â_stale = gϕ(h_stale, z_t)
4. **双路径损失**（关键公式）：
   - L = (1−λ)·‖â_fresh − a_t‖₁ + λ·‖â_stale − a_t‖₁
   - 两项监督同名当前真实动作 a_t；采用课程学习，λ 在前 n_warmup 步内从 0 逐渐升至 λ_max。

### 部署协议（完全异步、非阻塞）
- 边缘捕获 o_t → 异步发送给云端 → 云端返回特征后更新"最新可用特征" → 边缘计算 z_t → 边缘动作做 gϕ(最新云特征, z_t) → 执行。
- **机器人永不等待云端响应**，始终使用最新可用的云特征与当前实时视觉结合。

### 涌现表征特化（Emergent Representational Specialization）
- 过期路径的梯度 ∇θL_stale 要求云特征在随机延迟 d 下仍能预测当前动作 a_t。
- 这会产生一种**软压力**（非数学保证）：与瞬时状态绑定的特征变得不可靠，而任务身份、目标、粗进度等稳定信息被保留。
- 该压力与"干扰变化 → 不变表征"的理论联系一致（Achille & Soatto, 2018）。

### 核心结果
| 方法 | d_max=0 宏平均 | d_max=10 宏平均 | d_max=40 宏平均 |

### 关键结论
1. **极端延迟鲁棒性**：d_max=40 时，CloudEdgeVLA 在 4 个套件上保持 63.8-78.0% 成功率，比最强基线高 71.8 个百分点。
2. **延迟 AUC**：CloudEdgeVLA 达到 90.8%（VLASH 仅 32.4%）；同步成功率保留 76.5%（VLASH 1.8%）。
3. **表征专门化效应**：训练后骨干漂移在 d=20 处降低 59.2%，头的传递增益降低 72.7%，动作漂移降低 88.9%。
4. **消融揭示贡献来源**：
   - 当前边缘视觉是主要因素（+63.5 个百分点）。
   - 过期路径训练（L_stale）提供大部分鲁棒性（+34.4 百分点相对 L_fresh-only）。
   - 双路径联合监督比单独使用任一路径更好。
5. **负结果**：反事实审计显示，在 120k 检查点处，**当前边缘视觉对过期云端特征的直接校正作用极小**（边缘救援分数仅 0.03%），增益主要来源于稳定的骨干和头部衰减效应。

## 7. 优点

1. **问题形式化清晰**：将延迟容忍明确定义为云-边接口的特征学习问题，而非调度问题。
2. **无需显式延迟信息的非阻塞接口**：边缘始终使用最新特征，无需时钟对齐或频率比约束，非常实用。
3. **双路径配对训练设计精妙**：随机延迟 + 相同动作目标 + 课程学习 λ 调度，简洁有效地激励表征时间稳定性。
4. **训练部署不对称性合理**：训练双前向开销可接受，推理时完全异步。
5. **系统性消融与诚实的机制审计**：尤其是补剂部分的"反事实边缘年龄"分析，主动揭示机制局限（边缘视觉直接校正很小），避免夸大方法原理，体现了学术诚信。
6. **多视角验证**：闭环成功率 + 离线机制诊断 + 真实机器人小规模验证，形成较完整的证据链。
7. **良好的可扩展性**：云模型可无限扩充，边缘仅需轻量视觉编码器 + 小型 MLP。

## 8. 不足与局限

1. **延迟分布覆盖有限**：仅测试均匀延迟(0, d_max)，未评估真实网络延迟的高方差抖动、间歇性丢包或长时间断连。
2. **双骨干前向的训练效率**：配对帧训练每步需两次 7B 模型前向，训练成本较高。
3. **冻结 RGB 编码器的感知局限**：没有深度、力觉或触觉信息，限制了对接触敏感任务的处理能力。
4. **真实硬件验证不足**：
   - 10 次试验/单元不具有统计效力。
   - 边缘设备为工作站级（RTX 5080），未验证嵌入式/低功耗平台的可行性。
5. **机制主张需要细分**：反事实审计表明 EdgeVLA 的主要鲁棒性来自骨干稳定性与头部衰减，而非"边缘视觉直接修复过期云特征"这一直观叙事——作者对此澄清但意味着论文的"直觉故事"与实际机制存在部分偏差。
6. **单一仿真基准**：仅 LIBERO，未检验长视界任务（LIBERO-Long 表现已是最弱 63.8%）、复杂接触操作或更接近真实世界分布的更复杂任务。
7. **未与相关方法全面对比**：未包含 Fast-in-Slow、A2C2、语义-动作解耦方法的直接对比。
8. **不可无限容忍延迟**：作者明确声明"不隐含无限延迟或云端断连的容忍能力"；长时间断连需要时间戳特征与本地回退策略。
