## 摘要
无查询感知的KV缓存驱逐会压缩一次上下文，并将生成的缓存复用于任意未来查询，但在紧凑预算下性能可能崩溃。现有方法主要改进保留哪些原始KV对。我们引入RestoreKV，通过在同一总KV预算下进行学习式恢复，补充这种基于选择的方案。我们的关键见解是，尽管驱逐造成的信息损失是上下文特定的，但生成其紧凑补全的机制可以在不同上下文之间共享。在上下文预填充后，几个恢复令牌在单次LoRA自适应传递中关注完整KV缓存，生成一个紧凑的、上下文条件的恢复缓存。基础重要性评分器和驱逐规则保持不变，适配器在后续所有查询和解码中禁用。RestoreKV通过冻结全缓存模型进行参数高效的自蒸馏训练，仅优化0.4%的参数，且无需任务特定调整。在四个骨干网络和四个长上下文基准上，RestoreKV显著减少了压缩引起的性能下降。在Qwen3-4B上，它改善了五种基础驱逐方法在60个配对、预算匹配设置中的59个；在5%预算下，它在RULER-4K上将KVzip从38.2提高到73.2。将RestoreKV应用于KVzip+，在KVPress基准的16倍压缩下达到86.4的RULER准确率，同时在32K上下文评估中仅增加不到0.5%的一次性缓存构建开销。我们的项目页面可在https://paper.pnu-cvsp.com/RestoreKV/获取。

## Abstract
Query-agnostic KV cache eviction compresses a context once and reuses the resulting cache for arbitrary future queries, but performance can collapse under tight budgets. Existing methods primarily improve which original KV pairs are retained. We introduce RestoreKV, which complements this selection-based formulation with learned restoration under the same total KV budget. Our key insight is that, although the information lost through eviction is context-specific, the mechanism for generating its compact complement can be shared across contexts. After context prefill, a few restore tokens attend to the full KV cache in a single LoRA-adapted pass, generating a compact, context-conditioned restore cache. The base importance scorer and eviction rule remain unchanged, and the adapters are disabled for all subsequent queries and decoding. RestoreKV is trained through parameter-efficient self-distillation from the frozen full-cache model, optimizing only $0.4\%$ of the parameters and requiring no task-specific tuning. Across four backbones and four long-context benchmarks, RestoreKV substantially reduces compression-induced degradation. On Qwen3-4B, it improves 59 of 60 paired, budget-matched settings across five base eviction methods; at a $5\%$ budget, it raises KVzip from $38.2$ to $73.2$ on RULER-4K. Applied to KVzip+, RestoreKV reaches $86.4$ RULER accuracy at $16\times$ compression on the KVPress Benchmark, while adding less than $0.5\%$ one-time cache-construction overhead in a 32K-context evaluation. Our project page is available at https://paper.pnu-cvsp.com/RestoreKV/

## 1. 核心问题与整体含义

**研究动机与背景：**
- 大型语言模型依赖长上下文，但 KV 缓存随序列长度线性增长，造成高昂的推理成本。
- 查询无关（query-agnostic）KV 缓存驱逐方法能对上下文一次性压缩并复用于任意未来查询，在服务场景中具有重要实用价值。
- 但这类方法在紧凑预算（如 5% 缓存比率）下性能会严重崩溃——即使重要性评分策略不断改进，选择出更好的原始 KV 对子集仍无法阻止性能骤降。
- 现有方法（如 KVzip、KVzip+、ContrastKV 等）本质上都遵循同一范式：**从原始 KV 对中选出更好的子集**，缓存中全部元素都是原始状态，没有引入任何新的信息表示。

**核心洞察：**
- 驱逐造成的信息损失是**上下文特定的**（不同上下文丢失的"脆弱信息"各不相同），但生成紧凑补全的**机制是可以跨上下文共享的**。
- 因此，除了"选哪些"之外，还存在一个互补的问题：能否在驱逐之前生成一个小的、上下文条件的补全缓存，来保留那些本会被丢失的行为？
- RestoreKV 正是基于这一视角，将恢复机制引入查询无关 KV 缓存驱逐，在同一总 KV 预算下补充选择式方法，显著缩小与全缓存模型之间的性能差距。

## 2. 方法论

**核心思想：**
RestoreKV 在学习"保留哪些 KV 对"之外，补充了**学习式恢复**：在上下文预填充后、驱逐之前，使用少量可学习的"恢复令牌"（restore tokens）读取完整 KV 缓存，生成一个紧凑的、上下文条件的恢复缓存（restore cache），与保留的原始 KV 对共同构成最终的同预算缓存。

**关键技术细节：**

1. **恢复令牌与 LoRA 适配**
   - 定义 n 个可学习恢复令牌嵌入 \(E \in \mathbb{R}^{n \times d}\)（默认 n=8）。
   - 预填充完成后，恢复令牌在位置 T+1 至 T+n 以因果方式访问完整 KV 缓存 C，经过**单次 LoRA 适配的恢复过程**（restore pass），生成恢复缓存 \(C_{res} = \text{Restore}_{\theta,\phi}(E \mid C)\)，其中 θ 为冻结骨干参数，φ 为 LoRA 参数。
   - LoRA 更新方式：\(\Delta W = \alpha \frac{r_{\text{LoRA}}}{B} A_\phi B_\phi\)，秩 \(r_{\text{LoRA}}=8\)，缩放因子 α=16，作用于注意力 q/k/v 和 MLP 投影。
   - 每个恢复令牌在每个层、每个 KV 头上产生一对 KV，因此恢复缓存大小为 \(|C_{res}| = nLH\)。

2. **预算匹配**
   - 从总预算 B 中预留 nLH 个槽位给恢复缓存，基础驱逐器填充剩余 \(B - nLH\) 个槽位：
     \[\tilde{C} = \text{Concat}(\text{Evict}(C, s, B - nLH),\; C_{res})\]
   - 最终缓存与基础方法总 KV 预算完全一致（\(|\tilde{C}| = B\)）。
   - 保留的原始 KV 对维持其 RoPE 相位，恢复令牌占位置 T+1 至 T+n，未来查询从位置 T+n+1 开始。

3. **训练目标：自蒸馏**
   - 冻结全缓存模型作为教师，对同一上下文和查询生成答案 y。
   - 教师和学生（使用预算匹配缓存 \(\tilde{C}\)）分别评估相同答案的令牌分布 \(p_i^{\text{full}}\) 和 \(p_i^{\text{pres}}\)，最小化对称 KL 散度：
     \[\mathcal{L}_{\text{distill}} = \frac{1}{2M} \sum_i \left[ \text{KL}(p_i^{\text{full}} \| p_i^{\text{pres}}) + \text{KL}(p_i^{\text{pres}} \| p_i^{\text{full}}) \right]\]
   - 仅更新恢复令牌嵌入和 LoRA 参数（约 0.4% 的 4B 骨干参数），骨干和重要性评分器全部冻结。
   - 训练时从均匀分布 \(r \sim U(0.025, 0.25)\) 采样 KV 预算比率，使一个恢复机制支持多个预算。

4. **推理流程**
   - 对每个新上下文，恢复过程只执行一次（8 个额外位置的前向传播），之后 LoRA 被禁用。
   - 所有后续查询处理和自回归解码都使用原始冻结骨干，不增加任何查询时 KV 开销或解码成本。

## 6. 主要结论与发现

1. **显著缩小与全缓存性能的差距**：在 Qwen3-4B 上，5% 预算下将 KVzip 在 RULER-4K 从 38.2 提升至 73.2；KVzip+ 从 51.6 提升至 70.7；应用于 KVzip+ 后在 KVPress 基准的 16× 压缩下达 86.4 准确率。
2. **跨方法、跨骨干、跨预算的普适性**：在 60 个配对设置中改善 59 个；在 Qwen3 与 Llama 家族、0.6B 至 8B 规模上均一致有效；预算越紧、增益越大。
3. **注意力侧适配是恢复的主要来源**：固定嵌入 + LoRA 达到 71.9，而仅学习嵌入只有 42.1（r=0.05），说明收益主要来自 LoRA 对注意力的适配——即生成上下文条件恢复缓存的能力，而非嵌入中的通用记忆。仅适配 q/k/v 投影即可达到 72.4。
4. **全上下文条件访问提供了额外收益**：从完整缓存生成恢复缓存（73.2）比从已驱逐缓存生成（64.4）高 8.8 个点，确认驱逐前访问完整上下文是有价值的。
5. **注意力恢复机制**：RestoreKV 将最终查询令牌对非 sink 上下文 KV 对的注意力质量从 0.56% 恢复至 1.30%，逐层分布更接近全缓存模式（KL 从 0.198 降至 0.167），预测分布与全缓存的散度从 7.3 降至 3.8。
6. **开销极小**：32K 上下文中恢复过程仅增加 0.03–0.04 秒（<0.5% 压缩时间）和 84 MB 峰值内存（0.4%），推理时注意力延迟与 KV 内存与基础方法几乎完全一致。
7. **与 Fast KVzip 兼容且互补**：在 RULER-4K 上 16× 压缩下将 Fast KVzip 从 46.7 提升至 79.3，同时保留单次打分的高效性。

## 7. 优点

1. **视角新颖**：从"选得更好"转向"选 + 生成补全"，打开了查询无关 KV 驱逐的新研究方向。
2. **即插即用、兼容性强**：保持基础评分器和驱逐规则完全不变，仅替换部分缓存组成，可插入任意查询无关驱逐器。
3. **预算严格匹配**：恢复缓存消耗的是已有预算而非额外缓存，推理时 KV 内存和注意力延迟与基础方法完全一致。
4. **参数高效**：仅训练 0.4% 参数，训练时间约 2 小时，无需任务特定微调，且一次训练可跨任务复用。
5. **开销极低**

5. **开销极低**（续）：推理阶段零额外延迟，恢复过程时间与内存成本均可忽略，且无需修改基础方法的预填充或解码流程。

6. **推理阶段完全无额外成本**：LoRA 仅在恢复过程中启用一次，之后所有查询和解码均使用冻结骨干，注意力计算量与 KV 内存占用与基础驱逐方法完全一致。

## 8. 缺点与局限性

**客观指出论文存在的不足：**

1. **训练需逐模型逐方法单独执行**：论文明确说明 RestoreKV 需要针对每个骨干模型和每个基础驱逐方法各训练一次。虽然单次训练成本低（约 2 小时），但面对多种模型-方法组合时总成本线性叠加，实际部署中若需要频繁更换基座模型或驱逐策略，维护成本较高。

2. **未充分讨论恢复机制的可解释性**：论文虽然通过注意力分析说明了恢复令牌确实提升了查询对非 sink KV 的注意力质量，但恢复缓存中具体编码了什么样的"信息"、为什么某些上下文需要更多恢复槽位，仍缺乏细粒度的理论解释或案例分析。

3. **预算预留的竞争关系**：RestoreKV 从总预算中预留 nLH 个槽位给恢复缓存，这意味着在极低预算（如 r=0.025）下，保留的原始 KV 对数量会被显著压缩。论文虽通过训练时采样多个预算比率来缓解，但未深入分析恢复缓存与原始缓存之间的最优分配比例是否存在理论下界。

4. **对基础驱逐方法仍有依赖**：虽然 RestoreKV 可以叠加在任何查询无关驱逐器上，但其最终上限仍受制于基础方法保留的原始 KV 对的质量。如果基础驱逐器在极低预算下丢失了关键位置信息（如某些需要精确复述的长距离事实），恢复缓存可能无法完全弥补。

5. **评估基准的上下文长度有限**：虽然附录中报告了 SCBench（约 104K 令牌）的结果，但主实验集中在 4K–11K 令牌区间。对于 32K、128K 甚至更长上下文的实际部署场景，恢复令牌数量 n=8 是否仍然足够、LoRA 适配的泛化能力如何，缺乏系统验证。

6. **生成式蒸馏的长尾风险**：自蒸馏目标本质上是对齐学生与教师的分布，这意味着当教师（全缓存模型）本身在某个任务上表现不佳时，RestoreKV 无法超越教师的性能上界——它只能缩小差距，不能创造更好的一致性。

## 9. 与已有工作的对比定位

- **与选择式方法（KVzip、SnapKV、H₂O 等）的关系**：RestoreKV 不是替代而是**补充**。它保留了选择式方法的核心流程（重要性评分 + 驱逐），仅在其输出上额外叠加一个生成式恢复缓存。这使得它能与现有方法无缝集成，而非从头竞争。

- **与合成/生成式缓存方法（Attention Matching）的区别**：AM-fast 从头合成整个 KV 缓存，放弃了原始 KV 对中的所有信息；RestoreKV 则保留大部分原始 KV 对，仅用生成的补充缓存覆盖驱逐已有的信息损失。这种"选择 + 生成"的混合策略在低预算下更具鲁棒性——因为它在保留原始保真度的同时，通过生成部分引入了选择式方法无法访问的新信息。

- **与查询相关恢复方法（如按查询重算）的本质差异**：查询相关方法需要为每个新查询重新计算或恢复缓存，推理开销随查询数线性增长；RestoreKV 的恢复过程是一次性的、查询无关的，与任何未来查询的解码路径解耦——这使得它在多查询服务场景下具有独特的优势。

- **在 KV 缓存压缩研究谱系中的位置**：RestoreKV 处于"预填充时压缩"这一分支的最新端。它与其他非学习式启发式（如频率、局部性）和学习式评分器（如 ContrastKV）正交，且能与它们自由组合。论文的 60 个配对实验表明这种正交性在大部分配置下都能转化为实际增益。

## 10. 个人思考与展望

**这一工作可能引发的后续研究方向：**

1. **最优恢复缓存大小自适应**：当前 n=8 是固定超参数。未来工作可以探索根据上下文特性（如熵、语义密度、任务类型）动态调整恢复令牌数量，使预算分配在原始与恢复缓存之间更灵活。

2. **多粒度恢复单元**：当前恢复是以 KV 对为单位生成。可以探索在更大粒度（如 token 块、语义片段）上学习恢复表示，对长上下文压缩可能更高效。

3. **与推测解码/前缀缓存结合**：恢复缓存本质上是上下文的一种压缩摘要，可考虑用于多轮对话中的前缀复用或跨会话的主题缓存。

4. **统一框架的提出**：RestoreKV 的核心思想——"驱逐 + 生成补全"——可以推广到其他记忆压缩场景（如 RAG 的长期记忆管理、多模态上下文的视觉 token 压缩），形成一个统一的认知压缩框架。

**从更广的角度来看**，这项工作揭示了一个有趣的对称性：在 KV 缓存压缩中，"选择"与"生成"不是互斥的，而是可以像概率模型中的生成式重参数化一样互补。它的成功表明，在信息瓶颈下，最优的压缩策略可能不是单纯地挑选信息，而是将信息转化为一种更紧凑的隐式表示——这与认知科学中"记忆是重建而非回放"的观点有微妙的呼应。

## 11. 总结性评价

RestoreKV 在查询无关 KV 缓存驱逐领域提出了一种新颖且实用的补充机制。它通过"学习式恢复缓存"这一设计，将生成式压缩引入了一个长期由选择式方法主导的领域，在严格保持总 KV 预算的同时，显著提升了低预算下的模型性能。论文的实验设计注重公平性（预算匹配）、严谨性（控制实验、消融）和泛化验证（多骨干、多基准、多预算），结论可信度较高。其最突出的贡献在于证明了"选 + 生成"的混合策略优于纯选择策略，且几乎不增加推理成本——这一洞见可能对后续 KV 压缩研究产生持久的范式影响。尽管存在训练需逐方法执行、长上下文验证不足等局限，但整体上这是一项完成度高、实用价值明确、具有良好扩展性的优质工作。
