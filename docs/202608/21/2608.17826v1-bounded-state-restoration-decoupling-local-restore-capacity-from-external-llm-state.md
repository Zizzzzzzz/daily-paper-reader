## 摘要
分层KV缓存系统可以在GPU内存之外保留长上下文LLM执行状态，但保留容量并不决定使该状态可重新执行所需的本地内存。我们将这第二种资源隔离为恢复工作集（RWS）：在恢复期间其生命周期重叠的峰值本地暂存状态。在固定的上游LMCache全计划路径中，测量到的1.956、7.823和15.646 GiB/秩状态的完全复用点首次在2、8和16 GiB L1层级成功，成功的L1峰值分别为1.956、7.824和15.648 GiB/秩。我们引入了有界状态恢复（BSR），它将完整的发现与本地驻留分离。BSR探测完整的可复用前缀，而不在L1中物化整个命中，然后通过最多$W$块的可复用窗口安装已确认的状态。在有界辅助状态下，峰值恢复容量为$O(W)$，而总传输和安装工作量保持$Θ(|S|)$。由于可复用状态跨越异构分配器组和张量并行秩，BSR使用请求级提交规则：部分安装永远不会作为有效的可复用前缀暴露；失败会使已通告的前缀失效，并回退到较低的有效层级或确定性重新计算。在DeepSeek-V4-Flash上，TP=2跨两个DGX Spark节点，一次干净的无恢复扫描将外部状态从1.956增长到31.277 GiB/秩，而测量的L1 RWS在$W=32$时恰好保持在500.75 MiB/秩，最大状态外部与活暂存比为63.959倍。第二次全新的524K令牌运行重复了最大状态接受结果。评估的层级和秩不对称失败在回退前暴露了完全复用或零外部复用。匹配的SSD优化将512K恢复TTFT从43.1秒降至17.6秒，而RWS不变。

## Abstract
Hierarchical KV-cache systems can retain long-context LLM execution state beyond GPU memory, but retention capacity does not determine the local memory required to make that state executable again. We isolate this second resource as the restoration working set (RWS): the peak local staging state whose lifetimes overlap during restoration. In the pinned upstream LMCache whole-plan path, measured full-reuse points for 1.956, 7.823, and 15.646 GiB/rank states first succeed at 2, 8, and 16 GiB L1 rungs, with successful L1 peaks of 1.956, 7.824, and 15.648 GiB/rank.   We introduce Bounded-State Restoration (BSR), which separates complete discovery from local residency. BSR probes the complete reusable prefix without materializing the whole hit in L1, then installs confirmed state through a reusable window of at most $W$ chunks. Under bounded auxiliary state, peak restoration capacity is $O(W)$ while total transfer and installation work remains $Θ(|S|)$. Because reusable state spans heterogeneous allocator groups and tensor-parallel ranks, BSR uses a request-level commit rule: partial installation is never exposed as a valid reusable prefix; failures invalidate the advertised prefix and fall back to a lower valid tier or deterministic recomputation.   On DeepSeek-V4-Flash with TP=2 across two DGX Spark nodes, a clean no-resume sweep grows external state from 1.956 to 31.277 GiB/rank while measured L1 RWS remains exactly 500.75 MiB/rank at $W=32$, a 63.959x largest-state external-to-live-staging ratio. A second fresh 524K-token run repeats the largest-state acceptance result. Evaluated tier and rank-asymmetric failures expose either complete reuse or zero external reuse before fallback. A matched SSD optimization reduces 512K restore TTFT from 43.1 to 17.6 seconds without changing RWS.

**研究动机与背景：**
- 长上下文LLM服务中，越来越多的系统将先前计算视为可复用的执行状态，通过分层/分离式KV缓存将状态保存在主机内存、SSD或远程内存中（如CachedAttention、Mooncake、LMCache等），以规避重复长预填充的开销。
- 现有系统主要优化的是“外部保留容量”（retention capacity）——即可以在引擎之外存在多少可复用状态。然而，**保留容量并不决定恢复该状态所需的本地内存**。论文将后者独立定义为一个新资源：**恢复工作集（RWS, Restoration Working Set）**——恢复过程中生命周期重叠的峰值本地暂存状态。
- 在固定的上游LMCache全计划路径中，外部状态为1.956、7.823、15.646 GiB/rank时，需要2、8、16 GiB的L1层级才能完全复用，且实测L1峰值几乎等于整个选中状态大小。这表明传统恢复路径的本地暂存需求与外部状态规模**线性耦合**。
- 核心问题：**能否在知道完整可复用外部状态的前提下，通过一个显式有界的本地工作集恢复它，同时保持请求级正确性和故障时的fail-closed语义？**

**整体含义：**
- 论文提出**完全知识不需要完全本地驻留**（complete knowledge does not require complete local residency）这一核心洞察，将“发现完整可复用前缀”与“在本地物化该前缀”两个过程解耦。

## 2. 论文提出的方法论

### 核心思想
BSR（Bounded-State Restoration，有界状态恢复）将恢复过程分为三个独立阶段：

1. **Probe（探针）阶段**：仅执行查找，获得完整的候选命中位图（hit bitmap），不将完整结果物化到L1。输出的是**知识**——完整的可复用前缀集合，而非本地拷贝。
2. **Install（安装）阶段**：以窗口为单位（最多W个chunk）迭代安装。每个窗口先抓取、再验证完整性、映射到目标区块、传输、同步、然后释放暂存空间，供下一窗口复用。暂存容量从Θ(|S|)降为O(W)。
3. **Commit（提交）阶段**：请求级语义验证。定义
   - $Q(S) = \bigwedge_{r=1}^R \bigwedge_{g=1}^G q_{r,g}$
   - 仅当所有TP rank、所有语义组（allocator groups）均有效时，才暴露完整前缀复用。
   - 任何窗口失败/不完整/超时/传输异常都会使目标区块失效；异构内存分配中任何组的无效都会使**整个通告前缀折叠为零**。

### 关键技术细节
- **RWS形式化定义**：
  - $\text{RWS}(\rho) = \max_t \sum_{u_i \in L_\rho(t)} c_i$
  - 排除外部保留副本和正常模型执行所需的目标内存。
- **三种资源的区分**：
  - **保留容量**：外部可存放多少可复用状态。
  - **恢复容量**：使选中状态可执行所需的RWS。
  - **执行余量**：恢复池配置后留给模型权重、活跃KV、运行时缓冲和并发工作的剩余部分。
- **边界保证**（Proposition 1）：
  - $\text{RWS}_{\text{BSR}}(S, W) \leq W \cdot c_{\max} + M_{\text{aux}}(W)$
  - 即峰值恢复容量为$O(W)$，与N（状态规模）无关；状态增长转化为窗口迭代次数$K=\lceil N/W \rceil$的增长。
- **总工作量不变**：总传输与安装工作量仍为Θ(|S|)，BSR是空间抽象而非常数时间恢复。
- **窗口容量定律**（针对MTP-off注册的DeepSeek-V4-Flash）：
  - $M_{L1}(W) = W \times 16{,}408{,}576$ bytes/rank

### 协议流程
- 探针查找→通告前缀并分配目标块→窗口1(≤W)抓取/验证/安装/同步/释放→窗口2…→全秩+全组验证→提交或回退。
- **故障恢复**：安装force-local标记，跳过重复外部查找，重新进入本地prefill admission；失败路径为较低有效层级或确定性重新计算。

## 3. 实验设计

### 系统与配置
- 模型：DeepSeek-V4-Flash（MTP-off注册167个张量；MTP-on注册170个张量）
- 硬件：两个DGX Spark节点，TP=2；每个DGX rank有100 Gb/s RDMA直连到外部Mooncake存储（128 GiB segment，严格租户隔离）；本地SSD作为较低可复用层级。
- 软件：扩展LMCache和vLLM，不改模型kernel和外部状态表示。

### 实验组别
1. **上游whole-plan容量阶梯**（Experiment 1）：W=0，逐步增大L1配置（2/8/16 GiB），测32K/128K/256K前缀首次完整复用所需容量。
2. **干净的BSR同epoch扩展扫描**（Experiment 2）：W=32、MTP关闭、L1配置1 GiB、直接RDMA传输；在一个无恢复扫描中依次测32768/65536/131072/262144/393216/524032 tokens。另有一次全新524032 tokens重复运行。
3. **窗口定律验证**：256K前缀下W∈{8,16,32,64}四个设置，验证RWS是否严格等于W×16,408,576 bytes/rank。
4. **异构MTP状态**：524032 tokens、MTP开启、170张量，验证同一RWS定律。
5. **故障矩阵**：四个场景——远程健康正常恢复、远程不可用但SSD健康、远程+SSD均不可用、单rank远程恢复故障。验证“完整前缀复用”或“零外部复用”。
6. **SSD吞吐A/B**：512K前缀、W=32固定，文件系统对象加载并发从1调到4，测TTFT变化和RWS是否保持。

## 6. 论文的主要结论与发现

1. **上游whole-plan恢复路径将本地恢复容量与状态规模耦合**：32K/128K/256K前缀分别需要2/8/16 GiB L1才能完全复用，L1峰值分别达到1.956/7.824/15.648 GiB/rank，与外部状态几乎一致。
2. **BSR解耦了保留容量与本地恢复容量**：在干净的同epoch扫描中，外部状态从1.956增长到31.277 GiB/rank（15.99×），而实测L1 RWS恒为500.75 MiB/rank（W=32），最大外部/活跃暂存比为**63.959×**。
3. **W是显式的容量控制旋钮**：W=8/16/32/64实测RWS分别为125.19/250.38/500.75/1001.50 MiB/rank，与$W \times 16{,}408{,}576$ bytes/rank**零残差**匹配。
4. **异构状态与故障fail-closed**：MTP-on（170张量）的524K状态同样能满足接受标准。在远程不可用、远程+SSD均不可用、单rank故障场景下，暴露的要么是完整通告前缀，要么是零外部复用——从未观察到部分有效前缀被暴露。
5. **恢复吞吐与RWS可分离控制**：SSD对象加载并发从1提到4，512K恢复TTFT从43.1秒降至17.6秒（2.45×提速），RWS保持500.75 MiB/rank不变。

## 7. 优点

1. **概念定义精准**：将“保留容量”“恢复容量”“执行余量”“恢复吞吐”清晰区分为四种不同资源，为后续研究提供了清晰的抽象语言。
2. **理论与实证对照严格**：W定律（Eq. 5）与实测零残差，方法论上非常扎实。
3. **协议设计考虑了真实系统的复杂性**：
   - 可复用状态跨TP rank和多种allocator组，不是单一同质blob；
   - 部分安装可能传递“看似合法”的字节但语义不安全；请求级提交规则杜绝了这个风险。
   - 失败后设置force-local标记避免重复触发同一外部故障。
4. **实验纪律好**：区分“测量点”和“推导点”，拒绝将未完成的上游512K作为测量结果；干净的E1同一epoch扫描消除了跨epoch偏差。
5. **范围控制恰当**：不声称认证恢复、不声称常数时间恢复、不声称通用系数，诚实地限定在“外部层级仍需本地安装”这一常见场景。
6. **与现有系统生态兼容**：只修改LMCache和vLLM的控制路径，不改kernel和外部状态表示，部署成本低。

## 8. 不足与局限

1. **模型/配置单一**：所有实验使用单一的DeepSeek-V4-Flash、TP=2、单种chunk大小（256 tokens）。未验证其他模型架构、其他TP维度、其他状态表示下的普适性。
2. **性能结论强度有限**：
   - 主扫描的TTFT为“描述性”单次测量，不可推断统计显著性。
   - W∈{8,16,32,64}的TTFT非单调（7.54, 4.13, 8.09, 7.05秒），论文明确不选择“通用最优W”。
   - 恢复延迟仍然随状态规模线性增长（K=⌈N/W⌉迭代次数增加），吞吐与延迟仍有优化空间。
3. **并发模型保守**：原型用全局锁串行化所有有界恢复请求，限制多请求重叠。论文提出全局admission budget $B$作为未来方向但未实现。
4. **正确性验证是操作层面的**：接受标准虽严格（token计数+输出hash+TP健康），但不是对所有prompt和未来模型隐藏状态值的形式化证明。fail-closed性质也只是“在实现规则下成立”，不是形式验证。
5. **512K上游对比缺失**：整个平面最关键的32GiB whole-plan点没有实测，对比图中“BSR在512K仍500.75MiB”与上游预期32GiB之间的差异基于推导而非直接测量。
6. **应用限制**：BSR适用于“外部状态仍需本地安装”的层级架构。对GH200/GB200这类相干内存平台（可直接访问CPU内存、无需暂存）——直接消除暂存是更强方案，BSR在此类硬件上价值有限。
7. **辅助状态（auxiliary state）的边界**：RWS测量范围是LMCache L1恢复池，不包括模型权重、目标KV状态、allocator元数据、通信缓冲区等——论文说明了这一点，但它意味着RWS不等同于全部进程内存。
