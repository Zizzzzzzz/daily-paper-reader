## 摘要
智能体语言模型会反复编码跨请求以不同组合和顺序出现的工具和技能模式，这阻碍了标准前缀缓存复用其键值（KV）状态。我们提出了ReCache框架，用于独立缓存资源表示，同时降低其推理时的计算和内存开销。资源级注意力消除了跨资源交互并分配资源局部位置，从而产生组合不变的KV块。随后，ReCache将资源可见性限制在贡献选择的层-KV头组路由上，并通过结构和语义剪枝仅保留调用关键字段。我们在由七个公开工具和技能使用数据集（包括资源不相交测试）组成的基准上评估了ReCache。资源级注意力与密集调用性能相当（82.3%对82.4%的Inv-F1），同时提供了3.655倍的首词时间加速。完整框架将分配的KV张量内存减少了92.43%，并将注意力加速了1.423倍。这些结果表明，将可复用的模式编码与选择性资源访问分离，能够以有限的有效性损失大幅降低智能体推理成本。代码可在https://github.com/EIT-NLP/ReCache获取。

## Abstract
Agentic language models repeatedly encode tool and skill schemas that recur across requests in different combinations and orders, preventing standard prefix caching from reusing their key--value (KV) states. We introduce \textbf{ReCache}, a framework for independently caching resource representations while reducing their inference-time computational and memory overhead. Resource-wise attention removes cross-resource interactions and assigns resource-local positions, producing composition-invariant KV blocks. ReCache then restricts resource visibility to contribution-selected layer--KV-head-group routes and retains only invocation-critical fields through structural and semantic pruning. We evaluate ReCache on a benchmark assembled from seven public tool- and skill-use datasets, including resource-disjoint tests. Resource-wise attention matches dense invocation performance (82.3\% versus 82.4\% Inv-F1) while providing a 3.655$\times$ time-to-first-token speedup. The complete framework reduces allocated KV-tensor memory by 92.43\% and accelerates attention by 1.423$\times$. These results show that separating reusable schema encoding from selective resource access substantially reduces agentic inference costs with limited effectiveness loss. The code is available at https://github.com/EIT-NLP/ReCache.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**

- 智能体语言模型（Agentic LLM）通过动态调用外部工具和技能（统称为“资源”）来完成任务。随着资源池规模扩大，系统通常采用渐进式披露（progressive disclosure）或检索机制，仅向模型展示与当前任务相关的资源模式（schema）。
- **核心问题**是：这些工具/技能模式（即资源schema）经常在不同请求中以**不同的组合和顺序**重复出现，导致标准前缀缓存（prefix caching）无法复用其KV状态——因为前缀缓存要求复用的内容必须构成完全相同的前缀，而动态组合的资源上下文很难满足这一条件。
- 结果导致**反复的预填充（prefill）计算**，造成推理时的高计算开销和高内存占用。随着资源数量变多、schema越来越长，这个问题愈发严重。
- **关键观察**：论文通过实验发现（图1），Qwen3-4B模型在资源内部（within-resource）的注意力显著强于跨资源（cross-resource）的注意力；且后续对话tokens对资源末尾（suffix token）的注意力最强。这暗示资源内部语义信息比全局资源顺序更重要，为“解耦资源编码”提供了依据。

**整体含义：**

该工作旨在解决工具增强型智能体推理时资源模式重复编码导致的KV缓存失效问题，通过将资源编码与上下文解耦，使得资源缓存可以独立构建、独立复用、按需压缩，显著降低智能体推理的延迟和内存开销，同时最大程度保持资源调用性能。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想

ReCache采用“**编码时解耦 + 推理时压缩**”的整体思路，将每个工具/技能schema（称为资源）的KV表示构建为**组合不变（composition-invariant）的独立缓存块**，然后在推理阶段通过结构剪枝与语义剪枝仅保留对资源调用最关键的信息，实现从“每次重复编码”到“一次编码、多次复用、按需访问”的转变。

### 三大核心机制

**(a) 资源级注意力（Resource-Wise Attention）**

- 在KV缓存构建阶段，**消除不同资源块之间的注意力交互**（cross-resource attention），只保留资源内部token之间的因果注意力以及资源与共享前缀的注意力。
- 同时，**将每个资源内部的位置索引重置为从零开始的相对位置**（pos(t_{i,j}) = j），使每个资源无论出现在检索结果中的哪个位置都获得相同的位置编码，从而**消除对全局资源顺序的依赖**。
- 这一设计使注意力复杂度从 O(D_R²) 降为 O(Σ_i D_i²)，并使得每个资源KV表示**组合不变**——即使资源以不同组合、不同顺序出现，其KV缓存都可以直接复用。
- 为了适应这种去掉跨资源交互和全局位置信息的注意力模式，需要**轻量级微调（fine-tuning）**来调整模型参数。

**(b) 结构剪枝（Structural Pruning）**

- 基于Transformer不同层和KV头组（KV head groups，GQA下）对资源调用的贡献不均的观察（已有大量研究表明Attention Head/层存在冗余）。
- 使用**leave-one-in分析**（与常见的leave-one-out剪枝不同）：从 Ω = ∅（即对话tokens无法访问资源状态）出发，逐一激活某一层或某一KV头组，测量其对调用损失（invocation loss）的边际减少量：

  - 层贡献得分：s_l = J(∅) − J(Ω_l)，其中 Ω_l = {l} × [G]
  - 头组贡献得分：s_g = J(∅) − J(Ω_g)，其中 Ω_g = [L] × {g}
  - 调用损失 ℓΩ(X,Y) 是目标资源调用Y在给定配置Ω下的负对数似然，只在调用相关位置（Y的token跨度T(Y)）上计算。

- 将正贡献归一化为权重 w_i，按权重从高到低选择预算内的层（Top-K_L）和KV头组（Top-K_G），构造最终路由配置 **Ω⋆ = L⋆ × G⋆**。
- 在推理时，只有 Ω⋆ 中的层-头组路由使用 M_resource 掩码（可访问保留的资源KV状态）；其余路由使用 M_context 掩码（完全剪掉资源tokens，只保留标准因果注意在非资源tokens上）。

**(c) 语义剪枝（Semantic Pruning）**

- 基于工具调用失败主要由**无效资源名和错误参数**引起这一观察，仅保留每个资源中三个关键字段的token：
  - **资源名称**（resource name）：支撑资源识别；
  - **参数名称**（argument names）：支撑参数接口对齐；
  - **参数描述**（argument descriptions）：支撑参数取值约束。
- 同时**保留资源的末尾token作为语义汇总锚点**（suffix token），利用其因果状态天然聚合了前面所有字段的信息（无需额外训练新summary tokens）。
- 消融实验表明：资源描述字段相对于上述字段提供的信息增益极小，因此可以安全剪掉。

### 最终推理流程

在推理时，最终掩码将上述三个决策组合起来：会话文本仅在 Ω⋆ 选定的层-头组路由上注意资源块中保留的语义字段，实现“资源能看见”和“看见什么”的双重控制。

## 3. 实验设计：数据集、Benchmark与对比方法

### 数据集与Benchmark构建

- **数据来源**：由7个公开工具/技能使用数据集合并构建统一评测基准，包括：
  - ToolACE（函数调用）、APIGEN（可验证函数调用数据）、ToolMind（推理增强工具使用）、ToolRet（工具检索）、Toucan（真实MCP环境工具数据）、SkillRouter（技能路由）、WildToolBench（真实世界工具使用）。
- **数据处理**：
  - 过滤包含幻觉调用（资源未在候选集中却被调用）和格式错误的样本；
  - 采用**多样化优先采样（diversity-first sampling）**策略：优先选择包含新调用资源和新候选集配置的样本，减少频率偏置和配置重复；
  - 最终得到 **49,424条训练样本**，另有5,000条用于初步实验。
- **评测划分**：
  - **分布内（in-distribution, T_IND）**：1,000条，涉及资源在训练中出现过；
  - **分布外（out-of-distribution, T_OOD）**：1,000条，涉及资源在训练中完全未见——用于评估模型对**未见资源的泛化能力**，这是一个重要且严格的评测设置。

### 评估指标

- **有效性**：Inv-F1（资源级调用F1，要求资源名和所有参数完全匹配）、Resource ID precision/recall/F1、Hallucination Rate（预测资源名不在候选集中的比例）。
- **效率**：TTFT（首Token时间，衡量缓存命中时的预填充延迟）、TPOT（每输出Token时间）、注意力延迟（Attn.）、KV张量内存占用（Mem.）。

### 对比方法

- **Dense**：标准密集注意力（无缓存复用）作为主基线。
- **Block**：仅消除跨资源注意力，保留原位置索引（消融用）。
- **Ω_full**：资源级注意力+位置重索引（完整资源级注意力基线，即无结构/语义剪枝）。
- **结构剪枝基线**：
  - **SPEED**（Shallow Prefill, Deep Decoding）：深度不对称KV可见性策略；
  - **SA_{20,3}**（attention-margin-based selection）：按注意力质量排序选择路由的替代方案。
- **语义剪枝基线**：
  - **Gist**（summary token方法）；
  - **Beacon**（chunk-level summary方法）；
  - **SMP**（ReCache自身的语义剪枝，单独评估）。

### 主干模型

- 主模型：**Qwen3-4B**（全参数微调）；
- 辅助模型：**Qwen3-1.7B**（用于分析结构预算对模型规模的敏感性）。

## 6. 论文的主要结论与发现

1. **资源级注意力有效**：消除跨资源注意力并重置局部位置后，调用性能与密集注意力几乎持平（82.3% vs 82.4% Inv-F1），但提供 **3.655× 的TTFT加速**——说明跨资源交互和全局资源顺序对调用任务并非必需。
2. **资源KV表示可以组合无关复用**：每个资源可独立编码、独立缓存，不同请求中无论资源如何组合和排列均可直接复用已构建的KV块。
3. **结构剪枝显著节省资源**：通过贡献引导选择20/36的层和3/8的KV头组（Ql），可实现79.2%的结构稀疏度，而Inv-F1仅下降0.2%；贡献引导选择显著优于注意力质量选择（SA）和层不对称方案（SPEED），尤其在OOD场景下幻觉率从13.4%（SPEED）降至0.5%。
4. **语义剪枝保留关键字段**：保留资源名、参数名、参数描述和suffix token即可维持大部分调用性能；相比之下，Gist等通用文本压缩方案严重失效。
5. **完整ReCache的总体收益**：在T_IND上保留Dense的97.5% Inv-F1、在T_OOD上保留91.8%，同时将**KV内存减少92.43%、注意力加速1.423×**。
6. **效率对不同资源规模保持近常数**：随着资源总长度增大，Dense的TTFT从数十毫秒增长到5秒以上、KV内存接近8 GiB；而ReCache的TTFT保持在约5ms、KV内存被限制在0.03 GiB以下，展现出良好的可扩展性。

## 7. 优点

- **问题定位精准**：准确识别了前缀缓存对动态组合的工具/技能模式失效这一智能体推理中的实际痛点，并用注意力可视化实验支撑核心假设。
- **方法论设计优雅且系统**：采用“解耦编码 + 渐进压缩”的层次化框架，将注意力模式修改、结构剪枝、语义剪枝三个环节有机结合，逻辑清晰、环环相扣。
- **组合不变性设计**：通过资源局部位置重索引，使缓存不受资源组合/顺序影响，相比EPIC/CacheBlend等需要位置校正的方案更简洁高效。
- **贡献引导的路由选择**：采用leave-one-in分析和调用损失驱动的贡献评估，比传统的attention-margin选择更可靠，尤其在OOD场景表现显著更好。
- **字段感知的语义压缩**：针对工具schema的结构化特性定制压缩策略（保留资源名/参数名/参数描述），比通用文本压缩方法（Gist/Beacon）更适配调用任务。
- **评测基准严谨**：构建了包含7个数据集的统一基准，并设计资源不相交（resource-disjoint）的OOD评测划分，防止模型通过记忆资源名而非理解schema来“作弊”；
- **训练数据去偏方法细致**：核心的diversity-first采样策略有效避免了源数据的频率偏差和候选子集重复问题。

---

## 8. 不足与局限

- **模型覆盖不足**：端到端实验仅覆盖Qwen3系列的两个模型（4B为主，1.7B为辅），未在更大规模模型或其他架构（如Llama、Mistral）上验证；结构预算对模型规模的敏感性也表明，当前结论的推广性有限。
- **需要微调，不适用于冻结模型**：由于修改了注意力掩码和位置布局，需要全参数微调来适配，无法直接用于已部署的冻结模型。
- **依赖相对稳定的环境**：设计前提是资源和系统指令相对稳定、可跨请求复用；对于资源动态变化、检索顺序或跨资源依赖携带关键信息的场景不适用。
- **假设绝对位置不重要**：论文假设资源间绝对位置对调用任务不重要，虽然实验支持这一假设，但在某些需要对多个资源输出结果进行顺序指定的复杂任务中可能存在风险。
- **专业资源环境限制**：没有评估是否适用于多资源强交互场景（如资源间存在参数依赖或API输出相互引用的情况），这类场景中跨资源交互可能是重要信息。
- **算力细节缺乏**：未报告训练时长、GPU数量等关键算力信息，可复现性和能耗估计受限。
- **端到端推理成本报告不完整**：虽然报告了TTFT/TPOT/注意力延迟等指标，但未包含完整端到端推理系统的整体吞吐量或服务成本（如CPU开销、调度开销），效率指标的全面性稍有欠缺。
