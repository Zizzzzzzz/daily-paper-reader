## 摘要
大型混合专家（MoE）语言模型拥有260亿至1200亿参数，通过三重同时存在的压力超出消费级设备的存储容量：常驻权重矩阵、随上下文长度线性增长的键值（KV）缓存状态，以及数十个必须按需分页的专家子层。我们提出RotaryQuant，一种从三个维度进行压缩的系统，用以同时解决上述所有问题。混合精度权重量化根据架构角色分配位宽：稠密层采用4比特，路由专家采用2比特，共享专家因其高激活峰度而难以激进压缩，采用8比特。LRU专家卸载在真实内存压力下将非驻留专家分页至磁盘。新颖的维度是IsoQuant，一种KV缓存压缩方法，在3比特标量量化前应用Walsh-Hadamard变换及块对角SO(4)旋转，使激活分布各向同性化，每个注意力头仅需O(d log d)次操作和256个存储参数，而稠密旋转方法需要O(d²)次操作和16,384个参数。一个融合的四内核Metal GPU流水线直接在打包的3比特张量上执行注意力计算，无需物化全精度KV状态——这是一种不同的执行模型，而不仅仅是量化方案。该组合系统可在16GB预算内适配Gemma 4-26B-A4B和Qwen3-30B-A3B，在32GB内适配Nemotron-H 120B，以9–19 tok/s的速度交互运行，困惑度退化近乎为零（ΔPPL ≤ +0.0012），且在32K上下文下检索准确率达到100%。

## Abstract
Large mixture-of-experts (MoE) language models with 26--120 billion parameters exceed the memory capacity of consumer devices through three simultaneous pressures: resident weight matrices, key-value (KV) cache state that grows linearly with context, and dozens of expert sublayers that must be paged on demand. We present RotaryQuant, a three-axis compression system that addresses all three. Mixed-precision weight quantization assigns bit-widths by architectural role: 4-bit for dense layers, 2-bit for routed experts, and 8-bit for the shared expert whose high activation kurtosis resists aggressive compression. LRU expert offloading pages non-resident experts to disk under genuine memory pressure. The novel axis is IsoQuant, a KV cache compression method that applies a Walsh--Hadamard transform followed by block-diagonal SO(4) rotations to isotropize activation distributions before 3-bit scalar quantization, requiring $O(d \log d)$ operations and 256 stored parameters per head versus $O(d^2)$ and 16{,}384 for dense rotation methods. A fused four-kernel Metal GPU pipeline performs attention directly on packed 3-bit tensors without materializing full-precision KV state---a different execution model, not just a quantization scheme. The combined system fits Gemma 4-26B-A4B and Qwen3-30B-A3B within a 16\,GB budget and Nemotron-H 120B within 32\,GB, running interactively at 9--19 tok/s with near-zero perplexity degradation ($Δ$PPL $\leq +0.0012$) and 100\% retrieval accuracy at 32K context.

## 2. 方法论

### 2.1 核心思想：三轴压缩系统
RotaryQuant 组合三个独立的压缩机制（非交换顺序）：
```
M_total = O_E ∘ C_KV ∘ Q_W
```
- **Q_W（权重量化）**：按架构角色分配位宽——稠密层 4-bit (GPTQ/AWQ)、路由专家 2-bit、共享专家 8-bit（因其激活峰度κ=10.10远高于专家层的0.41）。
- **C_KV（KV压缩，即IsoQuant）**：新颖的KV缓存压缩方法。
- **O_E（专家卸载）**：LRU策略将非驻留专家分页至磁盘。

### 2.2 IsoQuant 压缩流水线（核心贡献）
每个KV向量 x ∈ R^d（d=128）经过四个阶段：
1. **归一化**：将向量映射到单位球面，存储标量范数作为缩放因子；
2. **结构化旋转**：R = R_SO(4) ∘ H_d——先做 Walsh–Hadamard 变换（O(d log d)）全局混合能量，再对每个连续4维块做 SO(4) 旋转（双四元数表示，v → q_L·v·q̄_R）进行细粒度对齐；
3. **标量量化**：使用 Lloyd–Max 最优码本，3-bit量化每个坐标；
4. **位打包**：d=128 维压缩至48字节（对比FP16为256字节），实现约5.3×压缩。

### 2.3 数学基础
- **内积保持**：R 是正交变换，⟨Rq, Rk⟩ = ⟨q, k⟩，因此压缩域注意力分数等价于原始域；误差界 E[|qᵀk − dqᵀk|²] ≤ dk·σ²q·‖q‖²₂。
- **各向同性保证**：Hanson–Wright 不等式确保 WHT 后坐标近似均匀分布，最小化维度间最坏量化失真。
- **SO(4)参数化**：每块6自由度（两个单位四元数各3 DOF），d=128 时共192个可学习参数（存储256个float），远低于稠密旋转的16,384个参数。

### 2.4 融合Metal解码流水线（不同执行模型）
- 标准解码：解压 → 物化FP16 → GEMM → 注意力（reconstruct-then-compute）；
- IsoQuant：**四个融合内核直接在3-bit打包数据上计算注意力**，仅对最终的聚合输出应用一次逆旋转，无任何全精度张量物化。
- 总成本：O(T·dk) + O(dk log dk)，其中逆旋转开销随序列长度T摊销（T=2048时占比<0.5%）。
- 延迟预填充：prefill阶段KV存FP16，在prefill-to-decode边界批量压缩（暂存缓冲约230MB），避免跨位置误差累积。

### 9.3 可复现性评价
- **积极方面**：文中提供了完整的码本构建算法（Lloyd–Max 量化）、SO(4) 四元数参数化公式（主文公式 4–7）、WHT 的递归实现细节、四种融合内核的调度图、以及 12-prompt 质量门的完整内容（附录 G），并开源了 GGML_TYPE_ISOQUANT3_0 格式定义。相关度很高，技术债低。
- **消极方面**：关键的超参数（旋转块大小、Lloyd–Max 迭代次数、码本初始化方式）在正文中未完整给出，部分依赖于代码仓库的补充说明；且所有实验在单一操作系统（macOS）和单一框架（Metal）上完成，跨平台复现成本偏高。

### 9.4 潜在风险与未验证假设
- **规模外推假设**：论文证实了 26B–120B 范围的适用性，但未验证 200B+ 模型（如 Mixtral 8x22B、DeepSeek-V3 的 MoE）上是否仍保持同样的压缩效率——更大的专家数量可能改变 LRU 命中率分布和稀疏模式。
- **长上下文下 KV 压缩的累积漂移**：旋转的正交性保证了单步内积等价，但多次解码迭代中量化误差是否会沿位置累积，论文只在 32K 单模型上做了初步验证，缺乏理论误差迭代分析。
- **并发场景的空响应问题**（表 11）：8 并发请求时 4/8 返回空响应体，暗示了系统在锁竞争或内存分配上的隐性问题，论文将其归因于"非本工作范围"略显回避——作为系统论文，这属于需要正面解决的问题。

## 10. 论文写作与表达评价

- **优点**：
  - 结构性极强，每章有明确的"问题→方法→验证"链条，读者可快速定位核心贡献；
  - 负面结果（预取预测器失败、任务感知固定失败）被清晰记录，这在系统论文中较少见，提升了可信度；
  - 附录丰富（质量门、长上下文、负载测试），支撑了正文的简洁度；
  - 用"解码时间归因表"（表 5）明确划分了适用/不适用场景，避免了夸大贡献。
- **不足**：
  - 部分公式符号引入过多，如 SO(4) 旋转部分（第 3.2 节）对非读者不友好，双四元数表示对没有图形学背景的 ML 研究者会造成理解障碍；
  - 结果表中的部分数据没有标注置信区间（如表 4 的吞吐量），对运行间方差的讨论仅在表 7 单独给出，未统一整合；
  - 对 Electron 内核（Kernel C）瓶颈的分析停留在"未来工作"，缺乏深入的性能剖析数据（如访存 vs. 计算单元的占用率）。

## 11. 总结性评价

**总体判断**：RotaryQuant 是一篇工程完成度高、实验覆盖面广、结果可信度强的系统论文。其核心价值不在于提出全新的数学工具，而在于 **打通了"算法创新（旋转量化）→ 系统实现（Metal 融合内核）→ 现实部署（MacBook 上运行 120B 模型）"的完整链路**，为消费级硬件上运行超大 MoE 模型提供了切实可行的参照路径。对于关注边缘推理、隐私保护、AI 本地化的研究者和工程师，这篇论文具有较高的参考价值。它的主要不足在于硬件平台单一性、长上下文验证不够系统、以及并发服务能力未解决——但考虑到其定位是"单设备推理"而非"服务端推理"，这些不足属于可接受的边界范围。

**综合评分**：如果要给一个二元整体印象分，可以给出 **8/10**——系统性、透明度、工程创新均达到优秀水准，扣分项集中在上下文验证深度和多硬件泛化验证的缺失。
