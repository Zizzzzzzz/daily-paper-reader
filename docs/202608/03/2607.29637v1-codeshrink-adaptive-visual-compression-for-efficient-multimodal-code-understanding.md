## 摘要
将源代码渲染为图像为降低多模态大语言模型（MLLMs）的输入成本提供了一种有前景的方法。调整图像分辨率可以在视觉令牌成本与内容保真度之间进行权衡。然而，仅调整分辨率忽略了两类低效来源：由换行和缩进产生的空白区域，以及与当前指令无关的代码区域。此外，最佳压缩设置因输入、任务和模型而异，限制了固定比率策略。我们提出了 CodeShrink，一种自适应视觉压缩框架，包含三个组件。无空白渲染用紧凑布局和显式结构标记替代依赖空白的布局，消除了布局引入的令牌。自适应压缩配置使用通过强化学习训练的轻量级代理来预测每个输入的设置，以平衡令牌效率和可读性。主导令牌选择在推理过程中联合分析指令和代码图像，以剪除与任务无关的视觉令牌。我们在代码问答、克隆检测和代码补全上评估了 CodeShrink。CodeShrink 最多可将视觉令牌使用量减少 71.2%，同时匹配或超越未压缩的纯文本输入，并在所有三个任务上持续优于基于文本和视觉压缩的基线。这些结果表明，结合布局压缩、自适应配置和指令感知剪枝可以使多模态代码理解更加高效。我们的代码可在 https://github.com/vinsontang1/CodeShrink 获取。

## Abstract
Rendering source code as images offers a promising way to reduce the input costs of Multimodal Large Language Models (MLLMs). Adjusting image resolution can trade visual token cost against content fidelity. However, resolution scaling alone overlooks two sources of inefficiency: blank regions created by line breaks and indentation, and code regions irrelevant to the current instruction. Moreover, the best compression setting varies across inputs, tasks, and models, limiting fixed-ratio strategies. We propose CodeShrink, an adaptive visual compression framework with three components. Blank-Free Rendering replaces whitespace-dependent layouts with compact layouts and explicit structural markers, removing layout-induced tokens. Adaptive Compression Configuration uses a lightweight agent trained with reinforcement learning to predict a per-input setting that balances token efficiency and readability. Dominant Token Selection jointly analyzes the instruction and code image to prune task-irrelevant visual tokens during inference. We evaluate CodeShrink on code question answering, clone detection, and code completion. CodeShrink reduces visual token use by up to 71.2\% while matching or exceeding uncompressed text-only inputs, and consistently outperforms text-based and visual compression baselines across all three tasks. These results show that combining layout compaction, adaptive configuration, and instruction-aware pruning can make multimodal code understanding more efficient. Our code is available at https://github.com/vinsontang1/CodeShrink.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLMs）在代码智能任务（如代码问答、克隆检测、代码补全、代码生成）中表现优异，但源代码通常包含长上下文、重复语法和稀疏格式，导致 token 消耗成为关键瓶颈。为降低输入成本，已有工作或直接压缩文本 token（如 LLMLingua 系列），或把代码渲染为图像后使用多模态大语言模型（MLLMs）进行处理。
- **核心问题**：以图像形式输入代码时，简单调整分辨率虽然能控制视觉 token 数量，但存在两个被忽视的低效来源：
  1. **空白区域冗余**：换行和缩进在图像中产生大量空白区域，这些区域仍被编码为视觉 token，却不含语义信息；
  2. **任务无关代码冗余**：与当前指令无关的代码区域贡献很小，却消耗了视觉 token。
  3. 此外，**最优压缩设置因输入、任务和模型而异**，固定比例策略无法满足多样化需求。
- **研究意义**：该论文旨在解决 MLLM 代码理解中视觉 token 低效使用的问题，通过自适应视觉压缩，在保证乃至提升任务性能的同时大幅降低计算成本，为多模态代码理解提供更高效的新范式。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

论文提出 **CodeShrink**，一个由三个组件构成的自适应视觉压缩框架：

### 2.1 整体框架
- CodeShrink 先通过**无空白渲染（Blank-Free Rendering, BFR）** 生成高密度代码图像；
- 然后通过**主导令牌选择（Dominant Token Selection, DTS）** 在推理时剪除低信息价值的视觉 token；
- 最后由**自适应压缩配置（Adaptive Compression Configuration, ACC）** 通过强化学习为每个样本预测最优压缩配置。

### 2.2 无空白渲染（BFR）
- **目标**：在固定视觉 token 预算内最大化代码密度，消除由换行、缩进产生的空白区域，将 token 预算集中于语义内容。
- **关键技术**：
  - 结构化线性化：去掉每行空白、删除空行，用 `<INDENT>`、`<DEDENT>` 和可见换行标记来保留二维代码结构；
  - 给定压缩比例 \( r_\delta \) 后，计算目标视觉 token 预算 \( B = \lceil n_s / r_\delta \rceil \)；
  - 通过二分搜索寻找最大可行字体大小 \( f^\star = \max\{ f : \text{PAGES}(T, W, H, f) \le p \} \)，保证页面数量在预算内；
  - 若最小字体仍无法容纳，则提高页面数量并重新迭代；
  - 将图像高度对齐到 patch 网格，去除末尾不满一行的空白 patch 开销。

### 2.3 主导令牌选择（DTS）
- **目标**：在指令与图像信息融合后，识别并保留与任务相关的视觉 token。
- **实现**：
  - 利用边缘和颜色梯度将视觉 token 分为前景代码 token 和背景空白 token；
  - 在浅层 MLLM 层中，用指令最后一个 token 的 query 向量 \( q \) 与每个视觉 token 的 key 向量 \( k_i \) 计算注意力重要性：
    \[
    a_i = \frac{1}{H} \sum_{h=1}^{H} \text{softmax}\left( \frac{q^{(h)} k_i^{(h)\top}}{\sqrt{d}} \right)
    \]
  - 在前景和背景集合内分别排序，剪除最低比例 \( r_\rho^f \)（前景）和 \( r_\rho^b \)（背景）的 token；
  - 剪枝发生在 prefill 阶段，物理删除视觉 token 及其 KV-cache 条目，后续层序列更短，效率更高。

### 2.4 自适应压缩配置（ACC）
- **目标**：为每个样本预测最优的压缩配置 \( a = (r_\delta, r_\rho^f, r_\rho^b) \)。
- **技术实现**：
  - 使用轻量级 MLLM（Qwen3.5-0.8B）作为 Config Agent，仅接收 1× 渲染的首页图像，不承担具体下游任务；
  - 定义离散动作空间 \( \mathcal{A} = \mathcal{R}_\delta \times \mathcal{R}_{\rho_f} \times \mathcal{R}_{\rho_b} \)；
  - 预先枚举所有配置在采样实例上的压缩率 \( C(a) \) 和正确性 \( y(a) \)；
  - **两阶段训练**：
    1. **SFT 预热**：在正确答案配置中选压缩率最大的作为监督标签；
    2. **GRPO 强化学习**：奖励函数为 \( R(a) = \frac{C(a)}{\max_{a'} C(a')} y(a) \)，结合压缩增益与正确性，并加入 KL 散度约束。
  - 训练时对下游 MLLM 进行少量 few-shot 微调以增强 OCR 能力。

## 6. 论文的主要结论与发现

- CodeShrink 在三个代码任务上均取得最优性能，同时大幅压缩视觉 token：
  - Python 代码 QA：准确率 82.3%，超过 Text-only 的 81.0%，token 减少约 40%；
  - Python 克隆检测：准确率 68.0%（F1 65.9%），优于所有基线；
  - Java 克隆检测：token 减少 71.2%，同时准确率 71.0%；
- BFR 渲染相比 vanilla 渲染，在多数模型和分辨率下都能带来一致提升，尤其在长代码和高压缩场景下优势显著；
- 消融实验表明 **ACC 是性能与压缩平衡的关键**，移除后性能和压缩率同时大幅下降；BFR 主要贡献压缩密度；DTS 和 SFT 提供稳定的边际增益；

- 案例研究显示：BFR 将空白覆盖率从 41.9% 降至 1.2%，字体从 22px 增至 32px；DTS 保留的 token 与任务语义需求高度一致；ACC 能选择每个样本的“甜点”压缩比例。
