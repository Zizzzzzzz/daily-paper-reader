## 摘要
现有的多模态大语言模型（MLLM）扩展策略通常要么扩展模型参数，要么扩展顺序推理计算，这会产生大量的内存或延迟开销。更重要的是，大多数现有方法无法改变视觉Transformer与大语言模型组件之间固定且僵化的计算分配，从而限制了特定任务的优化。为了解决这一问题，我们引入了面向MLLM的并行视觉语言（ParVL）扩展框架，该框架通过跨多个视觉和语言分支复用现有的ViT和LLM骨干参数来实现并行计算的扩展。该框架提出了一个核心问题：在给定固定骨干参数预算的情况下，额外的共享骨干计算应如何在视觉和语言模态之间进行分配？我们在共享骨干上为每个并行计算流实例化分支特定的前缀参数，并在约130亿tokens上通过全参数监督微调对整个模型进行端到端训练。我们系统地研究了ViT编码器与LLM解码器之间的计算分配权衡。ParVL在整体多模态性能上优于相同训练配置的单分支基线，且最佳评估的视觉-语言分配因任务而异。代码可在 https://github.com/YangYangGirl/ParVL 获取。

## Abstract
Existing scaling strategies for Multimodal Large Language Models (MLLMs) typically expand either model parameters or sequential inference computation, incurring substantial memory or latency overhead. More importantly, most existing methods fail to alter the rigid, fixed computation allocation between the Vision Transformer and the Large Language Model components, limiting task-specific optimization. To address this, we introduce the Parallel Vision-Language (ParVL) scaling framework for MLLMs, which scales parallel computation by reusing the existing ViT and LLM backbone parameters across multiple vision and language branches. This framework raises a central question: given a fixed backbone parameter budget, how should additional shared-backbone computation be allocated between the vision and language modalities? We instantiate each parallel computational stream with branch-specific prefix parameters over a shared backbone, and train the entire model end-to-end via full-parameter supervised fine-tuning on roughly 13B tokens. We systematically study the computation-allocation trade-off between the ViT encoder and LLM decoder. ParVL improves overall multimodal performance over same-recipe single-branch baselines, and the best evaluated vision--language allocation varies across tasks. Code is available at https://github.com/YangYangGirl/ParVL.

## 论文总结：ParVL——多模态大语言模型的并行扩展与可扩展计算分配

### 1. 论文的核心问题与整体含义

- **研究动机**：现有 MLLM 的扩展策略主要沿两条路径：一是增加模型参数（带来存储与内存成本），二是扩展顺序推理计算（如 CoT、迭代精化，带来延迟开销）。参数复用提供第三条路径——在固定骨干参数预算下通过共享参数在多个并行流上重复使用以增加计算量。
- **MLLM 特有的新问题**：将参数复用扩展引入 MLLM 后，多出一个纯文本领域不存在的问题——额外计算应在视觉（ViT）与语言（LLM）两个模态组件之间如何分配？传统 MLLM 在**设计时**就固定了这种分配（如选择特定规模的 ViT 与 LLM），无法根据任务需求灵活调整。
- **核心含义**：ParVL 框架首次将 MLLM 的计算扩展形式化为**二维视觉-语言分配问题**，在固定骨干参数预算下，通过并行参数复用实现计算的可扩展与可分配，使计算配置能够针对任务需求进行调整。

### 2. 论文提出的方法论

- **整体架构**：ParVL 使用 **Pv 个 ViT 分支**和 **Pl 个 LLM 分支**并行运行。分支间共享全部骨干权重，仅通过分支特定的 Key/Value 前缀（prefix）进行区分。配置记为 `Pv:Pl`（如 2:2 表示 2 个视觉分支 + 2 个语言分支）。
- **前缀条件注意力（Prefix-Conditioned Attention）**：分支 `k` 在每层自注意力中维护可学习前缀 `K_P^(k), V_P^(k)`（长度 Lp），与共享的原始 K/V 拼接后参与注意力计算。查询序列不添加前缀；前缀参数是唯一的**分支特定骨干参数**，参数开销远小于复制整个骨干。
- **分支聚合（Aggregation）**：每个模态使用独立的 token 级两层 SiLU MLP 聚合器。对每个 token，拼接所有分支的特征，预测 softmax 权重，并与均匀分布做插值平滑（λv=0, λℓ=0.1），再对各分支隐藏状态加权求和。聚合后的视觉 token 经过像素重排（InternVL pixel-shuffle）和连接器映射后，**复制**注入每个语言分支；语言输出聚合后再送入共享 LM head。
- **训练目标**：全参数 SFT，加权 next-token prediction loss，使用 `ωb = 1/√nb` 对长序列降权，防止过长回答主导训练。训练数据约 130 亿 tokens。
- **计算分配维度**：对 Pv 和 Pl 在 {1, 2, 4} 范围内变化，覆盖均衡（2:2）、视觉侧重（4:1）、语言侧重（1:4）等 9 种配置。
- **推理优化**：可选稀疏路由（top-1 分支对选择）与 Shared KV 缓存共享机制，用于降低推理延迟与内存。

- **对比方法**：同配方单分支基线（Pv=1, Pl=1）为**受控对照**；InternVL3.5-Instruct、Qwen3-VL-Instruct、Ovis2 等公共模型仅作参考上下文（训练配方不同）。

### 6. 论文的主要结论与发现

- **总体提升**：ParVL 在固定骨干参数预算下通过并行复用提升多模态性能。1B 最佳配置（4:4）将 9-benchmark 平均从 49.6 提至 50.5；2B（2:2）从 54.4 提至 54.7；8B（2:2）从 62.5 提至 63.0。参数增加最多不超过 4%。
- **分配因任务而异**：无单一配置在所有任务上最优。General 峰值在 2:2（41.1），Math 峰值在 4:4（28.0），OCR 峰值在 2:4（76.3）。同一域内不同 benchmark 的偏好也不同（如 MathVision 偏好 1:4，LogicVista 偏好 4:1）。
- **总分支数不能解释性能**：4:4 在 General 上反而低于 2:2，说明视觉-语言间的分配方向比总计算量更重要。
- **增益来源**：与循环语言模型研究类似，参数复用扩展计算有利于**知识操控与推理**（数学、OCR）而非知识存储密集型任务（MMMU 的 General 分数对分配更敏感）。
- **效率特性**：4:4 在 batch size 1 时相对 1:1 仅增加 1.04× 延迟，但内存增至 1.23×；batch size 8 时延迟 1.22×、内存 2.12×；Shared KV 可显著缓解内存增长（2.12×→1.47×），但延迟增加（1.22×→1.62×），精度损失很小（50.5→50.3）。
- **前缀优于 LoRA**：KV 前缀实现并行分支优于 LoRA 实现（总体 50.1 vs 49.8），且更节省计算。

### 7. 优点

- **问题新颖且重要**：首次系统提出并研究 MLLM 中的视觉-语言计算分配问题，填补了参数复用扩展在 MLLM 领域的研究空白。
- **架构简洁高效**：KV 前缀 + 共享骨干 + token 级聚合的设计以极小参数开销（≤4%）实现计算扩展，且视觉与语言计算可在配置层面独立调节。
- **验证充分**：1B 规模的 9 种配置完整网格 + 多种消融，受控对比设计严谨，结论可信度高。
- **效率分析深入**：提供延迟、内存、FLOPs、参数量的系统剖析，并探索稀疏路由与 Shared KV 等推理优化，兼顾实用部署考虑。
- **行文坦诚**：对 oracle 诊断、领域标签局限、数据受限等缺陷有明确交代，未夸大结论。

### 8. 不足与局限

- **规模覆盖有限**：仅在 InternVL3.5 一种骨干系列上验证；2B/8B 仅测试单一配置，未系统探索分配规律随规模的变化。
- **训练数据受限**：1/20 子采样 + 单一数据混合，较少的通用数据可能是 1B 规模 General 分数在部分配置下下降的原因；也尚未验证更大 SFT 预算下的表现。
- **只研究 SFT 阶段**：未涉及预训练阶段的并行扩展，结论的泛化性有限。
- **统计稳健性**：每配置仅一次运行，无 seed 方差报告；解码输出长度的差异在自举检验中包含零，不能确证统计显著。
- **推理开销**：多分支 KV 缓存导致内存增长明显（batch size 8 时为 2.12×），Shared KV 为近似实现而非等价变换，带来一定精度损失（MathVision -3.0）。
- **部署验证不足**：作者自认路由器等机制尚需真实请求场景下的延迟评估、校准测试与更多检查点验证。
