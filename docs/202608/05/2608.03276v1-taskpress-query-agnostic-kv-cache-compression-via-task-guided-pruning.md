## 摘要
大型语言模型的长上下文推理受到键值缓存随序列长度线性增长的制约。虽然剪枝可以提供缓解，但现有方法通常确定查询特定的令牌重要性，无法在未见过的查询中重用。为此，我们引入了TaskPress，一个用于任务引导、查询无关的KV缓存淘汰框架。TaskPress不是为单个查询优化缓存，而是基于高层任务指南构建可重用的内存表示。该指南在预填充阶段充当元查询，在下游查询发出之前过滤不相关的令牌。此外，TaskPress利用量化尺度因子作为检测有影响力的表征离群值的零成本信号，为令牌重要性提供高效代理。在长上下文输入的各种任务上进行的实验表明，TaskPress能够高效地为不同查询创建紧凑、可重用的缓存。

## Abstract
Long-context inference with large language models is constrained by the linear growth of the key-value cache to sequence length. While pruning offers mitigation, prevailing methods determine query-specific token importance that cannot be reused across unseen queries. In contrast, we introduce TaskPress, a framework for task-guided, query-agnostic KV cache eviction. Instead of optimizing the cache for a single query, TaskPress constructs a reusable memory representation conditioned on a high-level task guide. The guide functions as a meta-query during prefill to filter irrelevant tokens before downstream queries are issued. In addition, TaskPress leverages quantization scale factors as a zero-cost signal for detecting influential representation outliers, providing an efficient proxy for token importance. Experiments on conducted on various tasks with long context input demonstrate that TaskPress efficiently creates a compact, reusable cache across diverse queries.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLM）在长上下文推理中，键值（KV）缓存随序列长度线性增长，导致显存开销远超模型权重，成为部署与吞吐的瓶颈。
- **现有方案的不足**：
  - **查询依赖剪枝**（如 SnapKV、PyramidKV、Quest）：根据具体查询动态计算 token 重要性，压缩后的缓存无法复用于新的查询，在多轮或多查询场景中造成重复预填充计算。
  - **上下文重建方法**（如 KVZip）：虽然支持多查询，但预填充阶段需将提示词长度加倍，带来约 O(L²) 的二次计算开销。
- **本文核心思想**：从“查询时压缩”转向“任务时压缩”，利用高层任务指南（Task Guide）作为“元查询”（meta-query），构建**查询无关（query-agnostic）**、可复用的 KV 缓存，在保持性能的同时显著降低推理内存与延迟。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 整体框架
TaskPress 在预填充阶段将任务指南（长度 Lt）附加到上下文（长度 Lc）之后，利用任务指南与上下文的注意力分数，结合量化尺度因子，对每个头的 KV token 进行重要性评分，保留得分最高的 I 个 token，随后丢弃任务指南对应的 KV，得到一个可复用的压缩缓存。

### 2.2 任务引导的 Key 重要性（Task-Guided Key Importance）
- 设任务指南与上下文之间的注意力矩阵为 A ∈ R^{Lt×Lc}，其中 A_{j,i} 表示任务 token j 对上下文 token i 的注意力权重。
- 沿任务维度聚合，并采用 1D 平均池化（核大小 K）捕获局部依赖：
  \[
  s^{\text{key}}_i = \frac{1}{K} \sum_{k=-\lfloor K/2 \rfloor}^{\lfloor K/2 \rfloor} \sum_{j=1}^{L_t} A_{j, i+k}
  \]
- 该分数仅衡量 Key 的重要性，反映 token 在任务引导的注意力空间中的可检索性。

### 2.3 量化尺度作为 Value 重要性（Quantization Scale as Value Importance）
- 自注意力是注意力权重与 Value 的加权和，Value 的幅度同样重要。
- 采用 per-token 量化时，尺度因子定义为：
  \[
  \gamma_i = \frac{\max(|v_i|)}{2^{b-1} - 1}
  \]
  由于 bit-width b 为常数，γ_i 正比于 Value 向量最大绝对值，可作为异常值（outlier）分数。
- 该信号在量化推理管线中**零成本**获得（量化尺度因子已存在），无需额外计算。

### 2.4 KV 重要性评分
- 最终保留分数为 Key 分数与 Value 分数的乘积：
  \[
  s_i = s^{\text{key}}_i \cdot s^{\text{value}}_i
  \]
- 乘性交互要求 token 同时满足“结构与任务语义对齐（高 Key 分数）”和“语义信息丰富（高 Value 分数）”，两者缺一不可。

### 2.5 任务指南的构造
- **零样本初始化**：对已知任务，使用现成 LLM（如 Gemini）根据模板“Generate a task guidance for {task} in 2–3 sentences.”生成初始任务指南，直接作为强基线。
- **进化式发现**（Algorithm 1）：对未知或动态任务，从校准集 D_cal 中采样查询，用 LLM 变异器生成初始候选池；每代评估各候选在 D_cal 上的下游任务准确率，保留 Top-K，再通过变异（mutation）与交叉（crossover）生成新候选；迭代 G 代后返回最优任务指南 T*。

## 6. 论文的主要结论与发现

1. **查询无关压缩可行且高效**：TaskPress 通过任务指南作为元查询，实现了 KV 缓存的跨查询复用，打破了查询依赖方法在多轮场景中的内存-延迟权衡。
2. **零样本任务指南已是强基线**：在 LongBench 上，即使不经过任何优化，TaskPress 在 50% 和 75% 淘汰率下均取得最高的平均准确率。
3. **进化任务指南进一步提升性能**：对于未知任务，从查询集合自动推断并迭代优化任务指南，能在多数 QA 任务上超过查询依赖的 SnapKV；对已知任务的零样本指南也有正向提升。
4. **量化尺度因子是有效的 Value 重要性代理**：与 Value 范数的 Pearson 相关系数为 0.79±0.10，与注意力分数几乎正交（0.06±0.23），两者组合能提升准确率。
5. **效率收益显著**：75% 淘汰率下 TPOT 降低 35%，吞吐量提升 53%；预填充 TTFT 仅增加 1.2%（64-token 指南），峰值显存下降约 15%；多查询场景下相较查询依赖方法最多节省数十秒端到端延迟。
6. **与通道剪枝互补**：TaskPress 与 ThinK 结合（各 50% 淘汰）在 LongBench 上达到最佳性能。

## 7. 优点

- **概念清晰且实用**：将 KV 剪枝从“查询时”解耦到“任务时”，切中多查询/多轮部署的实际需求。

- **任务指南构造灵活**：既支持已知任务的零样本生成，也支持未知任务的进化搜索，适应不同部署场景。
- **实验全面**：覆盖多种基准、多种模型、多种淘汰率，包含效率与消融分析，验证充分。

## 8. 不足与局限

- **任务范围依赖**：压缩缓存针对任务指南定义的语义范围优化，若用户查询大幅偏离预期任务，检索上下文可能不足，性能不如全缓存基线。
- **高密度信息场景脆弱**：在 RULER MK-2/MK-3 等“needle inside needles”人工密集环境中，注意力被大量相似目标分散，导致关键 token 得分低于背景噪声，缓存被错误淘汰。论文承认此类极端密度在真实数据中不常见。
- **依赖量化统计**：默认假设推理管线已做量化；在全精度（FP16/BF16）下需要显式计算 per-token max，虽开销较小（约 0.26 秒 / 64K），但并非完全零成本。
- **进化指南需要校准集**：未知任务场景需要收集一小批真实查询用于进化搜索，实际部署中可能并不总能获得。
- **外部模型依赖**：零样本任务指南依赖现成 LLM（如 Gemini）生成，可能受其知识范围与生成质量影响；论文实验表明鲁棒性较强，但未做更系统的大规模稳定性验证。
