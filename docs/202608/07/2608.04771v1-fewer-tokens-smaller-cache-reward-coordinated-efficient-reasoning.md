## 摘要
大型推理模型（LRM）通过长思维链（CoT）推理在复杂任务上表现出色，但其冗长的中间步骤会导致严重的过度思考，从而推高推理成本。KV缓存压缩是一种常见解决方案，然而现有的面向推理的方法在整个轨迹上应用统一策略，并且仅根据从缓存中移除的内容来判断压缩效果。两个观察结果指向了另一个方向。首先，推理状态对上下文丢失的容忍度沿轨迹变化，过程奖励能够追踪这一点：在高奖励步骤删除令牌比随机删除相同预算更能保持准确性。其次，压缩在生成侧并非免费，因为较小的缓存会导致模型生成更多令牌，部分抵消了节省。这两点共同促使在单一过程奖励下协调两侧。我们提出了ReCo（奖励协调压缩），这是一个逐步框架，其中轻量级过程奖励估计器对每个已完成步骤进行评分，并驱动三个组成部分：（1）奖励自适应KV缓存压缩，在高奖励步骤更积极地缩减保留缓存，在低奖励步骤较少缩减；（2）对反思令牌的奖励分段惩罚，以抑制冗余生成；（3）基于置信度的提前停止，在推理可靠时触发。在三种推理模型和六个基准上，ReCo相比完整CoT将生成令牌减少了37%-65%，端到端延迟降低了2.08倍-2.35倍，同时基本保持了准确性。

## Abstract
Large Reasoning Models (LRMs) excel on complex tasks through long chain-of-thought (CoT) reasoning, but their lengthy intermediate steps cause severe overthinking that inflates inference cost. KV-cache compression is a common solution, yet existing reasoning-oriented methods apply a uniform policy across the trajectory and judge compression only by what it removes from the cache. Two observations point the other way. First, a reasoning state's tolerance to context loss varies along the trajectory, and process reward tracks it: deleting tokens at high-reward steps preserves accuracy far better than deleting the same budget at random. Second, compression is not free on the generation side, since a smaller cache leads the model to generate more tokens, partly canceling the saving. Together these motivate coordinating both sides under a single process reward. We propose ReCo (Reward-Coordinated Compression), a step-wise framework in which a lightweight process-reward estimator scores each completed step and drives three components: (1) reward-adaptive KV-cache compression that shrinks the retained cache harder at high-reward steps and less at low-reward ones, (2) a reward-banded penalty on reflection tokens that curbs redundant generation, and (3) confidence-based early stopping that triggers when the reasoning is reliable. Across three reasoning models and six benchmarks, ReCo reduces generated tokens by 37%-65% and end-to-end latency by 2.08x-2.35x over Full CoT, all while largely preserving accuracy.

## 论文核心问题与整体含义（动机与背景）

大型推理模型（LRM）依赖长思维链（CoT）在复杂任务上表现出色，但冗长的推理步骤导致严重的**过度思考（overthinking）** 问题，推高了推理成本，主要体现在三方面：

1. **令牌开销**：模型即使面对简单输入也会生成过长的推理链，产生大量冗余 token。
2. **KV 缓存膨胀**：推理过程中，KV 缓存随模型自身生成的思维链不断增长，占据大量显存，并推高逐 token 注意力计算成本。
3. **现有压缩方法忽视两个关键现象**：
   - **压缩容忍度因推理步骤而异**：高过程奖励（process reward）的步骤处于"已上正轨"状态，删减上下文对准确性影响小；低奖励步骤仍在探索，上下文更脆弱，删减更易破坏推理链。但现有方法（如 SnapKV、R-KV、RPC）对整个推理轨迹采用**统一压缩策略**，无视步骤差异。
   - **压缩会引发生成变长**：压缩缓存后，模型反而会生成更多 token（实验显示 25% 压缩率下，最多有 79.8% 的问题输出变长），部分甚至完全抵消压缩带来的收益。因此 KV 压缩不能仅看作缓存管理问题，须与生成长度控制联合考虑。

据此提出 **ReCo（Reward-Coordinated Compression）**，在统一的过程奖励信号下同时调控 KV 缓存压缩、反思 token 惩罚和提前停止，从而兼顾压缩效率与生成长度。

## 方法论

### 核心思想

ReCo 以**推理步骤（step）** 为粒度进行控制，核心链路为：

> 生成一个推理步骤 → 用 30M 轻量过程奖励模型 Pilot 为该步打分 → 用该分数同时驱动三个组件（KV 压缩、反思抑制、提前停止）。

### 关键技术细节

#### 1. 步骤划分与奖励信号
- 以换行符 `\n` 将推理轨迹 `C` 切分为步骤序列 `{c₁, …, c_T}`。
- 每完成一步 `cᵢ`，用 **Pilot**（30M 参数，从 Skywork-o1-Open-PRM-7B 蒸馏得到的紧凑过程奖励模型）为当前轨迹打分：`vᵢ = Pilot(c_≤i)`，分值 ∈ [0,1]。

#### 2. 奖励自适应 KV 压缩（Reward-Adaptive KV Compression）
- 当缓存新增 S 个 token 时触发压缩，将当前缓存长度 L 压缩至 `mᵢ = λᵢL`。
- **保留比例**由最新步骤奖励动态决定，公式为：

```
λᵢ = λ_base − δ · (vᵢ − v̄) / (v_max − v_min)
```
其中 λ_base 为基础保留比，δ 限定调整幅度，v̄/v_max/v_min 为当前轨迹内奖励的均值/最大/最小值。归一化后，λᵢ 反映步骤在轨迹内的相对优劣：**高分步骤压缩更狠，低分步骤保留更多上下文**。
- **选哪些 token 保留**：由注意力分数决定——只保留最近 w 个 token（query window）注意力最高的条目，最新 w 个 token 始终保留。
- 分工明确：**奖励决定压缩多少，注意力决定压缩哪些**。

#### 3. 奖励自适应生成控制（Reward-Adaptive Generation Control）
- **反思 token 分段惩罚（Reward-banded reflection penalty）**：维护一个反思类 token 集合 R（如 "Wait"、"Hmm"、"Alternatively"），按奖励值分三个区间施加不同强度惩罚：

```
βᵢ = 0       当 vᵢ ≤ τ_low
βᵢ = β/2     当 τ_low < vᵢ < τ_high
βᵢ = β       当 vᵢ ≥ τ_high
```

生成第 i+1 步时，从 R 中 token 的 logit 中减去 βᵢ 再采样，即 `z̃_t(u) = z_t(u) − βᵢ`。低奖励步骤自由探索，高奖励步骤被强烈抑制反思分支，促使模型收敛。纯 logits 操作，不增加额外前向开销。
- **基于答案置信度的早停（Early stopping）**：奖励连续两步落在高分段（≥ τ_high）后，插入结束思考提示（"Okay, I think I have finished thinking."）退出思考阶段，生成试探性答案 `a`，计算其困惑度：

```
PPL(a) = exp(−(1/n) Σ log p(x_t | x_<t))
```

当 `PPL(a) ≤ τ_p` 时停止并提交答案；否则丢弃试探答案、继续推理。**奖励负责判断轨迹是否健康，困惑度负责判断答案置信度**，二者互补，可抑制"流畅但错误"的提前终止。

## 主要结论与发现

1. **准确性**：ReCo 是压缩方法中精度保持最好的。平均准确率 Llama-8B 为 60.2% vs Full CoT 62.8%（差距 2.6 个百分点），Qwen-7B 为 60.0% vs 61.9%，Qwen3-8B 为 69.6% vs 72.3%。在 AIME25 上，ReCo 保持 33.3%，而全部 KV 基线跌至 ≤20%。
2. **Token 效率**：ReCo 相比 Full CoT 生成 token 减少 37%–65%（Llama-8B 37%、Qwen-7B 65%、Qwen3-8B 46%）。对比之下，纯缓存方法（SnapKV、R-KV、RPC）反而增加了 token 数，印证了"缓存压缩引发生成变长"的观察。
3. **延迟**：端到端加速 2.08×–2.35×（Llama-8B 2.08×、Qwen-7B 2.35×、Qwen3-8B 2.18×），显著优于纯缓存方法（仅 1.09×–1.33×）。长度控制基线（SAT、Dynasor）达到相近延迟但以牺牲精度为代价。
4. **显存**：峰值内存低至 17.92 GB（AIME25/Llama-8B），较 Full CoT（28.78 GB）降低 37.7%，也低于 R-KV（20.70 GB）。
5. **组件互补性**：完整 ReCo 在所有指标上优于任一单独组件，验证了"缓存侧 + 生成侧联合控制"的必要性。
6. **超参敏感性**：λ 过低（15%）导致精度下降且 token 膨胀（与长度膨胀现象一致）；δ=0（统一策略）效果最差；τ_p 过松时准确率显著下滑。选用 λ=0.25、δ=0.10、τ_p=1.10 在所有模型和数据集上无需逐任务调参，表现稳健。

## 优点

1. **视角新颖且具有说服力**：从"高奖励步骤容忍压缩"和"压缩会引发生成长度膨胀"两个实证观察出发，论证了 KV 压缩与生成控制需要联合优化，而非各自独立处理。两则观察均有实验数据支撑，逻辑自洽。
2. **单一信号统一驱动多个模块**：一个 30M 的轻量奖励模型同时驱动缓存压缩、反思惩罚和早停三组件，设计简洁，模块间天然一致，避免了多个独立信号之间的冲突。
3. **开销极低**：Pilot 打分 + 压缩 + 惩罚 + 早停合计不到端到端时间的 4%；无模型训练、无 prompt 工程，即插即用，应用门槛低于需要微调推理模型的方法。
4. **公平的基线设置**：KV 基线统一压缩比、长度基线统一加速水平，使对比结果可信；三次独立运行取平均提升了稳健性。
5. **消融与敏感性分析完善**：逐组件消融和三个关键超参的扫描，帮助读者清晰理解各模块贡献与参数选择依据。

## 不足与局限

1. **对过程奖励质量存在依赖**：整个框架建立在 Pilot 的奖励分数可靠地反映"推理路径是否有望走向正确答案"这一前提上。若推理任务超出 Pilot 训练分布（如代码生成、多模态推理），奖励信号失真时各模块可能失效。论文未报告 Pilot 在不同任务上的泛化能力。
2. **实验覆盖范围有限**：数据集集中在数学/科学推理，缺少代码生成、工具调用、agent 式决策等 LRM 常见应用场景；模型规模只有 7B–8B，未扩展到更大规模（如 70B+）或 MoE 结构模型，结论的可扩展性尚待验证。
3. **未报告训练成本细节**：虽避免了推理模型训练，但 Pilot 自身的蒸馏训练成本（GPU 数、时长、数据规模）未披露，完整部署成本无从估算。
4. **若干超参需人工设定**：λ、δ、τ_p、τ_low、τ_high 均为固定手动配置，虽然文中证明在所选范围内鲁棒，但缺乏自适应调节机制，面对新的模型/任务族时可能需要重新搜索。
5. **潜在的偏置风险**：对反思 token 的硬编码惩罚集合和固定 band 划分，可能对不同模型 tokenizer 的覆盖不完整；对"低熵但错误"答案的早停失败案例也缺乏深入的失败模式分析。
6. **硬件验证单一**：所有实验只在单张 H20 上运行，缺少跨硬件（如 A100、L40S、TPU）下的性能与显存数据，工程泛化性未充分验证。
