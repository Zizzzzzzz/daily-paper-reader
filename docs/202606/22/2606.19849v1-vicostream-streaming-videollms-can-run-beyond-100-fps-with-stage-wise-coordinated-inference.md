## 摘要
流式视频大模型必须持续处理传入的视频流，同时保持低查询延迟，因此视频摄入吞吐量和查询时响应性对于实时部署至关重要。现有方法主要聚焦于加速单个模块，例如视觉编码、令牌剪枝或KV缓存压缩，但对于由此产生的系统能否维持实时流式性能提供的见解有限。本文将流式视频大模型推理形式化为一个协调流水线，涵盖视觉预处理、视觉编码、令牌丢弃以及大模型预填充/解码。基于这一公式，我们提出了ViCoStream（视频协调流式处理），一个逐阶段协调的流式框架，结合了分块执行、CUDA流重叠、视觉令牌控制、有界视觉注意力和查询端检索，以限定每块的计算和内存开销。我们进一步对瓶颈迁移进行了系统研究，揭示了块大小、令牌保留、注意力局部性和检索范围如何塑造吞吐量-准确率权衡。在多个流式基准测试中，使用Qwen2.5-VL-3B/7B-Instruct进行的实验表明，ViCoStream在单个A100 GPU上实现了134 FPS的视频吞吐量和小于50毫秒的TTFT，同时保持接近全历史基线的准确率。

## Abstract
Streaming VideoLLMs must continuously process incoming video while maintaining low query latency, making both video-ingestion throughput and query-time responsiveness critical for real-time deployment. Existing methods largely focus on accelerating individual modules, such as visual encoding, token pruning, or KV-cache compression, but provide limited insight into whether the resulting system can sustain real-time streaming performance. We formulate streaming VideoLLM inference as a coordinated pipeline spanning visual preprocessing, visual encoding, token dropping, and LLM prefilling/decoding. Building on this formulation, we propose ViCoStream (Video Coordinated Streaming), a stage-wise coordinated streaming framework that combines chunk-wise execution, CUDA-stream overlap, visual token control, bounded visual attention, and query-side retrieval to bound per-chunk computation and memory costs. We further provide a systematic study of bottleneck migration, revealing how chunk size, token retention, attention locality, and retrieval scope shape the throughput-accuracy trade-off. Experiments with Qwen2.5-VL-3B/7B-Instruct across multiple streaming benchmarks show that ViCoStream achieves 134 FPS video throughput and less than 50 ms TTFT on a single A100 GPU while maintaining accuracy close to full-history baselines.

## 2. 论文提出的方法论

- **核心思想**：将流式VideoLLM推理看作一个多阶段并行流水线，每个阶段处理不同的视频块（chunk），通过阶段级并发（pipelining）使吞吐量由最慢阶段决定，而非各阶段延迟之和。同时为每一阶段引入有界控制，防止随流式长度增长而无限膨胀。

- **关键技术细节**：
  - **分块执行**：将输入视频流划分为固定大小c的非重叠块（chunk），支持批量ViT编码，提升效率。
  - **CUDA流重叠**：视觉预处理（如resize、normalization、patchification）在独立CUDA流上执行，与后续模型阶段重叠，减少串行延迟。
  - **视觉token控制**（时空丢弃）：
    - **空间压缩**（帧内）：采用平均池化、最大池化或熵基选择（保留信息量最大的top-K tokens）。
    - **时间压缩**（块内）：基于帧间相似度——对于每个空间位置，只有所有帧对相似度均超过阈值τ时才丢弃该token；同时保留每块第一帧作为锚点，避免完全丢失时间证据。
  - **有界视觉注意力**：块预填充时，只允许当前块关注最近acn个块（可配置窗口大小），使缓存大小和延迟不随流长度增长。
  - **查询端检索**：用户查询时，计算查询token均值与各块视觉特征均值的余弦相似度，仅选择top-k个块作为注意力上下文，限制响应延迟。
  - **自适应训练掩码**：训练时构造与推理时一致的注意力掩码——视觉token只能看到局部窗口，查询token只能看到检索的块，保持训练-推理对齐。

- **公式或算法流程**（文字说明）：
  - 流式输入：`V = {f1, f2, ..., fT}`，分为块`Vt`。
  - 流水线阶段：VP → ViT → Drop → LLM (Pre/Decode)
  - 稳态吞吐量：`T_pipe = max{T_vp, T_vit, T_drop, T_llm}`，`FPS_max = 1000*c / T_pipe`
  - 时间丢弃：相似度`S_{t,i→j}(p)`，当所有对>τ时丢弃该位置token。
  - 注意力掩码：视觉部分为阶梯窗，查询部分为非连续检索集。

## 6. 论文的主要结论与发现

- **主要结论**：
  - ViCoStream在单A100上达到最高134 FPS视频吞吐和<50ms TTFT（适中压缩）。
  - 精度方面：在保持30% token保留（约70%丢弃率）时，多数基准精度下降<3个百分点；在更激进压缩（10%保留）时，部分任务（如OvO-Bench后向追踪、RVS-Movie）下降较大。
  - **瓶颈迁移现象**：当LLM侧开销被控制后，视觉编码和预处理成为新瓶颈；增大块大小可提升FPS但到一定点后ViT/VP延迟反而拖累。
  - 时间丢弃比空间丢弃更安全；空间丢弃需保留语义显著token（熵基优于池化）。
  - 局部注意力窗口（acn=4）效果最优，查询检索窗口（ur=32）后饱和。
  - 有界注意力使长流预填充延迟保持恒定，不随流索引增长。

## 7. 优点

- **系统性框架**：首次将流式VideoLLM推理明确建模为多阶段协调流水线，提供了统一分析吞吐量瓶颈的方法论。
- **阶段级并发**：利用CUDA流重叠和分块并行，突破传统串行逐帧限制。
- **双向注意力控制**：视觉侧局部窗口 + 查询侧检索，兼顾效率与关键信息访问。
- **自适应训练掩码**：确保训练-推理一致性，减少压缩带来的分布偏移。
- **详尽的效率-精度权衡研究**：系统扫描块大小、token保留率、注意力窗口、检索范围等维度，为实际部署提供可操作指导。
- **高吞吐/低延迟实证**：实现134 FPS和<50ms TTFT，验证了框架的有效性。
