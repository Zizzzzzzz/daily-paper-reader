## 摘要
上下文密集型智能体对键值（KV）缓存施加了异常压力：长前缀在多个短轮次中被重复使用，而并发性决定了服务系统能否保持GPU的高利用率。我们针对这一场景研究了4位KV缓存压缩，采用TurboQuant风格的旋转和码本量化作为质量锚点，vLLM FP8 KV缓存作为部署锚点。我们报告了三项贡献。首先，我们将4位KV缓存置于多轮智能体工作负载的框架中，其中任务质量、缓存驻留和服务吞吐量必须联合衡量。其次，我们描述了使4位路径稳健所需的实际设计选择，包括非对称K/V处理、Walsh-Hadamard旋转、QJL去除和块级缩放变体。第三，我们展示了在AMD GPU上的服务优化，包括优化的解码注意力内核和UltraQuant——一种使用FP8查询、FP4 KV张量、UE8M0组缩放以及CDNA4上原生缩放MFMA支持的FP4近似路径。在长上下文、多轮智能体工作负载上，UltraQuant在缓存压力大的后期轮次中将P50首令牌时间降低了3.47倍（所有轮次平均降低2.3倍），并将输出吞吐量比FP8 KV基线提高了1.63倍。

## Abstract
Context-heavy agents place unusual pressure on the key-value (KV) cache: long prefixes are reused across many short turns, while concurrency determines whether the serving system can keep GPUs utilized. We study 4-bit KV-cache compression for this setting, using TurboQuant-style rotation and codebook quantization as a quality anchor and vLLM FP8 KV caching as the deployment anchor. We report three contributions. First, we frame 4-bit KV caching around multi-round agent workloads where task quality, cache residency, and serving throughput must be measured jointly. Second, we describe the practical design choices needed to make the 4-bit path robust, including asymmetric K/V treatment, Walsh-Hadamard rotation, QJL removal, and block-scale variants. Third, we present serving optimizations on AMD GPUs, including optimized decode-attention kernels and UltraQuant, an FP4 approximation path that uses FP8 queries, FP4 KV tensors, UE8M0 group scales, and native scaled-MFMA support on CDNA4. On a long-context, multi-turn agentic workload, UltraQuant cuts P50 time-to-first-token by 3.47x in the cache-pressured late rounds (2.3x across all rounds) and raises output throughput by 1.63x over the FP8 KV baseline.

# 论文总结：UltraQuant: 4-bit KV Caching for Context-Heavy Agents

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **问题背景**：大语言模型（LLM）正从短对话演变为具有长上下文代理（agent）的应用，如网页浏览、代码仓库检查、工具调用等。这类“上下文密集型智能体”对键值（KV）缓存施加了异常压力：长前缀被多个短轮次重复使用，同时高并发要求使GPU利用率成为关键。随着上下文窗口扩展到百万token级别，KV缓存线性增长，成为高带宽内存（HBM）的主要消费者。
- **研究动机**：现有KV缓存压缩方法（如FP8量化）虽然能提供约2倍压缩且接近无损，但对于4位量化而言，需要同时保持任务质量、缓存驻留（避免重复预填充）和服务吞吐量。然而，高精度压缩（如TurboQuant的码本方法）往往引入软件反量化开销，影响端到端服务性能。因此，需要一种既能在任务质量上接近无损，又能原生硬件加速的4位KV缓存方案。
- **整体目标**：本文提出一种以部署为导向的2位KV缓存研究，针对上下文密集型智能体工作负载，联合衡量任务质量、缓存驻留和吞吐量，并设计了两种实现：Ultra-TQ（基于优化码本）和UltraQuant（基于FP4微张量近似），旨在让4位KV缓存达到接近硬件原生FP8的可部署性。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- 通过**旋转（Walsh-Hadamard变换）**打散异常值能量，使KV缓存分布接近高斯分布，利于小比特量化。
- 采用**非对称K/V处理**：Keys旋转后量化，Values不旋转直接量化（因为值误差影响方式不同）。
- **块缩放**：每组32个通道使用一个UE8M0指数缩放，实现自缩放，避免每token归一化。
- **FP4微张量近似**：用硬件原生FP4 E2M1网格替换可校准码本，将反量化融合到CDNA4的缩放MFMA指令中。

### 关键技术细节
1. **TurboQuant风格旋转+码本（Ultra-TQ）**：
   - Keys经Walsh-Hadamard旋转，每token归一化（L2范数），然后对旋转后向量使用Lloyd-Max可校准16级码本量化。
   - Values使用均匀4位量化（对称INT4）+每组缩放和零点。
   - 反量化通过查表（LUT）实现，在解码注意内核中实时完成。
   - 改进：对10%的高均方误差层进行模型特定质心校准，降低K量化MSE 10.3%。

2. **UltraQuant（FP4近似路径）**：
   - **缓存布局**：Keys和Values存储为FP4 E2M1（每元素4位），每组32通道共享一个UE8M0指数缩放。布局：32×4 bits + 8 bits = 17字节每32通道，约4.25比特/元素。
   - **编码**：
     - Keys经旋转，直接分组，每组的缩放因子 \( s = c \cdot m \)，其中 \( m \) 为组内绝对最大值，\( c \) 为全局常数（优化为0.156）。
     - 指数 \( E = \text{round}(\log_2(c \cdot m)) \)，存储为UE8M0字节（8位无符号）。
     - 每个元素量化到FP4网格的最近码点 \( q(x_i / 2^E) \)。
   - **解码反量化**：\( \hat{x} = \text{code} \times 2^{E-127} \)，直接通过缩放MFMA指令转化为BF16，无需软件查表。
   - **注意计算**：查询向量也经旋转并舍入为FP8 E4M3，通过缩放FP8×FP4 MFMA计算QK和PV。

3. **服务优化**：
   - Ultra-TQ内核优化：GQA感知分块、结构体数组布局、AMD特定MFMA调度（Triton, 本地ISA, FlyDSL JIT）。
   - UltraQuant内核：直接使用CDNA4的 `v_mfma_scale_f32_16x16x128_f8f6f4` 指令，FP8查询提升到K-tile外循环，减少冗余打包。
   - 边界层保护：前两层和后两层注意力保留BF16 KV缓存。

## 6. 论文的主要结论与发现

1. **UltraQuant在服务性能上显著优于FP8 KV缓存**：在缓存压力大的多轮agent工作负载中，后期轮次P50 TTFT降低3.47倍，全局降低2.3倍；输出吞吐提升1.63倍。优势来源于更紧凑缓存使更多前缀驻留在HBM，避免重复预填充。
2. **UltraQuant的FP4近似路径接近硬件FP8的吞吐量**：UltraQuant相对BF16输出吞吐为1.38×，而FP8为1.37×，两者几乎持平，但UltraQuant使用一半的缓存字节。
3. **质量结果任务依赖**：UltraQuant在GPQA和MATH500上接近或略优于BF16，但在AIME25上有10-13个百分点的下降。作者把这一回归视为真实局限，而非平均掩盖。
4. **块缩放比码本更关键**：消融表明，使用每块绝对最大值（absmax）缩放恢复准确率，而码本（Lloyd vs uniform）在块缩放存在时影响不明显。这证明了UltraQuant设计中选择FP4网格+块缩放的有效性。
5. **全局常数优化对质量重要性**：常数c=0.156（MSE最优）使准确率超过FP8基线4.4pp；错误常数导致质量下降甚至低于FP8。
6. **旋转不可被码本替代**：即使在未旋转分布上拟合码本，MSE仍比旋转后的高2.3倍。
7. **硬件原生格式的优势**：当硬件支持FP4微张量直接MFMA时，略微次优的网格（相对于Lloyd-Max）可获得服务性能提升，端到端服务最优可能偏向硬件原生格式。

## 7. 优点

- **端到端服务视角**：将任务质量、缓存驻留、吞吐量联合评估，而非仅离线压缩指标。
- **清晰的部署导向设计**：从高质量码本（TurboQuant）出发，逐步简化至硬件原生FP4路径，同时保留大部分质量收益。
- **详尽消融**：分离了每块缩放vs码本、全局常数vs残差等，证明了关键设计因素。
- **解决真实系统瓶颈**：码本反量化的不规则内存访问被识别为解码瓶颈，FP4路径将其折叠入MFMA。
- **开源化**：Ultra-TQ和UltraQuant以优化的vLLM内核实现，社区可复现。
- **诚实报告局限性**：主动披露AIME25上的显著降维，以及c=0.156不仅是MSE最优也是准确率最优的事实。

## 8. 不足与局限

- **质量回归不均衡**：AIME25任务下降10-13个百分点，这对于数学推理可能导致实际应用不可接受。论文未提供误差分析或尝试缓解（如混合精度恢复部分层）。
