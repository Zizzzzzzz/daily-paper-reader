## 摘要
多智能体大语言模型（LLM）应用通常以同步轮次的方式组织执行，由中央调度器收集所有智能体的输出并重新分发合并后的上下文。这种全收集（All-Gather）通信模式产生了海量的 KV 缓存冗余，因为每个智能体的提示词都包含相同的共享输出块，而现有的重用方法无法高效地利用这一特性。我们提出了 TokenDance，该系统通过利用全收集模式进行集合式 KV 缓存共享，从而扩展了并发智能体的规模。TokenDance 的 KV 收集器（KV Collector）通过单个集合步骤完成整个轮次的 KV 缓存重用，使得无论智能体数量多少，重用共享块的开销仅需支付一次。其差异感知存储（Diff-Aware Storage）将兄弟缓存编码为相对于单个主副本的块稀疏差异，在代表性工作负载上实现了 11-17 倍的压缩。在 GenerativeAgents 和 AgentSociety 上的评估表明，在满足服务水平目标（SLO）要求的前提下，TokenDance 支持的并发智能体数量比带有前缀缓存的 vLLM 高出 2.7 倍，将单个智能体的 KV 缓存存储降低了多达 17.5 倍，并比针对单个请求的位置无关缓存实现了高达 1.9 倍的预填充加速。

## Abstract
Multi-agent LLM applications organize execution in synchronized rounds where a central scheduler gathers outputs from all agents and redistributes the combined context. This All-Gather communication pattern creates massive KV Cache redundancy, because every agent's prompt contains the same shared output blocks, yet existing reuse methods fail to exploit it efficiently. We present TokenDance, a system that scales the number of concurrent agents by exploiting the All-Gather pattern for collective KV Cache sharing. TokenDance's KV Collector performs KV Cache reuse over the full round in one collective step, so the cost of reusing a shared block is paid once regardless of agent count. Its Diff-Aware Storage encodes sibling caches as block-sparse diffs against a single master copy, achieving 11-17x compression on representative workloads. Evaluation on GenerativeAgents and AgentSociety shows that TokenDance supports up to 2.7x more concurrent agents than vLLM with prefix caching under SLO requirement, reduces per-agent KV Cache storage by up to 17.5x, and achieves up to 1.9x prefill speedup over per-request position-independent caching.

### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：在多智能体（Multi-Agent）LLM应用中，GPU显存是限制并发智能体规模的主要瓶颈。
*   **研究背景**：多智能体框架（如社交模拟、协作编码）通常遵循 **All-Gather（全收集）模式**：每一轮对话中，调度器收集所有智能体的输出，并将其合并后分发给每个智能体作为下一轮的上下文。
*   **痛点**：由于每个智能体有自己的私有历史（长度不同），相同的共享输出块在不同智能体的 Prompt 中处于不同的绝对位置。现有的前缀缓存（Prefix Caching）因位置偏移失效，而位置无关缓存（PIC）则需对每个请求重复计算，导致严重的计算和存储冗余。

### 2. 方法论：核心思想与关键技术
TokenDance 的核心思想是将优化粒度从“单个请求”提升到“多智能体轮次”，实现“一次计算，集体共享”。
*   **轮次感知提示词接口（Round-Aware Prompt Interface）**：在 Prompt 的逻辑块之间插入分隔符（如 `<TTSEP>`），使运行时能识别块边界，并采用基于段（Segment）的哈希索引而非绝对位置索引。
*   **集合式 KV 缓存重用（Collective KV Cache Reuse）**：
    *   **分组处理**：将同一轮次中兼容的请求分组。
    *   **摊销计算**：对组内所有请求执行单次批处理 RoPE 旋转和重要位置选择（Important-position selection），将重用分析的开销从 $O(N)$ 降至 $O(1)$。
*   **差异感知存储（Diff-Aware Storage）**：
    *   **主从布局（Master-Mirror Layout）**：仅存储一个完整的“主（Master）”缓存，其余智能体的缓存仅存储相对于主副本的“镜像（Mirror）”差异。
    *   **块稀疏差异编码**：利用 KV 缓存高度相似的特性，仅记录发生变化的块（通常仅占 10-20%）。
*   **融合差异恢复（Fused Diff Restore）**：在 GPU 传输流水线中直接应用稀疏补丁，避免了先重建完整缓存再读取的额外显存往返开销。

### 3. 实验设计
*   **数据集/场景**：使用了两个代表性的多智能体社交模拟框架：**GenerativeAgents**（斯坦福小镇）和 **AgentSociety**。
*   **Benchmark 模型**：Qwen2.5-7B 和 Qwen2.5-14B。
*   **对比方法**：
    1.  **vLLM (Prefix Caching)**：标准的前缀重用方法。
    2.  **CacheBlend (Ordinary Path)**：带 CPU 缓存池但不具备跨前缀重用能力。
    3.  **CacheBlend (Full PIC)**：最先进的针对单个请求的位置无关缓存重用方法。

### 4. 资源与算力
*   **硬件环境**：实验主要在 **NVIDIA A100 80GB GPU** 上进行。

*   **训练时长**：该论文侧重于推理服务系统优化，不涉及模型训练，因此未提及训练时长。

### 5. 实验数量与充分性
*   **实验规模**：
    *   测试了不同智能体数量（1 到 20 个）和不同请求频率（QPS 1 到 16）。
    *   涵盖了端到端延迟、系统容量（SLO 下的最大智能体数）、预填充加速比、存储压缩率、恢复延迟以及模型输出准确性（Fidelity）等多个维度。
*   **充分性评价**：实验设计较为充分且客观。通过对比不同规模的模型（7B vs 14B）证明了该方法在参数量更大时收益更高；通过准确性实验验证了系统优化未损害模型逻辑。

### 6. 主要结论与发现
*   **容量提升**：在满足延迟 SLO 的前提下，TokenDance 支持的并发智能体数量比 vLLM 提升了 **2.7 倍**。
*   **存储压缩**：在 14B 模型上实现了 **17.5 倍** 的单智能体存储缩减，KV 缓存存储开销降低了 **94%**。
*   **性能加速**：预填充阶段相比 PIC 方法实现高达 **1.9 倍** 的加速，集体重用峰值加速达 **2.57 倍**。
*   **模型扩展性**：模型越大，KV 缓存冗余越严重，TokenDance 的优势越明显。

### 7. 优点
*   **架构创新**：首次提出了针对多智能体 All-Gather 通信模式的系统级优化，填补了多智能体推理服务的空白。
*   **计算存储双优化**：不仅通过集合计算减少了预填充延迟，还通过差异存储极大地缓解了显存压力。
*   **无缝集成**：设计的接口简单，现有框架只需少量修改即可接入，且不影响模型输出的准确性。

### 8. 不足与局限
*   **模式依赖**：高度依赖于 All-Gather 这种同步通信模式。如果智能体之间的交互是高度异步或个性化（每个智能体接收完全不同的信息），则压缩率和重用率会显著下降。
*   **硬件绑定**：部分核心优化（如 Fused Restore）依赖于特定的 CUDA 内核实现，跨硬件平台的迁移可能需要额外开发。
*   **精度风险**：虽然实验显示影响较小，但底层 PIC 技术（如 CacheBlend）涉及选择性重计算，在极少数对数值精度极其敏感的任务中可能导致逻辑漂移。
