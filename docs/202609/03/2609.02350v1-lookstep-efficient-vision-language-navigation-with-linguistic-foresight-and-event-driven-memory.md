## 摘要
视觉语言导航（VLN）要求具身智能体在未知环境中遵循自然语言指令。最近的进展主要由多模态大语言模型（MLLMs）推动。现有方法遵循下一步动作预测范式，仅监督专家动作，这需要大量数据进行训练。它们还依赖认知地图、累积的历史帧或外部3D工具来维护状态，导致较高的计算和内存开销。为了实现资源高效的VLN，我们提出了LookStep，一个统一的端到端框架，结合了以语言为中心的未来状态建模和事件驱动滚动记忆，利用语言标签为每个候选动作生成粗粒度的导航进度和未来状态，同时自主决定是否将每个观察以语义角色写入有界滚动记忆。我们在经验上验证了LookStep。在VLN-CE任务中，LookStep在相同训练设置下优于现有方法，在R2R-CE Val-Unseen上取得了49.7%的成功率，同时具有更好的内存效率和更少的数据使用。代码和模型可在https://github.com/kunyang-YU/LookStep获取。

## Abstract
Vision-Language Navigation (VLN) requires an embodied agent to follow natural-language instructions in unseen environments. Recent progress has been largely driven by Multimodal Large Language Models (MLLMs). Existing methods follow a next-step action prediction paradigm, supervising only the expert action, which requires a high quantity of data for training. They also rely on cognitive maps, accumulated historical frames, or external 3D tools to maintain states, leading to high computational and memory overhead. To realize resource efficiency VLN, we propose LookStep, a unified end-to-end framework that combines Language Centric Future State Modeling and Event Driven Rolling Memory that uses language labels to generate coarse-grained navigation progress and future states for each candidate action, while autonomously deciding whether to write each observation into a bounded rolling memory with a semantic role. We validate LookStep empirically. On VLN-CE tasks, LookStep outperforms existing methods under the same training settings, achieving a 49.7\% success rate on R2R-CE Val-Unseen with better memory efficiency and less data usage. Code and model is available at https://github.com/kunyang-YU/LookStep.

- **论文的核心主张**：高效的VLN不应仅仅是状态表示问题，而应通过“数据利用和记忆管理”的协同设计来实现。LookStep旨在提供一种资源友好型（data-efficient、memory-efficient）的统一端到端导航框架。

## 2. 论文提出的方法论：核心思想、关键技术细节与流程

### 2.1 总体框架

- LookStep由两个互补组件构成：
  1. **语言中心未来状态建模（Language Centric Future State Modeling, LFS）**
  2. **事件驱动滚动记忆（Event Driven Rolling Memory, EDRM）**
- 模型在每一步输入指令、当前观察和历史上下文，输出导航进度 \(p_t\)、候选动作未来状态 \(F_t\)、记忆写入决定 \(W_t\)、记忆角色 \(R_t\) 和最终动作 \(a_{t+1}\)。

### 2.2 语言中心未来状态建模（LFS）

- **目标**：将导航训练从动作模仿转化为候选动作后果的显式推理，将轨迹中的隐式监督信号转化为结构化语言标签。
- **具体内容**：
  - 预测当前**粗粒度导航进度**，标签集合为 \(\{\)start, early, middle, late, near_goal\(\}\)；
  - 为每个候选动作（MOVE / TURN_LEFT / TURN_RIGHT / STOP）生成**短期未来状态标签**，标签集合包括 \(\{\)advance, advance_after_turn, advance_to_goal, start_turn, continue_turn, finish_turn, success_stop, too_early, overshoot_goal, wrong_at_goal, premature_forward, wrong_turn, over_turn, reverse_turn, early_left_turn, early_right_turn\(\}\)。
- **标签自动生成**：所有监督标签均基于专家轨迹的确定性规则自动产生，无需额外人工标注。例如：未来K=5步内包含STOP则标记为advance_to_goal；处于连续同向转向段的开始、中间、结尾则分别标记为start_turn / continue_turn / finish_turn；对于专家未执行的反事实动作则按规则构造错误类型标签（如wrong_turn、over_turn、too_early等）。
- **训练方式**：将进度、未来状态、记忆决定/角色、动作拼成一个结构化语言序列，使用标准next-token负对数似然进行统一训练。
- **理论动机**（信息论视角）：
  - 设直接动作预测的贝叶斯最优风险为 \(R^*_{\mathrm{base}} = H(a^*_{t+1} \mid X_t)\)，引入oracle未来状态标签后风险为 \(R^*_{\mathrm{oracle-fsm}} = H(a^*_{t+1} \mid X_t, F^*_t)\)。
  - 二者差值为 \(R^*_{\mathrm{base}} - R^*_{\mathrm{oracle-fsm}} = I(a^*_{t+1}; F^*_t \mid X_t) \ge 0\)。
  - 即oracle未来状态标签只要与动作存在条件互信息，就能降低动作预测的不确定性，为设计结构化候选动作后果语言建模提供了理论支撑。

### 2.3 事件驱动滚动记忆（EDRM）

- **动机**：解决历史观察冗余、关键导航事件丢失、以及静态窗口或启发式采样导致的信息质量不足问题。
- **核心机制**：
  - 模型在每一步自主解析当前观察是否为“导航关键事件”，并输出是否写入记忆的标签（keep/drop）和该观察在导航过程中的语义角色标签。
  - 记忆角色标签包括 \(\{\)stop_evidence, start_view, turn_start, turn_end, post_turn_alignment, goal_approach, recent_only\(\}\)。
  - 当记忆超过容量后以**FIFO**方式淘汰最旧条目，从而实现轻量级的有界滚动记忆。
- **关键点**：记忆选择被内化为模型自身的生成行为，而非外部启发式规则。该设计可视为一种“无需参数更新的在线更新（test-time adaptation in memory space）”。

## 7. 优点与亮点

- **创新性强的范式方向**：将辅助监督从单一动作迁移到结构化未来结果预测中，减少了传统“贪婪模仿”可能带来的偏差，实现更强数据利用效率。

## 8. 不足与局限

- **性能上限存在差距**：虽然提出方法是“SOTA under same training settings”，但绝对SR仍低于JanusVLN，在计算条件或精度为优先的场合，该方法未必是更好选择。
- **训练成本并不低**：在8×A100 80GB GPU仍需约1000 GPU小时训练，虽然从累计内存角度看有改进，但对于缺少训练资源的小团队依然不够“高效”。
- **真实场景验证相对有限**：真机成功率为70%，只进行了一次场景实验和30次试次，未在多种办公/家庭环境及多个机器人主体上做泛化验证；真实环境中评测仅以停止距离1m作为标准，没有细化执行时间、轨迹效率等指标。
- **记忆角色和事件识别的局限性**：goal_approach的预测精度仅为43.64%，记忆标签还远未能完美刻画复杂目标语义与空间关系。
- **对遗忘机制的潜在设计过于简单**：FIFO的淘汰规则虽然高效，但可能把非顺序性的关键线索（如返回起点、环形路线）从记忆队列中提前删除，面对复杂重定位轨迹时可能受限。
- **与跨环境泛化相关**：未评测REVERIE、SOON等高频VLN任务，

以及指令中包含明确“目标物体”与空间关系的任务，因此无法判断LookStep的事件驱动记忆和未来状态建模在目标驱动型导航或密集交互式导航中的实际收益。另一方面，效率评估主要聚焦于GPU峰值内存与单步推理耗时，未对完整导航过程的平均交互步数、碰撞率、路径长度波动、CPU内存占用或端到端能耗做更细粒度的报告，而这些指标对真实机器人部署的性价比判断同样重要。

此外，虽然LFS的标签通过专家轨迹规则自动生成，但规则的可靠性依赖于专家轨迹与指令之间的严格对齐。若轨迹中存在低层控制噪声、起始位姿偏差或多段路径目标重叠，自动标签可能引入系统性噪声，模型会学习到某些隐含但非因果的模式；论文没有对标签噪声做鲁棒性分析，也未讨论标签错误率对训练结果的影响。同样，记忆标签的语义类别集中在“转向”“接近目标”等局部事件层面，对长期规划中的“回环修正”“原路返回”等非顺序关系事件尚无对应分类，FIFO淘汰机制也难以保留这类需要跨越时间窗口才能体现的依赖关系。

在领域泛化方面，LookStep的核心实验均来自Matterport3D内部的R2R-CE / RxR-CE划分。虽然文中进行了HM3D-OVON上的开放词表迁移测试，但这类测试属于较简单的零样本目标导航设定，不足以验证模型在真实办公室、诊所、户外园区等具有剧烈光照变化、镜面反射和动态人物场景中的稳健性。真机实验虽然提供了可行的工程验证，但只报告了单场景、单一高度的成功停止率，缺少对路径长度、人工干预次数、暂停/恢复行为或网络故障等部署要素的统计，因此其“真实世界可行性”结论的支撑强度仍有限。

最后，从研究范式的角度看，LookStep通过给候选动作附加结构化结果标签，在信息论上证明了期望风险下降的可能，但该上界依赖oracle标签。实际训练时模型使用的是从专家轨迹推导出的反事实标签，这些标签并未考虑部分不可行动作、动态障碍物碰撞以及不同初始位姿下的行为等价性。当导航环境越来越开放、指令越来越抽象时，自动化标签生成规则将逐渐成为瓶颈；后续可以探索基于大模型自我模拟或世界模型生成未来状态标签的替代方案，以减少对确定性规则库的依赖。

总体而言，LookStep在数据与记忆效率的设计上走出了富有启发意义的一步，其语言中心化未来状态预测和事件驱动记忆机制为资源受限端到端VLN提供了一种低冗余、高可解释的新框架。未来工作若能进一步扩展标签体系、替换或补充FIFO记忆淘汰策略、在更多VLN任务变体和真实物理环境中验证，其方法价值会更完整、更稳健。
