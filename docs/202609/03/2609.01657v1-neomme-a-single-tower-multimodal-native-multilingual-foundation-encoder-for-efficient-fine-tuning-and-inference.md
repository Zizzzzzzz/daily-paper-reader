## 摘要
多模态模型通常建立在为生成式视觉语言建模而设计的架构之上，典型的做法是将分别预训练的视觉编码器与因果语言模型相结合。像ColPali这样的视觉文档检索器将这些模型重新用作编码器，从而为非生成任务承担了VLM的参数和计算开销。我们推出了NeoMME，这是一系列参数量为260M和800M的多模态、多语言双向编码器，它们在单个双向Transformer编码器中处理多语言文本和原始图像块。两个模型都从头开始预训练，采用掩码离散扩散文本目标，对于多模态样本以可见图像块为条件。两者都支持16,384个token的上下文，足以编码最多两幅标准的4K UHD图像。为了展示其下游能力，我们使用联合训练的密集头和后期交互头对NeoMME进行微调。在ViDoRe v3基准测试上，由此得到的NeoMME-Retriever 260M以0.523的nDCG@10超过了所有严格低于800M参数的评估模型，而NeoMME-Retriever 800M达到了0.556。在NVIDIA L40S上匹配的2048x2048图像输入尺寸下，NeoMME-260M编码页面的吞吐量约为ColModernVBERT的2倍。分层token池化和非对称量化将后期交互多模态文档嵌入压缩了255倍，同时保留了超过95%的基线nDCG@10。我们将NeoMME贡献给Hugging Face Transformers，并在Apache 2.0许可下于https://hf.co/collections/Hcompany/neomme发布预训练骨干网络和兼容检索的检查点。

## Abstract
Multimodal models often build on architectures designed for generative vision-language modeling, typically combining separately pretrained vision encoders with causal language models. Visual document retrievers such as ColPali repurpose these models as encoders, carrying over the parameter and compute overhead of a VLM for a non-generative task.   We introduce NeoMME, a family of 260M and 800M-parameter Multimodal and Multilingual bidirectional Encoders that process multilingual text and raw image patches in a single bidirectional Transformer encoder. Both models are pretrained from scratch with a masked discrete-diffusion text objective, conditioned on visible image patches for multimodal examples. Both support a 16,384-token context, enough to encode up to two standard 4K UHD images.   To demonstrate its downstream capabilities, we fine-tune NeoMME with jointly trained dense and late-interaction heads. On the ViDoRe v3 benchmark, the resulting NeoMME-Retriever 260M outperforms all evaluated models strictly below 800M parameters with 0.523 nDCG@10, while NeoMME-Retriever 800M reaches 0.556. At a matched 2048x2048 image input size on an NVIDIA L40S, NeoMME-260M encodes pages with about 2x the throughput of ColModernVBERT. Hierarchical token pooling and asymmetric quantization compress late-interaction multimodal document embeddings by 255x while preserving over 95% of baseline nDCG@10. We contribute NeoMME to Hugging Face Transformers and release the pretrained backbone and retrieval-compatible checkpoints under Apache 2.0 at https://hf.co/collections/Hcompany/neomme.

### 1. 核心问题与整体含义

多模态检索模型（如视觉文档检索器 ColPali）通常将专为生成式视觉语言建模设计的 VLM（如视觉编码器+因果解码器）重新用作编码器。这种方法论存在以下结构性问题：

- **参数与算力浪费**：非生成任务（如文档编码）承担了生成式 VLM 的解码器开销，推理和显存成本高。
- **架构不对称**：视觉塔与文本塔分离，计算路径不一致，微调、并行与服务化复杂。
- **缺乏原生编码器设计**：现有方案没有针对编码任务在架构和预训练目标上进行专门设计。

NeoMME 的核心含义在于提出一种新的模型类型：**单塔（single-tower）、多模态原生（multimodal-native）、多语言的基础编码器（foundation encoder）**，同时处理文本与图像，旨在兼具双向编码器的高表征质量与低参数/算力开销。整体目标是证明一个从零预训练的单塔双向 Transformer 可以在视觉文档检索和文本检索上取得与更大规模 VLM 复用方案相当甚至更优的性能，同时提供更高的吞吐和更低的存储占用，推动多模态编码器的架构范式转变。

### 2. 方法论

#### 2.1 总体架构
- **从零预训练**的单向（实际为双向）Transformer 编码器，无预训练的视觉塔，也无因果解码器。
- 输入：分词后的文本 token + 原始 32×32 RGB 图像 patch，经各自模态专用投影层进入共享编码器。
- 两种规模：260M 和 800M，均支持 16,384 token 上下文。

#### 2.2 关键设计细节
- **Tokenizer**：基于 SuperBPE 的 whitespace-unconstrained byte-level BPE，131K 词表，字节回退、逐数字拆分。
- **文本嵌入**：ALBERT 式分解嵌入（256 维查询表+线性投影），masked-token 输出使用共享因式分解解码器。
- **图像输入**：每个 patch 先经 LayerNorm 与 2-layer MLP 投影为模型输入向量；训练中动态采样最长边 1024–2048，保持宽高比，随尺寸变化产生动态 token 数。
- **位置编码**：2D RoPE（文本 token 用对角线坐标，图像 patch 用行列坐标）；全局注意力层使用 partial RoPE（旋转 25%）。
- **长上下文注意力**：混合滑动窗口注意力（半窗口在 256 与 1024 token 间交替）与全局注意力（每 6 层及最后一层）；260M 17 层、800M 20 层。
- **Multi-head 配置**：GQA；QK 归一化（RMS）； Squared-ReLU MLP；query-dependent sigmoid gate；残差分支乘以 (2L)^(-1/2) 的 Depth-µP 分支缩放。
- **特殊机制**：token-indexed value embeddings（首末全局层添加）、residual mixing（学习残差流与初始输入的混合）、exclusive self-attention 的可学习变体。
- **初始化**：attention 输出与 MLP down 投影初始化为零（Fixup 原则），模型初始为恒等映射。

#### 2.3 预训练目标
- 采用**掩码离散扩散（masked discrete diffusion）**文本去噪目标：对每个文本段采样掩码率 ρ（文本-only 段 U(0,1)，多模态段 U(0.3,1)），将选定位置替换为 mask，并**仅在这些位置计算交叉熵损失**。
- 损失使用 inverse-rate 加权（封顶 20），对每个数据并行 rank 独立归一化。
- 图像 patch 保持可见，作为条件信号；**无图像重建头**（no masked image modeling）。
- 多模态段的最低掩码率更高（0.30），以减弱文本自身上下文可预测性，迫使模型依赖图像证据。
- 通过 cross-modal input-ablation probe 记录正 image gain，表明模型确实利用图像信息。

#### 2.4 检索微调目标
- 对 NeoMME-Retriever 进行视觉与文本文档检索微调，单次骨干前向同时输出两种表征：
  - **Late-interaction head**：每个 token/patch 投影为 128 维归一化向量；
  - **Dense head**：mean pooling + L2 归一化，采用 Matryoshka 多宽度训练。
- 损失函数：联合优化 late-interaction（InfoNCE + 温度 0.02）与多宽度 dense loss。
- 支撑训练效率的技术：
  - **GradCache** 分块重计算以支持大批量对比学习；
  - **Late-Interaction Kernels (LIK)**：分块 MaxSim，降低显存峰值。

  - **部分对比分数来自外部报告（MTEB/论文），评估代码或 batch 配置可能不完全一致**，有公平性风险；
  - 消融只做了单一目标联合/单独对比，论文明确承认主要架构/数据/训练选择的消融缺失；
  - 多个下游迁移实验只有一个 seed 或未按严格协议复现；
  - 自然图像冻结表征很弱，作者解释为没有图像级目标，但并未提供配套的图像预测/重建/对比目标的对比实验；
  - 视觉训练数据与语言覆盖度有限（视觉 5–6 种语言 vs 预训练 20+ 种），未对混合语种文档检索进行评估。

### 6. 主要结论与发现

- NeoMME-260M 在 ViDoRe v3 上以 0.523 nDCG@10 超过所有 <800M 参数的基线。
- NeoMME-800M 达到 0.556，仅低于稍大的 Vultron Flash（0.565）0.9 个点，但优于 3.75B 的 ColQwen2.5（0.524）。
- BEIR-15 上 late-interaction 明显强于 dense：260M 为 0.488 vs 0.306、800M 为 0.513 vs 0.369。
- 吞吐量：at 2048×2048 L40S 上，NeoMME-260M 编码速度为 51.3 pages/s，为 ColModernVBERT（26.0 pages/s）约 2 倍；800M 在 1536×1536 时（39.2 pages/s）比 Vultron Flash 于 1344×1344（20.2 pages/s）快约 94%。
- 联合训练 late-interaction + dense 对 late-interaction 有增益（ViDoRe v3 提升 +1.38 nDCG@10 点），但对 dense 无显著影响；BEIR 上 dense 反而下降 1.85 点，呈现单向迁移。
- 分层 token 池化因子 10 可保留 99%+ 质量；int8/binary 非对称量化加池化因子 8 可实现 255.5× 压缩且保留 >95% 质量。
- 预训练模型显示了图像条件文本生成能力（无需微调即可以类 OCR/描述方式生成文本），以及 90% 掩码率下正向 image gain（260M：+38.4pp，800M：+40.5pp）。

### 7. 优点

- **架构创新清晰**：真正单塔 + 从零 + 原生 patch 输入 + 共享双向 Transformer，没有视觉塔和解码器冗余，计算路径统一，有利于端到端微调与高效部署。
- **预训练目标设计合理**：高掩码率多模态段 + 可见图像 patch 条件化文本去噪，配合跨模态探针验证，能有效抵御模态捷径并促进图像利用；不使用图像重建头，简洁节省计算。
- **推理效率与压缩贡献突出**：动态分辨率控制、LIK kernels、分层 token 池化 + 非对称量化构成的完整效率体系，从吞吐、延迟、显存、存储多角度同时评估，实用性强。
- **全面开放**：提供 Hugging Face Transformers 原生集成与 Apache 2.0 权重，可复现性佳。
- **检索适配灵活**：单次前向产出 dense 与 late-interaction 双表示，支持在不同规模语料库下做灵活部署（ANN 或 MaxSim + rerank）。

### 8. 不足与局限

#### 实验中暴露的短板
- **自然图像表征弱**：无图像级目标导致 frozen 16-shot 任务仅 13.2 平均精度，尽管微调可改善，表明语义表征需要任务适配。
- **文本检索 Dense 结果相对较弱**：BEIR-15 dense 的 0.37 与专用 dense 模型（0.55+）差距较大，联合训练对 dense 头无提升甚至轻微损害。
- **跨语言能力不均**：预训练 tokenizer 覆盖不足 204 语言中大量低资源语言（如藏语、南亚/东南亚语系出现较大压缩率退化）；检索微调语言覆盖远窄于预训练。

#### 方法层面的未验证问题
- **预训练规模不足**：524B tokens 相对 ModernBERT 的约 2T 少约 7 倍，不能排除更大数据量带来显著提升。
- **无图像侧监督目标**：系统未设计图像可见侧的被预测/重建目标，所以没有强制形成图像全局表征的证据；作者自己指出这可能限制了冻结自然图像嵌入质量，但没有进行消融对比。
- **检索训练监督量远小于 SOTA**：mLateOn 使用 660M 对比样本 + 16M 硬负样本，而 NeoMME 仅约几十万至百万级样本；BEIR 差距可能主要来自数据量而非模型设计，论文未能区分。
- **蒸馏、安全、偏见评测缺失**：论文明确表示无蒸馏实验；未对生成的安全与偏见输出做系统评估。

#### 可复现性与评估局限
- 外部对比模型的分数部分来自不同来源（MTEB/报告），评估代码未完全共享，存在跨协议对比偏差风险。
- 视觉文档评估只测单页检索，未覆盖混合模态语料库（如 UniDoc-Bench、MixBench），与论文强调的“混合模态检索”设计意图不完全对应。
- 检索训练中多个环节使用单种子、自挖掘负样本、生成式查询合成管线，带较大运行方差。
