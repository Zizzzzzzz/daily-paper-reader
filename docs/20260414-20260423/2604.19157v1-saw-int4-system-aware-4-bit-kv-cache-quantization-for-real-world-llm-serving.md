## 摘要
KV 缓存内存是真实场景下大语言模型（LLM）推理服务的主要瓶颈，系统必须同时支持延迟敏感的小批次请求和高吞吐量的并发工作负载。尽管许多 KV 缓存压缩方法提高了离线精度或压缩率，但它们往往违反了实际的推理服务约束，例如分页内存布局、规则内存访问和融合注意力执行，从而限制了其在部署中的有效性。在这项工作中，我们确定了在这些约束下仍然可行的 4 位 KV 缓存量化方法的最小集合。我们的核心发现是，一种简单的设计——采用块对角哈达玛旋转（block-diagonal Hadamard rotation）的逐令牌（token-wise）INT4 量化——能够一致地实现最佳的精度-效率权衡。在多个模型和基准测试中，该方法几乎恢复了朴素 INT4 损失的所有精度，而一旦考虑到推理服务的兼容性，矢量量化和 Hessian 感知量化等更复杂的方法仅能提供微乎其微的额外收益。为了使其具有实用性，我们实现了一个融合旋转-量化算子（kernel），该算子直接集成到分页 KV 缓存布局中，且引入的端到端开销几乎为零，在各种并发级别下均能匹配普通 INT4 的吞吐量。我们的结果表明，有效的 KV 缓存压缩从根本上是一个系统协同设计问题：在真实的推理服务约束下，轻量级的块对角哈达玛旋转是一种可行的方法，它在不牺牲推理效率的情况下实现了近乎无损的精度。

## Abstract
KV-cache memory is a major bottleneck in real-world LLM serving, where systems must simultaneously support latency-sensitive small-batch requests and high-throughput concurrent workloads. Although many KV-cache compression methods improve offline accuracy or compression ratio, they often violate practical serving constraints such as paged memory layouts, regular memory access, and fused attention execution, limiting their effectiveness in deployment.   In this work, we identify the minimal set of 4-bit KV-cache quantization methods that remain viable under these constraints. Our central finding is that a simple design--token-wise INT4 quantization with block-diagonal Hadamard rotation--consistently achieves the best accuracy-efficiency trade-off. Across multiple models and benchmarks, this approach recovers nearly all of the accuracy lost by naive INT4, while more complex methods such as vector quantization and Hessian-aware quantization provide only marginal additional gains once serving compatibility is taken into account.   To make this practical, we implement a fused rotation-quantization kernel that integrates directly into paged KV-cache layouts and introduces zero measurable end-to-end overhead, matching plain INT4 throughput across concurrency levels. Our results show that effective KV-cache compression is fundamentally a systems co-design problem: under real serving constraints, lightweight block-diagonal Hadamard rotation is a viable method that delivers near-lossless accuracy without sacrificing serving efficiency.

    *   **分页内存布局（Paged Memory）**：要求内存块大小固定且类型统一，不支持混合精度或动态剔除。
    *   **融合算子执行（Fused Kernels）**：为了性能，量化/去量化必须融合在注意力算子中，复杂的查找表或基变换会破坏内存对齐并增加延迟。
*   **研究目标**：寻找在真实系统约束下，能够兼顾精度恢复与端到端推理效率的“最小化”4-bit 量化方案。

### 2. 论文提出的方法论
*   **核心思想**：**SAW-INT4** 采用“逐令牌（Token-wise）INT4 量化”结合“块对角哈达玛旋转（Block-Diagonal Hadamard Rotation, BDR）”。
*   **关键技术细节**：
    *   **Token-wise INT4**：对每个 Head 的向量独立进行非对称量化。这种方式天然兼容分页内存，且不产生跨 Block 的依赖。
    *   **块对角哈达玛旋转 (BDR)**：在量化前，对 Key（或 KV）向量应用正交变换。其作用是打破通道间的异质性，平滑离群值（Outliers），从而显著降低 INT4 量化的精度损失。
    *   **块设计**：将全维度的旋转分解为独立的小块（如 Block Size = 128），以降低计算复杂度并提升算子并行度。
    *   **系统融合实现**：开发了融合的旋转-量化 CUDA/Triton Kernel。在 Prefill 阶段将旋转与写入融合，在 Decode 阶段将旋转与 Query 处理融合，避免了额外的全局内存读写。

    *   **复杂量化**：KMeans 向量量化（不同质心数 C=1 到 2048）、Hessian 感知量化（基于二阶信息的旋转）。

*   **实验规模**：论文进行了多维度的详尽测试：

    *   **消融实验**：探讨了旋转块大小（16, 64, 128）、旋转对象（仅 Key 旋转 vs KV 同时旋转）、向量量化质心数的影响。

### 6. 主要结论与发现
*   **旋转是关键**：在 Qwen3 等对量化敏感的模型上，朴素 INT4 精度几乎归零，而加入 BDR 后可恢复至接近 BF16 的水平（差距仅 1-3 分）。
*   **复杂度收益递减**：一旦应用了旋转，更复杂的 KMeans 或 Hessian 感知量化带来的额外精度提升非常微小，但在系统实现上却增加了巨大开销。
*   **系统零开销**：通过算子融合，BDR-INT4 的端到端吞吐量与朴素 INT4 完全一致，且显著优于 BF16（尤其在长文本和高并发场景下，吞吐量提升可达 10%-40%）。
*   **仅旋转 Key 即可**：实验发现仅对 Key 进行旋转和量化，Value 保持常规量化，足以维持绝大部分精度。

### 7. 优点（亮点）
*   **系统协同设计**：不孤立地看量化算法，而是从分页内存和算子融合的角度倒推算法设计，具有极强的工业部署参考价值。
*   **简洁高效**：证明了“简单算法+深度优化”优于“复杂算法”，回归了工程实现的本质。
*   **开源贡献**：提供了基于 SGLang 的完整实现代码，便于社区复现和集成。

### 8. 不足与局限
*   **比特数限制**：研究主要集中在 4-bit。对于更极端的 2-bit 或 3-bit 量化，BDR-INT4 是否依然能保持近乎无损的精度尚待验证（通常 2-bit 需要更复杂的非线性映射）。
