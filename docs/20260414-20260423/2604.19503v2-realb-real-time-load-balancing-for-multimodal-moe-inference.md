## 摘要
混合专家（MoE）架构在现代大语言模型和多模态模型中得到了广泛应用。然而，推理效率往往受到不同模态之间高度动态且倾斜的专家工作负载的限制。在大批量预填充阶段，视觉 token 经常在输入序列中占据主导地位。在专家并行（EP）模式下，这会导致严重的负载不均衡，使得部分设备过载，从而降低系统的整体吞吐量。我们提出了 ReaLB，一种用于多模态 MoE（MMoE）推理的实时负载均衡方法，该方法引入了零调度开销。ReaLB 在运行时以每个 EP-rank 为单位动态调整 MoE 专家的计算精度。对于由视觉密集型专家主导的 rank，ReaLB 通过利用 FP4 Tensor Core 分配低精度计算，以提高执行效率。ReaLB 不需要冗余专家或额外的内存分配。相反，它在运行时执行逐层专家精度转换，并将相关开销隐藏在 MoE 计算前的分发阶段。在代表性 MMoE 模型上的实验表明，ReaLB 实现了 1.29 倍的层级加速，同时将精度损失限制在 1.2% 以内。

## Abstract
Mixture-of-Experts (MoE) architectures are widely used in modern large language models and multimodal models. However, inference efficiency is often limited by highly dynamic and skewed expert workloads across different modalities. During the prefill stage with large batch sizes, vision tokens frequently dominate the input sequences. Under expert parallelism (EP), this leads to severe load imbalance, where a subset of devices becomes overloaded, reducing overall system throughput.   We propose ReaLB, a real-time load balancing method for multimodal MoE (MMoE) inference that introduces zero scheduling overhead. ReaLB dynamically adjusts the computation precision of MoE experts at runtime on a per-EP-rank basis. For ranks dominated by vision-heavy experts, ReaLB assigns lower-precision computation to improve execution efficiency by exploiting FP4 Tensor Cores. ReaLB does not require redundant experts or additional memory allocation. Instead, it performs layer-wise expert precision transformation on the fly and hides the associated overhead within the dispatch phase before MoE computation. Experiments on representative MMoE models show that ReaLB achieves 1.29x layer-level speedup while limiting accuracy loss to within 1.2%.

### 1. 论文的核心问题与整体含义
在多模态混合专家模型（MMoE）的推理过程中，尤其是大批量的**预填充（Prefill）阶段**，视觉 Token 的数量通常远超文本 Token。由于 MoE 的路由机制具有输入依赖性，这导致在**专家并行（Expert Parallelism, EP）**部署下，不同计算节点（Rank）之间的负载极度不均。

**核心痛点：**
*   **动态性高**：推理时的专家选择模式变化极快，传统的基于历史预测的负载均衡方法（如 EPLB）难以跟上变化。
*   **木桶效应**：少数处理视觉密集型专家的节点成为“长尾节点”（Stragglers），拖慢整个系统的同步速度。
*   **资源受限**：现有的专家复制或迁移方案会带来额外的显存占用和通信开销。

### 2. 论文提出的方法论
论文提出了 **ReaLB**，一种实时、模态感知的负载均衡机制。

**核心思想：**
利用视觉 Token 在计算中具有更高冗余度的特性，对负载过重的节点动态降低计算精度（使用 FP4），通过牺牲极小的精度换取计算速度的对齐，从而消除长尾效应。

**关键技术细节：**
1.  **实时模态感知调度**：在每一层 MoE 计算前，实时统计各节点的 Token 负载。若某节点负载超过平均值且视觉 Token 占比超过阈值（如 0.7），则判定为“视觉密集型过载节点”。
2.  **动态精度切换**：针对过载节点，将其专家计算从 BF16 切换为 **FP4** 精度，利用 Blackwell 架构 GPU 的 FP4 Tensor Cores 实现约 4 倍的理论算力提升。
3.  **在线精度转换流水线**：不预先存储低精度权重，而是在运行时动态转换。
4.  **开销隐藏（Pipeline Orchestration）**：将“路由统计同步”和“权重精度转换”的操作与节点间的“Token 分发（All-to-All Dispatch）”通信过程重叠，从而实现零附加延迟。

### 6. 主要结论与发现
*   **性能提升**：ReaLB 在 MoE 层实现了平均 **1.29×** 的加速，端到端吞吐量提升高达 **1.53×**。
*   **精度保持**：相比于全量 FP4 导致的精度大幅下降，ReaLB 将平均精度损失控制在 **1.2%** 以内，在某些任务上甚至能保持与 BF16 持平。
*   **调度效率**：通过流水线编排，成功隐藏了在线量化和调度的开销，证明了实时负载均衡在 MMoE 推理中的可行性。

### 7. 优点
*   **零显存冗余**：无需像传统方法那样存储专家副本，对显存极其友好。
*   **极速响应**：完全基于当前 Batch 的实时路由结果，解决了 MMoE 路由高度动态、难以预测的问题。
*   **软硬结合**：巧妙利用了 Blackwell 架构的 FP4 硬件特性，并结合多模态数据的语义特性（视觉冗余）进行系统级优化。

### 8. 不足与局限
*   **硬件依赖性**：该方法高度依赖支持 FP4 加速的新一代 GPU 硬件，在旧款硬件上无法实施。
*   **精度敏感度**：虽然平均损失小，但在某些极度敏感的任务（如 RealWorldQA）中，精度下降仍达到约 3%，说明低精度计算对特定文本逻辑仍有干扰。
*   **适用场景限制**：主要在**计算受限（Compute-bound）**的大 Batch 场景下有效；在小 Batch 或通信受限的场景下，加速效果会显著减弱。
