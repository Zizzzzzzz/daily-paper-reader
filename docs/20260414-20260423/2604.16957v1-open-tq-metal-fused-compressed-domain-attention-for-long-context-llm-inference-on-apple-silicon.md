## 摘要
我们提出了 Open-TQ-Metal，这是在 Apple Silicon 上首次实现的融合压缩域注意力，使得在单台 64GB 消费级 Mac 上实现 Llama 3.1 70B 的 128K 上下文推理成为可能——这一配置在所有现有推理框架下都是无法实现的。Open-TQ-Metal 将 KV 缓存实时量化为 int4，并通过自定义 Metal 计算着色器直接在压缩表示上计算注意力，从而消除了所有中间反量化矩阵。在涵盖两个模型系列（Gemma 4 31B 和 Llama 3.1 70B）的 330 次实验中，融合的 sdpa_int4 内核在 128K 上下文下相比“先反量化再计算注意力”的基准实现了 48 倍的注意力加速，将 KV 缓存内存从 40 GB 减少到 12.5 GB（3.2 倍压缩），并保持了与 FP16 推理完全一致的 top-1 token 预测。我们还提供了首次针对 KV 缓存量化方法的跨架构分析，揭示了注意力缩放因子（而非模型大小）决定了像 PolarQuant 这样的角量化方案的成败；其中 Gemma 4 的 attn_scale=1.0 对方向误差的放大作用比 Llama 标准的 1/sqrt(d) 缩放高出 25-100 倍。

## Abstract
We present Open-TQ-Metal, the first implementation of fused compressed-domain attention on Apple Silicon, enabling 128K-context inference for Llama 3.1 70B on a single 64GB consumer Mac -- a configuration impossible with all existing inference frameworks. Open-TQ-Metal quantizes the KV cache to int4 on the fly and computes attention directly on the compressed representation via custom Metal compute shaders, eliminating all intermediate dequantization matrices. Across 330 experiments spanning two model families (Gemma 4 31B and Llama 3.1 70B), the fused sdpa_int4 kernel achieves 48x attention speedup at 128K context over the dequantize-then-attend baseline, reduces KV cache memory from 40 GB to 12.5 GB (3.2x compression), and maintains identical top-1 token predictions to FP16 inference. We further provide the first cross-architecture analysis of KV cache quantization methods, revealing that the attention scale factor -- not model size -- determines whether angular quantization schemes like PolarQuant succeed or fail, with Gemma 4's attn_scale=1.0 amplifying directional error 25-100x more than Llama's standard 1/sqrt(d) scaling.

*   **现有方案不足**：现有的推理框架（如 mlx-lm, llama.cpp）在处理量化 KV 缓存时，通常采用“先反量化为 FP16 再计算注意力”的模式，这会产生巨大的中间矩阵，消耗带宽并导致内存溢出。
*   **研究目标**：开发一种直接在压缩域（Compressed-Domain）执行计算的注意力机制，打破内存墙，实现长上下文推理。

### 2. 方法论：核心思想与技术细节
*   **融合 int4 SDPA 内核**：开发了自定义的 Metal 计算着色器（Compute Shader）。其核心思想是**在 GPU 寄存器中实时进行位运算反量化**，直接计算 Query 与量化 Key/Value 的点积，不产生任何中间反量化矩阵。
*   **向量化位提取（Vectorized Nibble Extraction）**：借鉴了 MLX 的 `qdot` 模式，通过预除 Query 值并配合掩码（Mask），在一次操作中同时计算四个 int4 值的点积，极大提升了吞吐量。

*   **混合预填充/解码策略**：
    *   **预填充阶段**：使用标准 FP16 计算，完成后实时量化存入 int4 缓存。
    *   **解码阶段**：直接从 int4 缓存读取并使用融合内核计算。
*   **内存锁定（Wired Memory）**：通过 `set_wired_limit()` 强制将权重固定在物理内存中，防止 macOS 将其交换到 SSD，从而将吞吐量提升了 10 倍。

### 6. 主要结论与发现
*   **性能飞跃**：在 128K 上下文下，融合内核比基准快 **48 倍**；KV 缓存压缩了 **3.2 倍**。
*   **硬件突破**：首次在 64GB Mac 上实现了 Llama 70B 的 128K 上下文推理（总占用 53.6GB，尚有 10.4GB 余量）。
*   **架构敏感性发现**：**注意力缩放因子（$\alpha$）是量化成败的关键**。Gemma 4 使用 $\alpha=1.0$，会放大角量化误差；而 Llama 使用 $1/\sqrt{d}$，能有效抑制误差。这解释了为什么 PolarQuant 在 Llama 上成功但在 Gemma 上失败。

*   **工程实现卓越**：通过 Metal 着色器深度优化，解决了 Apple Silicon 上的长文本推理难题。

*   **开源贡献**：代码、着色器和 Benchmark 全部开源。
*   **精度无损**：在 int4 量化下实现了与 FP16 完全一致的贪婪搜索输出。

### 8. 不足与局限
*   **硬件局限性**：内核高度针对 Apple Silicon 的 32-wide SIMD 架构，迁移到 CUDA 需要重新实现。
*   **端到端开销**：由于 KV 缓存拼接管理（而非预分配缓冲区）的工程问题，端到端吞吐量比 mlx-lm 低约 18%。

*   **带宽瓶颈**：尽管优化了注意力计算，但 70B 模型的权重加载仍受限于 400GB/s 的带宽，推理速度上限被锁定在约 10 tok/s。
