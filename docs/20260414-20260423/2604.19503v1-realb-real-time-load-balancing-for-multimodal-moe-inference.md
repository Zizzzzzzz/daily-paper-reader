## 摘要
混合专家（MoE）架构在现代大语言模型和多模态模型中得到了广泛应用。然而，推理效率往往受到不同模态之间高度动态且倾斜的专家工作负载的限制。在大批次预填充阶段，视觉标记（vision tokens）经常在输入序列中占据主导地位。在专家并行（EP）模式下，这会导致严重的负载不均衡，即部分设备过载，从而降低系统整体吞吐量。我们提出了 ReaLB，一种用于多模态 MoE（MMoE）推理的实时负载均衡方法，该方法引入了零调度开销。ReaLB 在运行时根据每个专家并行秩（EP rank）动态调整 MoE 专家的计算精度。对于由视觉密集型专家主导的秩，ReaLB 通过利用 FP4 Tensor Core 分配低精度计算来提高执行效率。ReaLB 不需要冗余专家或额外的内存分配。相反，它在运行时执行逐层专家精度转换，并将相关开销隐藏在 MoE 计算前的分发阶段。在代表性 MMoE 模型上的实验表明，ReaLB 实现了 1.29 倍的层级加速，同时将精度损失控制在 1.2% 以内。

## Abstract
Mixture-of-Experts (MoE) architectures are widely used in modern large language models and multimodal models. However, inference efficiency is often limited by highly dynamic and skewed expert workloads across different modalities. During the prefill stage with large batch sizes, vision tokens frequently dominate the input sequences. Under expert parallelism (EP), this leads to severe load imbalance, where a subset of devices becomes overloaded, reducing overall system throughput.   We propose ReaLB, a real-time load balancing method for multimodal MoE (MMoE) inference that introduces zero scheduling overhead. ReaLB dynamically adjusts the computation precision of MoE experts at runtime on a per-EP-rank basis. For ranks dominated by vision-heavy experts, ReaLB assigns lower-precision computation to improve execution efficiency by exploiting FP4 Tensor Cores. ReaLB does not require redundant experts or additional memory allocation. Instead, it performs layer-wise expert precision transformation on the fly and hides the associated overhead within the dispatch phase before MoE computation. Experiments on representative MMoE models show that ReaLB achieves 1.29x layer-level speedup while limiting accuracy loss to within 1.2%.

### 1. 论文的核心问题与整体含义（研究动机和背景）
*   **核心问题**：在多模态混合专家模型（MMoE）推理过程中，由于视觉 Token 数量远超文本 Token 且专家路由具有高度动态性和倾斜性，导致在专家并行（EP）模式下出现严重的**负载不均衡**。部分 GPU（Stragglers）因处理视觉密集型专家而过载，成为系统瓶颈。
*   **研究背景**：现有的负载均衡方法（如辅助损失函数、专家复制等）多针对训练阶段，或依赖于历史预测。然而，多模态推理的路由模式变化极快，预测往往不准，且专家复制会带来巨大的内存和通信开销。

### 2. 论文提出的方法论：ReaLB
*   **核心思想**：利用视觉 Token 在前向传播中具有较高冗余性的特点，在运行时动态降低过载设备上专家的计算精度（如从 BF16 降至 FP4），利用硬件加速（FP4 Tensor Cores）抵消工作负载倾斜，实现执行时间的实时对齐。
*   **关键技术细节**：
    *   **实时模态感知调度**：在每一层 MoE 计算前，根据当前路由结果识别“热点设备”。若某设备负载超过平均值且视觉 Token 占比超过阈值（$M_d$），则将其标记为视觉密集型，采用低精度计算。
    *   **在线精度转换流水线**：不预存低精度权重，而是在运行时动态量化。通过流水线编排，将权重转换（Quantization）和调度元数据同步的开销完全隐藏在 Token 分发（All-to-All Dispatch）的通信延迟中。
    *   **自适应激活机制**：仅在计算密集型（大 Batch Size）场景下激活 ReaLB，避免在小 Batch 的通信密集型场景中引入不必要的开销。

### 6. 论文的主要结论与发现
*   **性能提升**：ReaLB 实现了平均 **1.29 倍**的 MoE 层级加速，端到端吞吐量提升高达 **1.53 倍**。

### 7. 优点（亮点）
*   **零内存开销**：无需像 EPLB 那样存储冗余专家副本，对显存极其友好。
*   **零调度开销**：巧妙利用通信时间掩盖了量化延迟，实现了“免费”的负载均衡。
*   **模态感知**：精准打击视觉 Token 带来的负载倾斜，保护了对精度敏感的文本处理。

### 8. 不足与局限
*   **硬件依赖**：该方法高度依赖支持 FP4 加速的最新硬件（如 Blackwell 架构或 RTX 50 系列），在旧款 GPU 上无法发挥优势。
*   **阈值调优**：模态阈值 $M_d$ 目前仍需手动配置，虽然实验证明其相对稳定，但在极端多变的工作负载下可能需要更复杂的自适应算法。
